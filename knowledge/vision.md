## 問題陳述

AI 領域（工程實作、學術論文、最新趨勢）的資訊爆量且更新極快——但**看過不等於理解，
理解了不等於留得住**。真正的成本不在「知不知道發生了什麼」，在**你信的東西半年後
還答不答得出「我當初為什麼信這個」**。既有的新聞、訂閱、筆記工具都不管這一段：
它們幫你收集，不幫你**沉澱**，更不會在你想歪的時候頂你一句。

## 核心想法

KnowField 是**你的場**：一個以**你親手冊封的核心理解**為吸引子組織起來的知識場。

- **跟你的場聊**——AI 帶著你的核心理解回答，且**反逢迎**（有話直說、不順著你講好聽話）。
- **人冊封、AI 提議**——AI 大量提候選、標缺口；**不可逆的那一步永遠是你按的**。
- **溯源不可省**——每條理解答得出「這是從哪來的」；消化到底，隨時回得到原文。
- **輸出是出海口，不回灌地基**——生成的文章是場的產物，不會變成場的養分（防 model collapse）。

⚠️ **轉移鏈（讀這段之前先知道）**：原定位是「新聞分診 → 每日匯整 → 收藏」的**推／拉雙模式**，

（見 [history/109](history/109-願景定位落後產品轉向二十天.md)）。

**差異化定位**：不是「更好的資訊流」，是**理解的複利**——別的工具幫你收集，
這個工具讓你**冊封**，而冊封過的東西會回頭當下一次思考的地基。
與個人化論文工具（如 Scholar Inbox）的差別在**主權**：權重由你給，不是由推薦系統給。

> 設計源＝[draft/2026-08-21-來源直接對話.md](draft/2026-08-21-來源直接對話.md)。
> 承階段 37：**同一套機制換一個資料來源**，形狀沿用、不重開討論。
> ⚠️ 來源**現在就已經**進得了對話（`_chat_corpus` 撒網，`app.py:262`）。
> 本階段的價值不是「讓來源能進對話」，是把「**它猜哪些相關**」換成「**我說就是這一份**」
> ——撒網真正的成本是**沉默地漏掉**（它沒撈到，你不會知道）。

**驗收**
- [X] `/source` 頁一個動作把這份來源帶進**新的一段對話**，形狀與階段 37 逐項相同
      （第一則、`<details>` 比照章節、無起手式、無額外控制項、不在對話間殘留）
- [X] 帶了來源的回答**可驗證地反映該來源內容**，且**不依賴撒網有沒有撈到它**
      （關掉撒網仍要答得出來——這條是本階段存在的理由）
- [X] ⚠️ 注入的是**原文**，並在脈絡中明講「使用者讀的是譯文」；譯文（AI 產物）不進脈絡
- [X] 長來源：短的全文進、長的走**份內檢索**（既有 `retrieve_corpus` 加 url 過濾）；
      ⚠️ **不得**用「截斷前 N 字」——那是又一個沉默失敗
- [X] ⚠️ **雙重注入去重**：同一份既被帶入又被撒網命中時，只算一次
      （否則模型把同一段當兩個獨立佐證，而畫面上看不出來）
- [X] ⚠️ **041 的冊封閘門不照搬**：來源不是 AI 產物，從來源冊封是既有合法功能
      （`/api/source/distill`）；照搬等於閹掉一條本來就開著的路
- [X] bare 模式不注入來源（沿用階段 37）
- [ ] **out of scope**：段落級出處、多來源同時帶入、來源編輯

- [X] 文章在脈絡中要**標示為 AI 生成物**，與收進的來源分開——它們的可信度不同層

- [ ] **out of scope**：Canvas 編輯（階段 38 候選，且卡在「文章唯讀」定案的張力）、
      段落級出處（那是 Canvas／可合併的地基，不擋本階段）、自動注入、跨文章比對

⚠️ **已知風險（記著，不在本階段解）**：**當輸出物變成思考的踏板，它就同時是思考的護欄**
