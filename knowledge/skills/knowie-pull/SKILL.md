# 從場裡拉判準

**為什麼存在**：使用者有十幾個專案、上千條教訓，而開新專案還是從零撞起。
`knowie-xbase` 已經證明複利是真的（49 群跨 base、16 群跨 ≥3 個）——
這一支是把那些判準**送進去**的那一半。

## 為什麼叫 pull，而**沒有** push

`seed` 只名得住「開頭那一次」。而同一個需求在專案跑了三個月、踏進新領域時一樣會來
——判準要有修剪力，`pull` 蓋得住整個生命週期，`seed` 蓋不住。

⚠️ **而 `push` 不存在，是刻意的。** 三個代價，這裡三個都不能要：

| git 的 push | 這裡 |
|---|---|
| 落地成共享狀態 | 違反「共享空間必須是**收件匣，不是資料庫**」 |
| 有共同祖先、可 merge | 沒有共同物件——你送出的是**拷貝** |
| 對稱：push 完再 pull 拿得回自己 | ⚠️ **那正是馬太迴圈** |

場怎麼知道這個 base 學到什麼？**它自己來讀**（`knowie-xbase` 掃所有 base）。
設計原話就是那份 draft 的標題：**讀而不寫**。
要主動送就叫**「發送」**（送出的是拷貝，落在**收件匣**），不叫 push。

## 判準：**借來的要標成借來的**

> 「一個空的 base **沒有試金石**——你還不知道這個專案會撞到什麼。
> 大量收下通用判準，等於在還不知道它們有沒有用的時候就先信了。
> 那會長出一個『看起來很有經驗，但**沒有一條是自己撞出來的**』知識庫。」

⇒ 三件因此是硬的，不是偏好：

1. **要少。** 10–15 條，不是把一百條倒過去（`--top`）。
2. **每條標 `⚠️ 借來的（from: …）`**，並附**各 base 的原文**——你要能像肉眼校驗那樣判斷。
3. ⚠️ **標記由 `emit_lesson` 產生，不要手打。** 標記寫壞了，下一次量測就把它算成
   「這個 base 也獨立撞到了」⇒ 計數餵回推薦、推薦餵回計數，**而沒有人會發現**。

## 步驟

```bash
# 在**新專案的 repo 裡**跑。--exclude 自己：問的是「**別人**獨立撞到什麼」
XB=~/Documents/Projects/KnowField/knowledge/skills/knowie-xbase/xbase.py

# 1. 先看數字（不帶 --threshold ⇒ 拒絕給群；門檻校驗見 knowie-xbase）
uv run python $XB ~/Documents/Projects --exclude <這個專案> \
  --calib "沒有東西會叫的失敗|||沉默的失敗不會自己現形"

# 2. 取「最大一群還不黏」的最高門檻，只留前 12 群
uv run python $XB ~/Documents/Projects --exclude <這個專案> \
  --calib "..." --threshold 0.62 --min-bases 2 --top 12 \
  --emit /tmp/pull.md --out /tmp/pull.json
```

3. **逐條篩**（這一步是人的，不是腳本的）——兩個問題：
   - 它會**改變某條判準怎麼寫**嗎？（不會 → 那是實踐，不是判準，會過期）
   - 它提到**只在別的 repo 存在**的東西嗎？（是 → 不可攜，丟掉）
4. **逐條**貼進這個 base 的 `experience.md`。⚠️ **沒有「全部收下」**——
   跟收件匣同一條線：**captured ≠ committed**。
5. 之後這個 base **真的撞到**其中一條時：**刪掉那一行 `⚠️ 借來的`**、換成實際出處
   （commit／history）。⇒ 它從那一刻起才算這個 base 的經驗，也才進得了跨 base 計數。

## 這一支不做的

`push`（見上）· clone 基礎設施 · 走 KnowField API（現在是 Google OAuth session，
CLI 打 `/api/` 會 401；⚠️ 加機器憑證是**新的對外攻擊面**——等真的換機器再說）·
把 `principles`／`vision` 也拉過來（前者大半在 constitution 裡、後者是專案特有的）。
