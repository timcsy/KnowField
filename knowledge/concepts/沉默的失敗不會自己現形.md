# 沉默的失敗不會自己現形：問「如果它錯了，誰會發現」

> 父概念。2026-08-26 由 `/knowie-judge` 從 `experience` 收攏——**10 條課投影到同一個判準**，
> 而它們原本各自躺著，看起來像 10 個不相干的坑。
> ⚠️ 母概念是 [有吸引子的場](有吸引子的場.md)：這一條講的是**場的儀器**，
> 而場的儀器壞掉時**場看起來完全正常**。

## 這個概念的主張（可以拿文字去判）

> **一個機制只有在「它壞掉時有人會撞到」的前提下才算可靠；
> 沒有消費者會撞到的錯誤，會一直錯下去，而且看起來一直是對的。**

⇒ **修剪力**：拿任何一個「已完成」的東西問——**如果它現在就是錯的，誰會發現？什麼時候？**
答不出具體的人或時刻 → 那件事還沒做完，要另外配一個偵測。
（答得出來的東西不歸這個概念管，不要硬塞進來。）

## 三個投影

- **principles**（規範）：憲章 V 可觀測性；原則 3（資訊可追溯源頭）——
  溯源的價值在**斷掉時看得出來**，而不是在正常時好看。
- **vision**（情境）：每一刀的驗收都要問「這一刀若做壞了，哪個數字會動」；
  對抗測試（先看它變紅）就是這條的操作化。
- **experience**（存在）：下面十條，各是它的一個面。

## 已知的形態（每一種都咬過一次）

| 形態 | 它回報什麼 | 課 |
|---|---|---|
| **儀器讀錯欄位** | 一個看似合理的數字 | 對話由來徽章讀錯欄位 |
| **條件恆真** | 「全部都是」 | `source_entry_id IS NOT NULL`（欄位預設 0） |
| **訊號還沒起算** | 0 | 「0 是還沒到，不是不要」 |
| **指認用時間而非內容** | **成功** | `gh run list --limit 1` 抓到上一次的 run |
| **缺了輸入** | **乾淨** | 文章沒有來源連結 → 糾纏偵測回報「沒問題」 |
| **只擋畫面沒擋路徑** | 一切正常 | 封存過的知識仍在餵 RAG |
| **斷言指到旁邊的字** | 綠燈 | 驗「詞出現過」而不是「規則還在」 |
| **版面被擠掉** | 什麼都沒有 | `opacity-0` 仍佔寬度 ＋ `truncate` 吃掉名字 |
| **命名排除了可能性** | 沒有抗議 | 用「形式」命名一個位置 |
| **冗餘防護的副作用** | 更安全的錯覺 | 封存清 embedding，弄壞復原 |

⚠️ 這張表**會長**。新的一種形態出現時，先問它是不是上面某一種的變體——
是變體就併進去，**不要每次都新增一列**（那樣它就退化成一份坑的清單，失去修剪力）。

## 操作化：三個現成的做法

1. **對抗測試先看它變紅**——沒被錯誤實作撞過的測試，不知道自己守著什麼。
   ⚠️ 而且要確認攻擊**真的打得到**（三種沒落地：測試沒牙／攻擊是 no-op／攻擊打到別條路徑）。
2. **sweep 測試**——「封一件，斷言它不在**任何一份**活的清單裡」。
   比逐一記得每個讀取點可靠。
3. **實跑一次**——`assertRaises` 測的是拋出，不是**呈現**；500 vs 400 只有真的打 HTTP 才看得到。
