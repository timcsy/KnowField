## 為什麼（正中核心）
根公理就是「跟上**趨勢**的成本要極低」。現有**興趣清單**只給「使用者**已知**想看什麼」；
趨勢熱詞補的是「**幫你發現**現在在紅什麼」——兩者互補。這是 discovery，興趣清單給不了。

## 定案的方向（使用者選 A）
從**當日實際抓到的材料**萃取最熱／竄升的關鍵字，在首頁顯示成可點的**熱詞 chips**，
點一下就用它去「拉」（深挖該趨勢）。使用者不必事先知道趨勢。

## 守原則（硬約束）
- **原則 3 溯源**：每個熱詞背後都是**真實抓到的材料**，點下去＝溯源後的文章，不是工具
  憑空講的趨勢。
- **原則 4 可回溯**：熱詞是**描述性**的（今天這些詞實際最常出現/最新）、**可點回**背後
  的真實材料；工具可自由消化但答案要能回溯，措辭中性（「今日高頻」而非「未來會爆」）。

## 併入：live web search 作為活水（2026-07-25）
> **狀態（2026-07-25）**：**已完成**——WebSearchAdapter 接進 digest（opt-in 預設停用、需金鑰），vision 階段 13／spec 015／`history/046`、257 綠。治「追不到剛紅新聞」痛點。
使用者洞見：有些有價值／趨勢的東西**只能靠當下 web search 找**，不只固定名冊
（arXiv/HF/電子報）——名冊訊噪比高，但**看不到剛紅、還沒進論文/電子報的東西**。

- **缺口只有一塊**：Web Search adapter（`query → [(標題,網址,摘要)…]`）。拿到網址後
  **`fetch_url`（2a spec 006 已有）＋消化＋去重＋排序全複用**。＝加一個**可插拔搜尋後端**
  （同 embedder/answerer pattern：預設離線 stub、真實走 API），**非重寫**。
- **選項**：Tavily／Exa（為 LLM/RAG 設計、回乾淨內文）、Brave（獨立索引）、SerpAPI（代爬 Google，貴）；
  或使用者 gateway 若支援 web_search tool 就零額外相依。合規：優先未登入公開頁（見來源研究 episode
  Meta v. Bright Data）。
- **兩用法**：①**拉擴到開放網路**（廣度↑）②**趨勢發現換活水**（補固定池的近因斷層）。
- **概念呼應**：這是 concept 第 3 層**反濾泡／驚訝力**的具體機制——刻意伸手到策展名冊**之外**，
  抓固定來源看不到的。
- **取捨**：成本→**使用者觸發才搜**（不每次 digest 自動搜）；雜訊→靠 LLM-native 搜尋＋既有去重/
  排序/解說文權重把關；溯源（原則 3）→結果帶網址不失守；忠實（教訓 7）→消化照套 grounding。

## 搜尋結果 → 種子？（2026-07-25 往下推）
**能，但『預設短暫、人冊封才留』**——否則雜訊自動變種子＝違原則 5、污染 KB。兩段：
- **搜尋回來的一堆＝短暫的流**（像 pull，預設不落庫、會衰減）。
- **看到有價值的那則 → 點「收進」冊封成種子**（`ingest <網址>`，`fetch_url` 已支援）。機制**現成**，
  只差搜尋結果旁一個「收進」鈕。
- **最深一層**：**搜尋＝AI 撒大網（高召回低精度候選）；冊封＝人挑該留的（主權換精度）。**
  與 **2b 根因萃取同模式：AI 提候選、人冊封吸引子**——live search 只是把候選生成從固定名冊
  擴到整個開放網路。
- **搜尋發現物三個去處（都由人路由）**：有價值文章 → **種子**（ingest）；趨勢關鍵字（是詞非文件）
  → **興趣清單**追蹤／日後成 why-node；只瞄過 → **短暫流、衰減**（不留）。
  → **趨勢＝對 live 流的讀數、種子＝從流冊封下來的點**，兩者分得乾淨。

## 待解／開放問題（孵化重點）
1. **萃取方法**：
   - (a) **LLM 一次呼叫**：「從今天這批標題萃取 6–8 個熱門主題詞」——品質好、貴一點、
     要防幻覺（只能用出現過的詞）。
   - (b) **詞頻／實體統計**（stdlib，零成本）：n-gram/實體計數，或相對某基線的**竄升**
     （今天 vs 前幾天）——最省、最可溯源，但可能較粗。
   - 傾向：先 (b) 統計為底（可溯源、零成本），需要更聰明再疊 (a)。
2. **資料來源範圍（兩條）**：
   - (內) **固定候選池統計**：用全部候選池（未經興趣過濾）反映領域趨勢。但 `digest_entries`
     只落庫 top-N、沒存全池；要 digest 時額外算熱詞並落庫。
   - (外) **live web search 活水**（見上）：補固定池看不到的剛紅趨勢。使用者觸發、可冊封成種子。
   - 兩條互補：內＝穩定的高頻/竄升讀數、外＝即時的開放網路發現。
3. **排序**：純高頻 vs **竄升**（今天相對前幾天的成長）——竄升更像「在紅」，但要存歷史。
4. **數量／呈現**：首頁頂端 6–8 個 chips？點擊 → `/pull?topic=<熱詞>`。
5. **時機**：在每日 digest 時一併算好落庫（CronJob 友善），web 只讀顯示——不在 web 請求
   即時算（貴）。
