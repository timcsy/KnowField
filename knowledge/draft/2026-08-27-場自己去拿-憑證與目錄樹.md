# 場自己去拿：憑證的形狀，與「只要樹不要內容」

> 狀態：**draft／設計已定調（2026-08-27 使用者拍板），實作未開始**。
> 從 [knowie 接進來](2026-08-27-knowie接進來-讀而不寫.md) §六 分出來——那一節說「先不要當 runtime」，
> 而這一份是**使用者決定要往那個方向走一步之後**，該怎麼走。

## 起點：使用者要的是方便

> 「我希望可以直接複製 git 網址過去就可以方便使用的，**存取權越方便拿到越好**（private repo），而且是**好的 UX**。」

我先後兩次拿「攻擊面」擋過這個方向。使用者兩次都重申 ⇒ **這是他的決定**，接受，改成設計問題。

## 一、實查：雲端 agent 實際怎麼接 GitHub（2026-08-27）

**Codex cloud**——連的時候你**自己挑哪幾個 repo**；每個操作用**短命、最小權限的 App installation token**，
尊重原本的 repo 權限與 branch protection。容器流程：建容器 → checkout → 跑 setup script → 套網路設定。
**兩階段**：setup 階段有網路有 secrets，**agent 階段預設離線、且 secrets 在它開始前就被移除**。寫回＝開 PR。

**Claude Code on the web**——兩條路：裝 GitHub App，或 `/web-setup` 把你本機 `gh` 的 token 同步上去。
ⓘ 而它自己文件寫得很白：cloud session 存取得到「**連接帳號看得到的任何 repo**」，
「App 安裝**不是 session 層的存取控制**」——要限制得在 GitHub 那邊限制帳號。
憑證**從不進沙盒**，由一個**代理**持有 scoped credential，**在請求到達 GitHub 前就擋掉 push**。
沒有 GitHub 連線時的退路：**本機打包上傳，而那種 session 不能 push 回去**。

⇒ 兩家花大力氣蓋沙盒／代理／網域白名單，是因為它們要**執行程式碼並寫回去**。
**KnowField 兩件都不做** ⇒ 那一整套不需要。可抄的只有兩條：
**拿資料的階段可以有憑證、處理資料的階段不能**；以及**唯讀要做在結構上**（token 不給 write scope）。

## 二、決定：GitHub App，而且它**同時是比較好的 UX**

| | 貼 PAT | GitHub App |
|---|---|---|
| 你要做什麼 | 進設定→找頁面→勾 scope→複製秘密→貼過來 | 按「連結 GitHub」→在 GitHub 勾 repo→跳回來 |
| 過期 | 會，壞了還不講為什麼 | 不會（背後換發） |
| 撤銷／加 repo | 重產一次 | GitHub 設定裡點一下 |

⇒ **安全的那條跟方便的那條是同一條。** 這不是取捨。

`Contents: Read-only` 一個權限就夠。⚠️ 而 App 的 private key **自己讀不到任何東西**——
它只能替**你批准過的安裝**換發 token。

### 而且不用 clone

實查：正式環境容器裡 **`git: not found`**。而走 API 根本不需要它——
Trees API（`recursive=1`）一次拿到檔案清單，然後**只抓 `knowledge/**` 的 blob**。
⇒ 不裝 git、不用磁碟、不用等下載，而且**場裡從頭到尾只有 markdown**。

（token 讀得到整個 repo——GitHub 沒辦法按路徑授權——但**程式只去拿那個資料夾**。
你在 GitHub 勾了哪些 repo 就是實際範圍，所以那一步值得慢慢勾。）

## 三、目錄樹：要結構，不要內容（使用者提的）

> 「或許 knowledge 以外的也可以拿到目錄樹，但不用拿內容。」

**而樹本來就在手上**：`recursive=1` 那一次呼叫就回整棵樹，找 `knowledge/**` 用的正是它。
**不留它是一個選擇，不是省下什麼。**

### 它能做、而內容做不到的三件

1. **跨 base 的死指標檢查——今天完全沒人做得到。** 每條教訓的「來源」指著一個路徑
   （`src/knowfield/store/repository.py`），而**那個檔案還在嗎？** 沒有樹就無從得知。
   本 base 就有兩條教訓指著 `digest/builder.py`，而它在 `5cb07b9` 就被刪了。
   ⇒ 這是 judge 那條 dead-reference，而它是**全稱**問題（每一個，不是 top-k）
   ——[§四](2026-08-27-knowie接進來-讀而不寫.md) 說「要全部的時候不要用 RAG」⇒ **樹是它唯一的解法**。
2. **給查詢補上「形狀」。** README 講「這是什麼」（＝你已經知道的），樹講「你在蓋什麼形狀」。
   對話給「你怕什麼」＋樹給「你在蓋什麼」，合起來比單獨一個好。
3. ⚠️ **結構的跨 base 比對——先不要做。** 「你 4 個專案都有 `e2e/`」是**流行度不是判準**，
   跟「只算撞到不算借走」同一個陷阱換件衣服。要做也只能純呈現、不進推薦排序。

### 三個誠實的代價

- ⚠️ **檔名本身就是內容。** 樹會洩漏內部代號、客戶名、未公開的功能名、`secrets.enc` 的存在。
  比抓內容小非常多，但**不是零**。
- **會爆量。** monorepo 或 commit 了 `node_modules` 的 repo 可以到幾萬條（GitHub 自己也截斷）
  ⇒ 濾雜訊目錄＋設上限，而且**截斷了要說**，不能靜默。
- ⚠️ **樹一抓下來就開始過期，而沒有人會發現。** 正是「死的知識不是靜止的知識，
  是沒有任何消費者會發現它錯掉的知識」⇒ 存 `fetched_at`，死指標報告要顯示「根據 N 天前的樹」，
  否則它會給你一份**看起來很權威的過期報告**。

## 四、分類：樹是第三種東西

| 類別 | 是什麼 | 去哪 |
|---|---|---|
| **可拉的** | 判準（experience）· 概念 · 原則（當**範例**） | 收件匣，逐條冊封 |
| **佐證** | history · episodes | 掛在可拉的項目上，給人判斷用 |
| **查證用的事實** | **目錄樹** | ⚠️ 不給人讀、不進收件匣、不當判準——只回答「這個路徑還在嗎」 |

⇒ 抓進來之後**不要跟其他六層混在一起**。
