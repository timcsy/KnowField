# 對話的暫時存檔（自動、TTL 衰減）＋永久存檔（人閘門）

> 狀態：**✅ 已完成、已反流、保留為設計記錄（history/067）**（spec 028、vision 階段 23、history/067；441→456、commit `51e4489`）。
> 因果與洞見（膜正向運作、對應 knowie draft 層）已 reflow 到 history/067。日期：2026-08-03。

## 由來
使用者「不能存檔」踩雷後怕丟東西，問「能不能自動存檔？」。討論用膜頂回去：**自動存全部＝打臉 spec 023
「預設流走、不囤積」**（剛花 025/026 清完 19→4 複本）。使用者自己提出更好的模型：**暫時存檔（自動、閒置一段
時間刪）＋永久存檔（手動）**——這**正是 knowie 的 draft 層**（捕捉了、預設衰減、動它才留）＝「captured ≠
committed」投影到產品；「閒置就刪」把**「預設流走」從口號變成機制**。使用者定 **TTL＝7 天**。

## 兩層
| | 暫時存檔 | 永久存檔 |
|---|---|---|
| 觸發 | **自動**（每輪完成後 upsert） | 人按（存這段／冊封連同存） |
| 命運 | **閒置 > 7 天 → 自動刪** | 留著（無 TTL） |
| 對應 | draft（短期、衰減） | episodes（沉澱、committed） |
| 標題 | **便宜**（首句截斷、**不每輪呼 LLM**） | 升永久時才生落點標題 |

## 設計形狀（plan 再定細節）
- **自動暫存**：live 對話一筆（**upsert、非每輪新增**）——client 記 temp_id，首次 POST 建、後續更新 messages＋
  last_activity。每輪完成（串流 done）後觸發。
- **TTL 衰減**：`last_activity_at`；每次新對話/接回**重設計時**。判準純函式 `expired_temp_ids(convos, now, ttl_days)`
  離線可測。
- **懶清、不開背景排程**：`/conversations` 載入 或 存檔時順手 `purge_expired_temporary(now)`。
- **升永久**：按「存這段」/冊封連同存 → 該筆 `temporary=0`＋生正式標題（**不新增重複**）。
- **UI**：`/conversations` 分「永久」「暫存（會自動清除）」兩區；暫存每筆有「轉永久」。

## 硬約束（對齊原則/教訓）
- **不囤積**（原則 6 味）：暫存會衰減＝「預設流走」機制化。**不污染**：暫存仍是沙盒層、**絕不注入回場**
  （既有 build_field_system_prompt 只吃冊封根因的守衛已涵蓋，仍寫測釘）。
- **人閘門**（原則 5）：**升永久**是人按；自動暫存不等於承諾。
- 教訓 1 離線 stub：TTL 判準純函式、標題可注入可測。教訓 3：autosave 失敗不該擋聊天（best-effort、不崩）。
- 教訓 8：conversations 表加 `temporary`＋`last_activity_at` 欄（冪等 migrate；既有存檔＝永久 temporary=0）。
