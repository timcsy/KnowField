# 跨專案聯邦與兩種冷啟動：判準與做法要走不同的管道

> 狀態：**draft／未定案設計（thinking-line）**。日期：2026-08-16。
> 怎麼冒出來的：使用者觀察到各大 AI 平台主畫面都有「對話 / 代理」兩種模式的切換，想到 KnowField 和
> knowie 或許也有類似分工；再往下推成「開發知識散落一地，該做一個共同開發知識庫，但保有專案界線」，
> 最後用細胞／組織／器官的比喻收束。全程 chat-only 發想。

**這是同一個主題的第三次快照**——見 [共享的膜與跨 base 聯邦](2026-08-03-共享的膜與跨base聯邦.md)
（2026-08-03 開，2026-08-06 補 C-MVP 與上線分階）。同主題累積出第三個快照，本身就是「該固化」的訊號。

---

## 先接回去：這不是被否決的「匯集」，但只差一條紀律

⚠️ 舊快照裡有一條已否決的框架：`❌「匯集各 base → 變共享知識」（匯集優先）＝典型過度抽象＋
共享的膜缺席＝共享的污染`。這輪討論的「共同開發知識庫」跟它長得很像，必須講清楚差在哪。

差別只有一條：**掛載進來的是候選，不是條文**。過本地閘門、落 `draft/`、由本專案冊封才收下——
那就是舊快照 C-MVP 的機制（「發布一條根因（帶出處）＋別人把它當候選、過自己的試金石＋自己冊封才收下」），
只是聯邦的對象從「別人」換成「自己過去的專案」。而舊快照的分階本來就寫著先聯邦自己的 base。

**少了這條紀律，共同開發知識庫就是那個被否決的匯集。** 這是全篇最容易掉的一句。

## 新的東西 1：有兩種冷啟動，要的東西剛好相反

這是這輪最值錢的一段，而且它**修正**了 knowie 那邊 2026-08-14 的推論
（`knowie/knowledge/draft/2026-08-14-跨專案判準複利與冷啟動.md`，主張「判準會走、做法隨技術棧過期」）。

那條只對**異領域**冷啟動成立。使用者舉的例子是「今天要做前端應用」——同一片技術領域再來一次，
這時排序整個翻過來：

| 冷啟動類型 | 例 | 真正省時間的是 | 判準式教訓的角色 |
|---|---|---|---|
| 異領域 | 新聞分診 → 電路 CAD | **判準**（做法是雜訊） | 主體 |
| 同技術領域 | 前端 → 前端 | **做法原文**（重踩要一天，套用只要一秒） | 你早就內化了，不省時間 |

本庫 35 條教訓裡，對「再做一次前端」最值錢的正是那些綁技術棧的：
`CJK 輸入法組字中的 Enter 不該送出（isComposing）`、
`後端處理的路由前綴，都要同步加進 PWA SW 的 navigateFallbackDenylist`、
`具體路由要註冊在 catch-all mount 之前，否則被吃掉`。

**推論：跨專案層不能只是一份蒸餾物。** 「560 條壓成 30–50 條母判準」這種收斂，會正好丟掉同技術領域
冷啟動要的那一層。所以要兩層，掛載觸發條件不同：

- **判準層**——少、收斂過、任何新專案都掛。答異領域。
- **技術領域層**——多、原文保留不蒸餾，只在技術棧對得上時才掛（從 `package.json` / `pyproject.toml`
  判，比對 tag）。答同技術領域。

## 新的東西 2：掛載機制——skill 用投影，知識條目不能

已經在跑的 skill 投影（`knowledge/skills/` → `.claude/skills` / `.agents/skills`，per-item 相對 symlink）
**不能直接搬給知識條目**：symlink 是同一個檔，在專案 B 改它等於改了源，而掛載進來的東西按定義必須
在本地被重新判斷。

- **skill → symlink**：它到哪都是同一個東西，沒有在地判斷的問題。
- **知識條目 → 指標**：`draft/` 裡放一行存根，帶 `origin`，指回源。本地能自由批註、判斷、否決，源不動。

不過境的：vision、history、episodes、根公理、綁領域的 skill——那些是 endeavor 自己的，搬走沒有意義。

## 新的東西 3：反流是跨專案層唯一的除錯通道

各專案至少有現實在糾正——測試會紅、部署會炸、沒人用你就知道錯了。**跨專案層沒有這個接觸面**：
一條爛判準躺在那裡不會怎麼樣，它只會一直看起來有道理。

⇒ **它的唯一除錯訊號是反流**（「這條在專案 B 不成立」）。沒有反流的共同庫，會長成一本沒有任何東西
反駁得了的格言集——而那正是 knowie 整套設計要防的東西。

配套的機制發現：**第二個專案是第一個專案的邊界測試。**
「不適用的時候」這一欄（0.7.3 加進 experience 模板的），**在學到它的那個專案裡寫不出來**，因為手上
還沒有對照組。只有它被掛進第二個專案、然後不成立，那個邊界才長出來。

所以反流不該是另一個「記得同步」的儀式，該掛在**取用的那一刻**：一條浮上來、你用了或判它不適用——
前者確認，後者填邊界。兩種都是資訊，不用額外花力氣。

## 新的東西 4：細胞比喻——買到什麼，以及必須剪掉的三處

舊快照的四透鏡已經盤問過生物透鏡，並標出它的騙人處（`免疫優化「自己/非己」，知識要優化「真/假」
——正交`）。這輪用的是**細胞／組織／器官**這一支，抓到的是不同的三刀。

**買到的：分化。** 每個細胞帶同一份基因組，差別只在表現了哪些基因。所以問法要改——不是
「這個專案要領哪些條目」，而是**這個專案表現了哪些**。源永遠是同一份（呼應「指標不是內容」）。

**買到的：受體在接收端。** 組織內＝縫隙連接（貼著、高頻寬、傳原文＝技術領域層）；跨器官＝內分泌
（灑進血液、低頻寬、只帶得動判準）。而荷爾蒙灑給所有人，**只有帶受體的細胞會反應**——
廣播很便宜，貴的是反應。⇒ 共同庫不必決定推給誰，只要讓東西可被碰到。

必須剪掉的三處：

1. **細胞沒有主權，你有。** 受體結不結合是化學不是判斷。⇒ **傳遞可以自動，表現不行**——
   訊號自己流過來沒問題，要不要表現是人點頭（＝原則 6 的閘門，別因為換了比喻就鬆掉）。
2. **生物不缺 oracle，因為死亡就是 oracle。** 表現錯基因的細胞會死、被選擇清掉。共同庫沒有死亡，
   ⚠️ 這個比喻最危險的地方就是它讓你以為收斂會自己發生。生物靠死亡免費換到的，你只能靠反流手工造。
3. **癌症是它自帶的失敗模式，而且給了藥方。** 癌細胞不是特別會分裂，是**它聽不見周圍叫它停的訊號**。
   知識庫版本：一條判準到處被掛上、從沒被否決過——因為接受免費，否決要花力氣寫理由。
   ⇒ **否決必須跟接受一樣便宜。** 這是「條目多到變負債」的機制性解釋：不是產太多，是抑制那側從沒建。

**組織不該用宣告的，該用觀測的。** 一塊組織的身分是那群細胞的表現輪廓長得像，不是誰畫線。所以
「類似的專案形成組織」不該是手動開資料夾歸類，該是被看出來的——那就是
[有吸引子的場](../concepts/有吸引子的場.md) 的**成核**（流一直在沒有吸引子的區域聚集 → 該冊封新的）。

⚠️ 舊快照的馬太陷阱在這裡照樣適用：**「多少個專案採用了這條」絕不餵回浮現排序**（共識引力的跨專案版）。
同一條在單人版是 [收進的活化沉降與核心理解拓撲](2026-08-05-收進的活化沉降與核心理解拓撲.md) 的
「引用頻率別餵檢索排序」。

## 新的東西 5：兩條線的工程方向相反

|  | 吸收型（KnowField） | 開發型（跨專案層） |
|---|---|---|
| 語料 | 外部、海量、有 ground truth | 自產、少量、沒有 oracle |
| 難的地方 | **過濾**：什麼值得你的注意力 | **收斂**：多壓成少 |
| 器官 | 漏斗 | 蒸餾器 |

兩邊都叫知識庫，但一個往裡收、一個往上壓。**這比「對話型 vs 開發型」是更硬的分家理由**——
硬做成同一個系統加模式切換，等於逼同一套機制做兩份相反的工。

而接點在於：開發型需要的「相關時才浮上來」，正是吸收型這邊已經建好的引擎。
〈有吸引子的場〉的「人冊封吸引子、場動力學自動跑」，換到開發型就是「哪條能立為母判準是人的事，
什麼時候浮上來給你看是機器的事」。**KnowField 建的器官，正好是跨專案層缺的那一個。**

## 外部框架：平台的模式切換

各大 AI 平台主畫面的 Work / Agent / Code / Spark（各家名字不同）——它們切的不是知識種類，是
**掛載了哪一份語料**（Work 掛組織的、Code 掛這個 repo 的、Spark 掛這個工作區的）。這對上了本篇的
「共同庫 ＋ 專案界線」。

按 knowie 的既有教訓「外部框架是照出 stated-why 的鏡子」，它進得來是因為**它替我們早就在做但沒名字的
東西命了名**（有範圍的掛載），不是因為它有趣。

它的弱點也要記：**模式切換要人在動手前就挑對語料**，但你常是做到一半才發現另一個專案的某條判準適用，
那時已經來不及切。⇒ 要的不是切換器，是相關時浮上來的東西。

而「對話 vs 代理」那一刀切的其實是**迴圈歸誰握**（對話每輪回到人手上，代理連跑很多步才回來），
不是主題。它出現在主畫面上是一種認輸：沒辦法讓一個模式服務兩種用法，只好讓使用者自己挑。

## 界線有兩種，只有一種會複利

- **界線＝隔離**：A 專案的知識不流到 B。這是現狀——六個庫互不污染，也互不受益。隔離滿分，複利是零。
- **界線＝出身**：條目搬到哪都記得從哪來、在什麼處境掙到的、後來在別處成不成立。

要的是後者。（這跟舊快照的**出處向量**是同一條，只是那邊是跨人、這邊是跨自己的專案——
兩條獨立推導指到同一個機制。）

⚠️ `origin` 指向外部 repo 會腐爛（改名、搬走、轉私有）。所以**判準本身和它的邊界要自帶、看得懂**，
外部只留 how 那條腿（code / spec / commit）。這跟根公理 2「how 用指標不複製」不衝突：
不能丟的是 why，不該重複的是 what。

## 本庫現況：目前產不出可攜條目（實測，2026-08-16）

這是整件事的**阻塞點**，不是題外話。

- `history/` 93 條；全庫 markdown 連結 14 條，其中**指向 `history/` 的是 0 條**（另有 40 處純文字路徑
  提及，人讀得到、機械檢查抓不到）。
- `episodes/` 5 個。`vision.md` 的 `[x]:[ ]` ＝ 226:6。
- `history/008-拉模式完成.md` 的轉移欄寫著 `舊：只有推（每日分診）；拉模式僅為 draft 設計。`
  ——把「還沒做」寫成「舊」，那是進度條不是轉移（0.7.3 新規矩要抓的正是這個）。

**為什麼這擋住聯邦**：一條沒有現場的教訓，判不出它適不適用。教訓 → 現場那條連結斷著，抽出去的會是
一疊沒有邊界的結論——而那是最容易被誤用的形態。

⇒ **順序：先修本地代謝（跑 judge），再談抽取，最後才是掛載。**

## 候選（⚠️ 只提議，等人定案）

- **判準候選 A**：「死的知識不是靜止的知識，是**沒有任何消費者會發現它錯掉**的知識。」
  本庫的 93 條孤兒 history 就是實例——它們天天隨 commit 移動，一點都不靜止，但沒有東西會因它們錯而出問題。
- **判準候選 B**：「**否決必須跟接受一樣便宜**，否則增生沒有相對應的凋亡。」
- 兩條都是判準式（不是做法式），若成立該進 `experience.md`；但它們來自分析、還沒被兌現驗過，所以留在這裡。

## 出口

- design + problem 型 → 出口是（a）人冊封母概念／判準，或（b）成熟後升 vision 路線圖（帶驗收 ＋ 雙向連回本檔）。
- **先做得起來的最小一步**：跑 `/knowie-judge`，把上面「本庫現況」那三件事修掉。在至少一個庫能產出
  **帶著現場的可攜條目**之前，跨專案層不值得建。
- 反流待辦：本篇的「兩種冷啟動」修正了 knowie 那份 draft 的單軸推論，該送回去；
  另外「〈有吸引子的場〉與 knowie 分工同構」這件事，knowie 的五專案審計把 KnowField 歸進「兩兩不相干」，
  是漏的，也該回流。
