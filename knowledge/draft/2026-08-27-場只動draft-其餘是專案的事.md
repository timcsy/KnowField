# 場只動 `draft/`——其餘是專案的事

> 狀態：⚠️ **已被取代**（2026-08-27，同日）——見
> [專案就是來源](2026-08-27-專案就是來源-而模式是你在幹嘛.md)。
> 使用者改了方向：「**就不要跟 draft 扯上關係了**⋯專案就像是一個來源一般」
> ⇒ 聊完的結果**冊封進你自己的場**，不寫回任何 repo。spec 077 整支退役。
>
> 本檔保留為**當時的分析**：那條「只動 draft ＝ 只動短期記憶」的界線本身是對的，
> 只是那個方向沒有被走下去。
>
> 原狀態：draft／設計已定調（2026-08-27 使用者拍板），實作未開始。
> 從 [knowie 接進來 §七](2026-08-27-knowie接進來-讀而不寫.md) 分出來——
> 那一節做了開發模式的**閱讀**（已出貨），這一份是它的**寫**那半。

## 起點

> 「我想要對專案也可以聊，也可以互動（來源、互動、理解、應用），但是是**以專案開發為目的**的，
> 然後會**收進 draft** 之類的。」
> ⋯「我們**只會動 draft**，代表**短期記憶**。至於**如何處理 draft 就是專案的事了**。」

## 決定：那條界線

**KnowField 對別的專案，只寫 `knowledge/draft/`。**

它不是「先做這個、之後再做別的」——是**能力邊界**：
寫入路徑**只組得出** `knowledge/draft/*.md` 這種檔名，掃程式碼就驗得了
（`history/131`：禁令做在結構上，不是紀律上）。

而它剛好對齊 knowie 自己的分層：**draft ＝ 捕捉那一層，本來就不需要誰批准**
（`captured ≠ committed`）。往上每一層都需要判斷，而那個判斷**是專案的**
——用那個 repo 自己的 `knowie-consolidate`／`judge`。

## 兩個方向因此對稱了

| 方向 | 落在哪 | 誰決定它留不留 |
|---|---|---|
| 別的 base → 這個場 | **收件匣**（`status='candidate'`，階段 67） | 你，`anoint_why_node` |
| 這個場 → 別的 base | **`draft/`** | 那個專案，`knowie-consolidate` |

⇒ **兩邊都是收件匣，而閘門都在「收的那一側」。**
這不是新發明——是 [room 與組織的 AI](2026-08-27-room與組織的AI-人的樹.md) 那條
「共享空間必須是**收件匣，不是資料庫**」的第二次套用，只是這次往外。

## 三個跟著解掉的

**一、「兩份記憶會漂」消失。** KnowField 不持有那個專案的記憶——它是**投遞口**。
權威始終只有一個：repo 裡的 knowie。（這正是根公理 2 在防的東西。）

**二、開發模式的四個入口塌成兩個。**

```
💬 互動   → 落在 KnowField（對話在 repo 裡沒有家）
📚 來源   → 那個 repo 的 knowledge/（唯讀，階段 68 已抓）
💡 理解 ┐
🧩 應用 ┘ → 都是「**產出一份 draft**」，差別只在那份 draft 裡裝什麼
```

⇒ 冊封不再是 KnowField 的動作，它變成「**提議一份 draft**」；真正的冊封在那個 repo 裡發生。

**三、迴圈自己閉合。** draft 寫出去，下次「重新抓」它就以 `ext_item` 回來
⇒ **不需要另外存「我送出去過什麼」**。

## ⚠️ 而 draft 會衰減——所以互動要留在場裡

knowie 的 draft **預設衰減**。⇒ 投出去一份 draft **不等於那個知識被保存了**，
它是一份**有保存期限的提議**。

⇒ 這反而說明了為什麼**互動必須留在 KnowField**：
對話是那次思考的**耐久紀錄**，draft 只是它的沉澱物提案。兩者不能互相取代。

## 寫回去的形式

只建新檔、不改舊檔 ⇒ **開 GitHub 的「新檔案」頁面、內容預填**就夠：

```
https://github.com/{owner}/{repo}/new/{branch}?filename=knowledge/draft/YYYY-MM-DD-x.md&value=…
```

⚠️ **而選它最強的理由不是安全，是「作者是誰」。** 讓 bot 往你的知識庫 commit，
`git log` 就不再分得出哪些是你寫的、哪些是工具生的——而這整個專案的認識論
（`origin: self`／`self:judgment`／`from:`、原則 5「權重由人冊封」）就是在做那條線。
按下 commit 那一下**就是冊封**，它不是多餘的摩擦，是閘門本來的位置。

⇒ 附帶：**不需要 `Contents: Write`**，App 維持唯讀。

### 兩個要實測的

- ⚠️ GitHub 那個頁面的 `value` 參數**吃多長**？一份 draft 常常幾 KB。
  不夠就退回複製按鈕——而**要說清楚為什麼退**，不是靜默降級。
- 私有 repo 的那個頁面吃不吃預填。
