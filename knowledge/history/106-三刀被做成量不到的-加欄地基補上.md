## 擋在前面的地基：專案不會加欄

`schema.py:148`（當時）：「不含舊 SQLite 檔的 `_migrate` 補欄」。
而 `CREATE TABLE IF NOT EXISTS` 對既有表是 **no-op** ⇒ 正式庫既有的表不會長出新欄。

spec 039 沒踩到是因為它加的是**新表**；spec 043 的「文章存 `conversation_id`」
就是被這件事擋掉、列進 out of scope 的。⇒ 一個地基卡住兩件事，才動手蓋。

**兩個關鍵否決**（都在 `plan.md` D1）：

- ⚠️ **否決 `ALTER TABLE … ADD COLUMN` 包 try/except**：那會把「欄已存在」
  跟「型別寫錯／表不存在／權限不足」混成同一件事——真的錯了也靜默過去。
  這正是本專案 48 小時內連撞兩次的那類（[102](102-譯文快取-從逐文件改為逐單位.md) 的 import 路徑錯被吞、
  [104](104-重繪擦掉排版而effect不再排-公式永久卡成原始碼.md) 的 typeset 失敗被 `.catch(() => {})` 吞）。
- ⚠️ **否決 `ADD COLUMN IF NOT EXISTS`**：PG 有、**SQLite 沒有** ⇒ 破雙後端 parity（spec 036）。

⇒ 走「先問有哪些欄、缺的才加」。宣告式一張清單，**不是 migration 框架**——
代價講明：不支援改型別或刪欄，真的需要時再升級。
