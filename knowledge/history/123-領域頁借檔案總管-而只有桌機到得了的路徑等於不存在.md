# 123：領域頁借了檔案總管，而「只有桌機到得了的路徑」等於不存在

- 日期：2026-08-26
- spec：[057](../../specs/057-explorer/)、[058](../../specs/058-explorer-polish/)、[059](../../specs/059-tap-vs-scroll/)、[060](../../specs/060-menu-fixes/)
- 階段：vision 階段 52–55

⚠️ **一份蓋四刀**，因為那四刀是**一條弧**，不是四件事：
蓋出檔案總管 → 發現觸控完全到不了 → 修輸入模型 → 修「修出來的洞」。
拆成四份會把弧切碎，而弧才是可召回的單位。

## 轉移

| | 之前（階段 45 出貨時在行的） | 之後 |
|---|---|---|
| 領域頁的比喻 | **整理台**——自己造的名字與版面 | **檔案總管**——借一個人已經會用的比喻 |
| 互動模型的預設 | **桌機**：hover 出勾選 · 右鍵出選單 · `hidden md:block` 藏樹 | **觸控是一等公民**，且觸控**刻意不啟用**指標拖曳 |
| 手機拖放 | 想做（階段 45 用 Pointer Events 就是為了它） | **明確放棄**——在觸控上，拖曳與捲動的開頭一模一樣 |

## 四刀，各推翻了什麼

**① 檔案總管（spec 057）**——使用者：「這個頁面可以弄的**更像檔案總管**一些」。
推翻的是「整理台」這個**自造的比喻**：人已經會用資料夾，不需要學一個新的。
⚠️ 但擋在前面的不是元件是**容器**：`Layout.tsx:41` 把非聊天頁鎖在 `mx-auto max-w-3xl`
——兩欄檔案總管在那個框裡不可能成立。判準已沉澱進 experience。

**② 手機上只能看不能用（spec 058）**——① 出貨的那一頁有**三件事在觸控上到不了**：
選取（只有 `group-hover`）· 改名／封存（只有右鍵）· 領域樹（`hidden md:block`）。
而 KnowField 是 PWA。⇒ 這是「只有一種輸入裝置到得了的路徑」**第二次**
（第一次是 spec 050 的 HTML5 DnD）。⚠️ **三條路全都不會報錯**——它們只是不存在。
裁決：兩邊的慣例**不用同一套硬套**（手機抄 Files／Drive、桌機抄 Finder）。

**③ 滑動不是點選（spec 059）**——使用者：「現在在手機上面**滑動就會被視為點選**」。
查下去發現更嚴重的：`beginDrag` 綁 `pointerdown`，捲一下 `armed` 就 true，
手指停在資料夾列上放開＝**真的把知識搬過去**（而資料夾就排最上面），畫面只閃一句「搬好 1 件」。
⇒ 從「補一個門檻」升級成**能力縮減**：觸控不啟用指標拖曳，改走長按選單。

**④ 修「修出來的洞」（spec 060）**——③ 讓長按進批次模式，然後**退不出來**
（兩個進入來源，按鈕只看其中一個）。順手殺掉「存下這段」：它會把 `tempId` 清成 null，
下次 autosave 另開一段 ⇒ **按一下等於複製一份對話**，而畫面顯示「已存下」。

## 這條弧的形狀本身

四刀都在同一天，而**每一刀的問題都是使用者實際伸手用才冒出來的**，
不是測試、不是我的實跑（我的實跑在桌機瀏覽器上，那裡三條路全都通）。
⇒ 呼應 experience「真實使用是照妖鏡」——但這裡的版本更窄也更硬：
**當你的驗證裝置和使用者的裝置不同，你的實跑證明不了那一頁能用。**

ⓘ 沒有另抽 episode：這條弧的教訓已經逐條進 experience（10 條，`spec 057`–`060` 為來源），
現場的價值就在上面那張轉移表裡，再抽一份只會多一個入口指向同樣的東西。
