# 099：可插拔介面的沉默代價——健康檢查要說得出「能力」

> 日期：2026-08-21。**決策轉移**。觸發＝使用者回報「K3s 那邊我怎麼好像沒看到新加的功能」。

## 轉移

- **舊**：可選能力的相依放在**可選 extra**（`pyproject` 的 `s2t`），介面缺席時走 identity
  fallback。理由引的是 experience「把重量級相依藏在可插拔介面後，預設離線 stub」。
  健康檢查是 `{"ok": true}`。
- **新**：**執行期會用到的相依一律進執行期 extra**（`web`）；可插拔介面與 fallback
  **保留當防線**，但不再兼任「要不要安裝」的決策。`/healthz` 回報 `capabilities`。

## 為什麼變

spec 037（簡→繁）上線之後，**在 prod 完全沒作用**。使用者看不到那個切換，因為
`s2t_applied` 永遠是 false——`Dockerfile:20` 裝的是 `.[web]`，而 OpenCC 在可選的 `s2t` extra。

我自己設計的 identity fallback 於是生效：**不轉換、不報錯、`/healthz` 照樣回 `{"ok": true}`**。
本機有裝所以全綠、測試對缺席情形有 skip 標記所以也綠。**沒有任何訊號會因為這個功能是啞的而改變。**

⚠️ 兩個各自獨立的錯：

**一、誤引教訓。** 「重量級相依藏在可插拔介面後」那條的理由寫得很清楚——
「TDD 會變成先裝好幾百 MB 才能跑第一個測試」。而 `opencc-python-reimplemented` 是純 Python、
**5ms 裝完**。⇒ **引用一條教訓時要連它的理由一起檢查，理由不成立時結論也不成立。**
可插拔介面該留（防後端掛掉），但「因此列為可選安裝」是另一件事，我把兩者綁在一起了。

**二、`history/087` 坑 2 的原樣重演。** 當時是 `httpx` 只在 `dev` extra、執行期要 import
→ 本機測綠、prod crash，修法就是移進 `web` runtime deps。同一個坑第二次。
**差別是這次沒有 crash，只是安靜地什麼都不做——更難發現。**

## 治本：讓「功能是不是啞的」變成看得見的

`/healthz` 從 `{"ok": true}` 改成回 `capabilities`（各能力的布林）。

- **`ok` 與能力分開**：能力缺席是**降級不是掛掉**，k8s 探針不該因此重啟 pod。
- **只回布林、不回設定內容**：這個端點免登入可探。
- 測試包含「引擎不可用時旗標必須翻 False」——**不會變的旗標等於沒有旗標**，那正是原本
  `{"ok": true}` 的毛病。

⇒ 部署後要核對的從一件變成兩件：**digest 對了，功能仍可能是啞的**。
寫進 `deploy/README` 與 [run-knowfield](../skills/run-knowfield/SKILL.md)。

## 這條與那個概念候選

它是「**一個不會因為事情為假而改變的訊號，不能用來確認那件事**」的又一次兌現——
`{"ok": true}` 在功能全啞時長得一模一樣。相關教訓已累積到十一條以上，母概念仍待冊封。
