## 四、⚠ 燒掉一小時的坑：ghcr token 過期 → buildx push 靜默失敗 → 部署白做
- **現象**：連續數次「改碼→build→rollout→healthz 200」全部成功，但使用者手機/線上**完全看不到任何更新**（回答仍在舊 max_tokens 斷、新功能不出現）。
- **診斷**：`kubectl exec pod -- python -c "Config.from_env().chat_max_tokens"` → **AttributeError**（pod 跑的是舊碼）；比對 **pod imageID digest 一小時沒變**。回頭看 buildx：**`docker login ghcr.io` 的 token 過期**，`buildx --push` 於是 build 成功、**push 靜默失敗**（結尾沒有 `pushing manifest done`，但 exit 0 不明顯），rollout 每次拉到同一個舊 digest。
- **修**：`gh auth token | docker login ghcr.io -u timcsy --password-stdin` 重登 → push 成功。改用 **git sha 當唯一 tag**（`ghcr.io/…:<sha>`）＋**部署後核對 `pod imageID digest ＝ 這次 build`**，不再信任「rollout 成功」。
- → 升 experience。

## 五、⚠ 插一刀的坑：PG 密碼存在 /tmp 被清 → helm upgrade 用預設密碼 → 站一度掛
- `helm upgrade` 需帶 `--set postgres.password`（PG 密碼固定在 PVC）。我存 `/tmp/kf_pgpw.txt`，**被系統清掉** → upgrade 用了 values 預設 `change-me-postgres` → 新 pod 連不上 PG → rollout timeout、站一度掛。
- **救回**：從舊 ReplicaSet 的 `env KNOWFIELD_DATABASE_URL` 撈回真密碼（`ZxX-…`）、存回、重 upgrade。資料全程安全（在 PVC）。
- → 教訓：**關鍵密鑰別只放 /tmp**；chart 應改成「密碼從自動生成的 Secret 讀」免每次帶（未做，記著）。
