# 104：重繪擦掉排版、而 effect 不再排——公式**永久**卡成原始碼

> 日期：2026-08-21。**缺陷與修正**（推翻 [100](100-數學渲染全面檢查-四個缺陷與前端測試從零到有.md) 那次檢查的完備性）。
> 由 spec 042 真跑照出；commit `3aa6b46`。

## 轉移

- **舊**（`history/100`，2026-08-21 上午的「全面檢查」）：數學渲染的四個缺陷都修了，
  判準也改成用 DOM 證據（`mjx-container`）而不是「我觸發過」。以為收斂了。
- **新**：還有第五個，而且是**最嚴重**的一類——**永久**卡住，不是時序上晚一點。

## 缺陷

`Markdown` 的 typeset effect 綁 `[text]`。但 React 重新套用 `innerHTML` 會把 MathJax 的
`mjx-container` **擦掉**，而**重繪未必伴隨 `text` 改變**——例如收合帶入來源的 `<details>`（改的是 state）。

⇒ 那次重繪之後**永遠不會再排一次**。

實測（來源頁 68 個公式）：

| | 已排版數 |
|---|---|
| 載入完成 | 68 |
| 收合 `<details>` 後 0.3 秒 | **0** |
| 再等 4 秒 | **0** |

## 為什麼上一輪的「全面檢查」照不到

⚠️ **當時沒有「內容不變但會重繪」的元件。** 章節是 uncontrolled（用 ref 開闔，不觸發 React state），
所以那條路徑不存在。是 spec 042 的帶入來源用了**受控 `<details>`** 才把它生出來——
而受控是 spec 041 那一刀為了「打字重繪不要把它掰回展開」刻意選的。

⇒ 一次「全面檢查」的完備性，**上限是當時存在的路徑**。新加一條路徑就可能把舊結論作廢，
而它不會自己舉手。

## 修法

typeset 改成**無依賴 effect**（每次 render 都排一次；`scheduleTypeset` 自己 debounce 且冪等，很便宜）。
＋ `scheduleTypeset` 的 `.catch(() => {})` 改成「失敗也重試、放棄要 `console.warn`」
——原本一次暫時性失敗就讓整頁停在原始碼，而且沒有任何線索。

修完：68 → 收合 → 展開，全程 68/68。
