# 069：問答併進聊天（帶膜的 NotebookLM）完成（階段 24）

> 日期：2026-08-04。承接 068（退役新聞分診）。spec 029 出貨（271 測綠、零回歸）。
> 源＝產品轉向後「問答(RAG)／聊天(field-chat)兩條路」的收斂，使用者定案「問答併聊天」。

## 由來：兩條 grounding 路合成一條
產品轉向前後留下兩條對「使用者內容」發問的路：
- **問答（/ask，RAG）**＝ground 在**收進的文章/論文**（外部證言）。
- **聊天（/chat，field-chat）**＝ground 在**精選的核心理解**（地基）＋每輪 web 撒網。
使用者定案**合併**：讓聊天**每輪也檢索相關收進條目**、當**證言**餵進場脈絡（帶反逢迎的膜）。
＝**在你自己內容上的、帶膜的 NotebookLM**。

## 靈魂＝膜分層（原則 6，這功能最硬的一條）
把「收進的文章」引進聊天最大的風險：它**混進地基**、被當成「使用者的想法」。守住三層份量：
- **核心理解＝地基**（reason from、往下推）——只有它進 `build_field_system_prompt`。
- **收進的文章＝外部證言**（可引用、標「你收藏的」、「你收的資料說…」、**比核心理解軟**、可能他人觀點或有誤）
  ——只進**注入塊**，**絕不進地基、絕不自動變核心理解**。
- **web＝最外圈外部資料**。
守衛測（`TestPurityGuard`）：引用了含 `SECRET_外部觀點` 的收進條目後，`build_field_system_prompt(roots)` **不含**它、
`list_why_nodes` **不因引用而增**。＝spec 023/028「不注入回場」純度守衛，延伸到「收進」這層。

## 關鍵決策
1. **抽出純函式 `retrieve_corpus(repo, embedder, query, top_k, min_score)`**：把檢索段從 `RagService.answer` 抽出，
   **RAG 與聊天共用**（DRY）；`answer` 改呼叫它、行為不變。離線可測（注入 stub embedder，教訓 1）。**無新表**（只讀
   既有 `digest_entries`/embeddings，教訓 8）。
2. **web＋收進併成一個連號 sources 清單、帶 `kind`**（web 在前、收進在後）——而非各開一塊。`_messages` 的 sources
   塊依 `kind` 分兩類講（「你收藏的」vs「web」）、cited-only 濾、模板加「📎 你收藏的」小標（伺服器端＋串流 JS 都吃）。
3. **best-effort（教訓 3）**：檢索用 `corpus_search_for_test` 可注入；失敗/無語料→`[]`、聊天照跑（只 核心理解＋web）。
   腦力激盪模式**不檢索收進**（沙盒不撒網、不引外部證言）。
4. **`/ask`→302 導 `/chat`**（移除 RAG 頁邏輯、**保留 `RagService`/`retrieve_corpus`**）；導覽「問答」退場；刪 `ask.html`
   ＋舊 web 測（檢索能力改由 chat 測涵蓋）。CLI ask 契約（`test_ask.py`）保留、不動。
