# 138：`pull` 有、`push` 沒有——而**對稱的名字會蓋出不對稱的東西**

- 日期：2026-08-27 · 使用者提問 · 相關：
  [137](137-兩條規則被同一天的實跑推翻-而測試都是綠的.md)（同一條線的前一刀）、
  [136](136-一次性人工操作-而它不是一個功能.md)（「最自然的下一步會不會拆掉剛立的禁令」）

## 發生了什麼

我提議把冷啟動那半做成 `knowie-seed`。使用者問：「**還是用 knowie-pull knowie-push 會比較好？**」

⇒ 兩個轉移，一個接受一個否決。

## 轉移一：`seed` → `pull`（接受）

`seed` 只名得住「開頭那一次」。而同一個需求在專案跑了三個月、踏進新領域時一樣會來。
照 knowie 的「Named well?」判準——**名字要有修剪力**——`seed` 只歸檔冷啟動，
`pull` 蓋得住整個生命週期。使用者是對的。

## 轉移二：`push` **不做**（否決）

git 的 `push` 帶三樣東西，這裡三樣都不能要：

| git 的 push | 這裡 |
|---|---|
| 落地成共享狀態 | 違反「共享空間必須是**收件匣，不是資料庫**」（[room 與組織的 AI](../draft/2026-08-27-room與組織的AI-人的樹.md)）|
| 有共同祖先、可 merge | 沒有共同物件——你送出的是**拷貝**（[隱私與 AC](../draft/2026-08-27-隱私與AC-揭露範圍不是可信度.md)）|
| 對稱：push 完再 pull 拿得回自己 | ⚠️ **那正是馬太迴圈** |

而場怎麼知道這個 base 學到什麼？**它自己來讀**——設計原話就是那份 draft 的標題：
[knowie 接進來，**讀而不寫**](../draft/2026-08-27-knowie接進來-讀而不寫.md)。

⚠️ **判準：一個對稱的名字，會讓那個對稱性看起來像是已經成立的。**
這裡兩個方向的認識論地位**完全不同**（拉進來的要標 `from:`、不算你撞出來的；
而「推上去」根本沒有目的地）。名字一旦對稱，補齊另一半就成了最自然的下一步
——這正是 [136](136-一次性人工操作-而它不是一個功能.md) 那條判準的第二次現身。

## ⚠️ 而這一問翻出一個真的洞

不管叫什麼：**「給」的那半一旦寫下去，「讀」的那半就開始說謊。**

`knowie-xbase` 的 `lessons()` 讀 `experience.md` 的每個 `###` 當一條獨立教訓
——它**不知道 origin**。`knowie-pull` 把借來的判準寫進新 base 之後，
下一次量測會讀成「這個 base 也獨立撞到了」⇒ 計數餵回推薦、推薦餵回計數。
draft §八 早就寫過禁令（「只算『撞到』，不算『借走』」），
但那時**還沒有寫入口**，所以讀取器沒有需要知道這件事。**是寫入口讓那條禁令變得可違反的。**

⇒ 修法：`BORROWED_MARK` 一個常數，**產生器與讀取器共用**；帶標記的教訓不進計數。

## 順帶：對抗性驗證翻出的第二個洞

四種攻擊裡有一種**沒被抓到**——把產生器的標記字串改掉，測試照樣綠。
原因：標記在區塊裡出現**兩次**（標記行 ＋ 那句「怎麼升格」的說明）。

而那不只是測試鬆，是**真 bug**：照說明刪掉標記行的人，另一處還在
⇒ 升格失敗、量測照樣跳過它，**而沒有人會發現**。

⇒ 判準：**一個標記的「拿掉」，必須跟「加上」一樣機械。**
加是程式做的（一次寫對）；拿掉是人做的 ⇒ 必須**刪一行就完成**。
現在那個不變式寫成 `emit_lesson` 裡的一句 assert，加上一條測試把它接到行為上。
