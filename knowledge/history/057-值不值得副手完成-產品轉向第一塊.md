## 這一輪最重要的不是功能，是「先驗真實有用、再 promote」
**第一次把 experience 教訓「提案-批准 ≠ 打到需求」真的用上**：不是我提案→使用者說好→蓋；是先跑
**手動探針**驗**賭注 A**（一份誠實綜合到底有沒有幫到你），使用者答「有用」＋撞出兩個真風險，**才**
promote＋speckit。手動探針＝可執行規格。這是產品轉向後的新工作法，值得固化成經驗（見下）。

## 關鍵設計（串既有零件、核心零新相依）
- **比 SmartSearch 更輕**：心得證據就在**搜尋結果的標題/摘要**裡——**不逐則抓內文、不嵌入排序**
  （手動探針證明：HN 反應/早期實測/CodeRabbit 評測都是 WebSearch 直接回的摘要）。故新建精簡
  `assess_worth`，不套 SmartSearch 全管線。
- **獵心得 query 用確定性模板**（`worthit_queries`）不用 LLM 擴展：好 query 就那幾個固定角度（心得/
  評價、review、缺點/complaints、值得嗎、怎麼用），模板確定性/離線可測/穩定；**價值在綜合那段 LLM，
  不在 query**。
- **收內容口**＝路由收 `content` 欄（牆內也送得進來）；subject 解析序 name＞content首行＞url抓標題
  (best-effort try/except)＞url——**探針的 403 教訓落地**：伺服器抓被擋不崩，只要有 subject 字串就能跑。
- **反逢迎綜合＝新 prompt**（不複用 RAG answerer，語氣/結構不同）：官方/獨立/用戶分開、明說炒作/
  缺點、只依證據＋附引用、沒料說沒料（grounded，原則 3/教訓 7）。**principle 6「反逢迎」從概念變成
  code 的 `_SYSTEM`＋grounded。** 不落庫（原則 5/6）。
