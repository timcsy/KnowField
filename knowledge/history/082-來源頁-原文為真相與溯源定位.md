## 轉移：抽取的 markdown 從「主角」降為「檢索參考」
**舊**：來源頁把抽取的 markdown 當內容主體展示。
**新**：**原文/PDF ＝唯一真相（原礦）**升為主角；**抽取 markdown ＝萃取參考**（給檢索、也能看），
降為次要並**誠實標有損**（「自動萃取、可能有小誤差，準確請看原文」）。
- **為何**：抽取一定有損（表格簡化、OCR 誤字、標題重排）——**誠實標示 > 讓加工物冒充 ground truth**
  （接原則 3「直達原文、拿原礦自己煉」＋反逢迎的膜）。
- **連鎖效果**：markdown 一旦是「參考」，**複雜表格糊掉、公式偶爾不完美就不是災難**（保真責任卸回原文）
  →「複雜表格轉 HTML/圖片」壓力大降（**圖片幾乎否決**：讓表格內容從知識庫蒸發＝違背 RAG 工具 job；
  只在來源本身就是表格圖時退路）。→ 前面 `081` 修數學/圖/表格的定位＝「參考夠好讀＋檢索乾淨」，不追像素級。

## 溯源定位：由來指回原文的段落/頁（使用者 `/goal`「做完這兩刀」）
「由來」不只丟整篇連結，指回**原文那一段/頁**（＝「看真相」精準版；接 `對話的章節骨架`——那面定位對話則數，
這面定位來源段落，同「精準溯源」母題）。
- **第一刀（`269502a`）網頁 Text Fragment**：why_node 存 `source_quote`（verbatim 錨點）、由來「🌐 看原文」
  帶 `#:~:text=` → 瀏覽器原生捲到並高亮。**誠實：TF best-effort**——長句跨行內元素/腳註配不到（改取 ≤90 字）、
  且只在真實使用者手勢觸發（自動化測不出捲動，真點擊才作用、配不到退回開頁面）。
- **第二刀（`effde0b`）PDF 頁級＋IA 翻轉**：收進 PDF **存原始檔進 `/media`**（防原文失效＋預覽）；OCR 每頁前置
  `<!--kf-page:N-->` 標記（顯示隱形）→ distill 算錨點落頁→`source_page`→由來「第 N 頁」→來源頁 PDF 原生
  iframe 預覽翻到那頁。IA 翻成原文/PDF 為主、markdown 標「萃取參考」。
- **段落級 PDF 高亮（PDF.js viewer）＝否決**：使用者定案「到頁就滿意」，不做重工程 viewer（YAGNI）。

## 防原文失效的張力（分層解，非只指回原文）
「原文＝真相」但**會失效**（付費牆/下架/連結爛）；進料層 job 是脈絡卸載、讓人敢關分頁（`進料轉檔選型` I 節）。
解＝**分層**：顯示以原文為真相主角；**底層仍存**抽取（檢索）＋PDF/圖（`/media`）＝可檢索參考＋**防失效備份**。
鐵律：**embedding 一律吃文字版**（不論顯示層 markdown/HTML/圖/PDF）——否則來源變檢索黑洞（原則 3 延伸）。

## 順修的 bug（值得記，免得重踩）
- **PWA SW SPA-fallback 攔 `/media/*.pdf`**：iframe 對 PDF 的導航被 service worker 當成頁面導航→回 index.html
  （PDF 預覽變成聊天頁）。修：`navigateFallbackDenylist`（`/api`、`/media`、匯出、帶副檔名）。正式環境才不破。

## arxiv 排版三修（`5112568`，補 `081` 未收的）
使用者指出 arxiv 來源三處「看不懂」：① 空 bullet「- •」（LaTeXML list marker 當內容、真內容散成獨立 `<p>`）
→ 跳 `ltx_tag`＋`<li>` 裡 `<p>` 續收；② 資料表變一排數字（`<table class=ltx_tabular>` 沒處理→格散成 math 又被
合併成直欄）→ 資料表轉 markdown 表格、公式表維持數學流；③ Abstract 不粗（h6 前端只給 h1-h3 粗體）→ CSS h4-h6 也粗。

## 教訓歸屬（已反流）
- experience「解析 > 辨識」「確定性修承重內容 > 丟 AI」「先實測再斷言」（`history/081` 同串，這裡續）。
- **新（本篇）**：**顯示保真 vs 可檢索要分層**——顯示層可豐富（原文/PDF/HTML），檢索層必須有文字；
  加工物誠實標示、不冒充真相。（未升 experience；先記 history，重複出現再蒸餾。）

## 延伸：論文專屬展示＋收進入口分流（同串後續）
「原文為真相」推到底＝**論文（尤其 arXiv）得到最完整的真相展示**（`a7b2f25`／`4268406`）：
- **論文展示三合一**：來源頁偵測論文→**Abstract（來自 arXiv API `export.arxiv.org`，非抽取＝最可信）
  ＋作者/日期 ＋原文 PDF 預覽 ＋萃取參考**。加料機制＝`ingest/paper.py enrich_arxiv`：arXiv 收進成功後
  抓 metadata JSON＋原始 PDF 存 `/media`（路徑由 url 衍生、零 schema、best-effort）。**補上「arXiv 走 HTML
  沒 PDF 預覽」的缺口**（HTML 負責檢索、arXiv API 的 Abstract＋PDF 負責看真相——正是「顯示 vs 檢索分層」）。
- **收進入口分流**：「🎓 收進論文（arXiv）」與「📄 收進 PDF（一般報告）」分開兩框。**why：別讓 arXiv PDF
  被貼進 PDF 框走 OCR**——那會錯過 HTML 的數學/圖優勢＋論文展示。論文走 `ingestUrl`（normalize→HTML＋加料）、
  一般 PDF 走 OCR，各走各的。
- **邊界**：只認 arXiv；別的論文源（OpenReview/DOI/期刊）要各接 metadata API（後續）。既有 arXiv 來源要跑一次
  `enrich_arxiv` 才有展示（新收進自動加料）。
