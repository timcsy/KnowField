# 062：/chat（階段 17）真實使用打磨——一條因果收斂

> 日期：2026-07-29　｜　承接 history/059（/chat 出貨）。把散在多個 commit 的打磨收斂成一條記錄。

## 為何記這一筆
`/chat`（spec 022）出貨後，**使用者一開始真的用**，一路回饋，逐項打磨。**九個修沒有一個是測試或我
自己審查抓到的**——全是真實使用照出來的。這一連串本身就是 experience「**真實使用才是驗收**」「**內部
概念詞彙別洩漏到產品對外表面**」的活證據，值得留一條因果。

## 打磨清單（真實使用回饋 → 修）
1. **版面**：raw markdown 洗版 → 接上既有 `answer-md`＋marked.js 渲染。
2. **術語洩漏**：AI 一直說「grounded/冊封/場-增量」→ **de-jargon 膜 system prompt**（行為全留、輸出自然口語）。
   ＝experience「內部詞彙別洩漏產品表面」的觸發源。
3. **佐證時機**：使用者「不該按鈕才找、該一邊聊一邊找」→ 佐證**按需 → 每輪自動撒網＋句尾 [n]**。
4. **進度**：每輪多一次撒網會慢 → 送出後分段進度指示。
5. **搜尋 query 爛**：問 Flow Matching 卻搜到「flow是什麼牌子」→ **LLM 先把問題轉成好 query（消歧義）
   ＋只顯示被引用的來源**（垃圾自動濾掉）。＝「Web Search 該下什麼關鍵字」風險真的發生（早在 spec 021 flag 過）。
6. **腦力激盪開關**：純發想輪不想被搜尋干擾 → `brainstorm=1` 不撒網（沙盒模式，principle 6）。
7. **整理分層**：一段對話常不只一個知識點、且不同層次 → distill 回**多條、標 derived/empirical/applied**
   （複刻示範的地基/觀察/類比分層）。
8. **省成本**（帳單優先）：長對話每輪帶全上文 → **砍歷史（只帶最近 N 則）＋確認 OpenAI 自動快取**
   （穩定的 system＋場前綴命中）。對齊「場才是記憶、留得下的請冊封」。
9. **串流**：blocking 50-70s → SSE 串流＋分段進度。**真後端照出使用者的 API 閘道不支援串流**（送
   stream:true 仍回整包 JSON）→ `_post_stream` 偵測非 SSE 就退回解析整包、一次吐完整答案（穩健、
   未來換串流端就真串流）。＝供應商限制、非 bug；真實測試才照得出。
10. **網址讀取**：貼 arXiv 網址 AI 只能說「打不開」→ 偵測訊息裡 URL、伺服器端 best-effort 抓內容
    （複用 `fetch_url`）注入該輪場脈絡；抓不到→給 note、令 AI **據實說讀不到、不假裝讀過**（教訓 3）。
    真驗：貼 2511.11665 → 真讀到（RoPE→Clifford rotor）。＝moment-A「收內容 vs 收網址」在對話重現。
11. **編輯已送出訊息（任一句）＋開新分支**：每則 user 訊息加 ✏️（就地改、從那句重問，這串會變）＋
    🌱（另開一頁載入前綴、原對話保留）。對話 client 帶著跑、無 server session → 分支＝另開一頁載前綴，最省。
12. **以存下的對話「接著聊」**：`/conversations/{id}/resume` 把存檔載回 live `/chat`（快照不動）；載進去後
    每句的 ✏️/🌱 即可從任一點續聊/開分支。＝串起迴圈：聊→存成由來（連根因）→回來接著聊/分支→再存。
13. **數學式可複製**：渲染時把數學片段包成 `.mathcopy`＋`data-tex`（原始 LaTeX）；點一下/選取複製回傳
    含 `$`（行內）或 `$$`（獨立行）的原始碼——**保留原始分隔符故 $/$$ 自動正確**，不用猜。四頁皆有。
    - **更正/補完（2026-07-29）**：初版只兌現「**單一**數學元素」的選取（focus/anchor 同一 `.mathcopy`）；
      使用者要的是**選一整段混合文字＋公式**時自動處理。改 base.html `copy` handler：`cloneContents`
      選取範圍→把其中每個 `.mathcopy` 換成 `data-tex`（block 補換行）、其餘文字照舊→`frag.textContent`。
      ＝又一次「真實使用照出措辭與實作的落差」（第 13 項當初「選取複製」講得比實作大）。

## 教訓再釘
- **真實使用是唯一照得穿的光**：測試全綠＋我泡在裡面對缺陷免疫；只有使用者一用就照出。
  （已在 experience「提案-批准 ≠ 打到需求」解方＋「內部詞彙別洩漏產品表面」，此為又一批實證。）
- **真後端才照得出供應商能力**（串流那條）：接真實後端一定要再驗（呼應 experience「stub 綠 ≠ 真實正確」）。
