# 108：對話的由來徽章讀錯欄位——「儀器說謊」的第三種形態

> 日期：2026-08-23。**缺陷與修正**。階段 18（對話的由來）；spec `specs/045-conversation-yield-badge/`；commit `e1983af`。

## 轉移

- **舊**：對話清單用 `conversations.why_node_id` 判斷「這段是不是某條核心理解的由來」
  （`ConversationsPage.tsx:73`、`ConversationSidebar.tsx:139`）。
- **新**：改讀**事實來源** `why_nodes.conversation_id`，且回傳**條數**而非布林。

## 為什麼舊的是錯的——程式自己知道

`repository.py`（`save_conversation` 內）：

```python
if why_node_id is not None:    # 連結存 why_node 側（事實來源）
    self.conn.execute("UPDATE why_nodes SET conversation_id=%s WHERE id=%s", …)
```

⇒ 註解自己寫著哪一邊是事實來源。而 `conversations.why_node_id` **只在
`save_conversation(…, why_node_id=…)` 這一條路被填**——**冊封走的是 `promote_conversation`，
它只更新 why_nodes 那側**。

**正式庫實測**：真的是由來的 **12** 段，畫面只認得 **4** 段 ⇒ **漏掉 2/3**；反向誤標 0。

## 這是本週第三次「儀器在說謊」，而三次的形態不同

| | 說謊的形態 | 修法 |
|---|---|---|
| 帶著文章／來源聊 | **訊號還沒開始記** | 補欄落庫（spec 044） |
| 來源訂閱 15/0 | **機制已退役** | 改標殘骸（[107](107-退役會教錯路的來源skill-小腦沒有oracle.md)） |
| 對話由來徽章 | ⚠️ **量錯欄位——事實在隔壁** | 讀事實來源（本條） |

前兩次錯在**報告**，這次錯在**使用者的畫面**。⇒ 一個量測項出現可疑數字時，
「沒人用」是**最後**才該考慮的解釋，前面還有三個：沒開始記、機制沒了、讀錯地方。

## 兩個順帶的決定

- **回條數不回布林**：同一個 `GROUP BY` 就拿得到，而 15／6／2／1 這種資訊
  布林值從來傳達不了。「這段聊出了 15 條」與「這段聊出了 1 條」對使用者不是同一件事。
- ⚠️ **不刪 `conversations.why_node_id`**：加欄路徑（spec 044）明寫**不支援改型別或刪欄**。
  照舊回傳、停止讀它。⇒ 它從此是**死欄位**，記在 spec 045 的 out of scope。

## 一條差點沒牙齒的測試

「不要逐筆查」是**效能**斷言——**純看輸出分不出逐筆與批次**，兩者結果一模一樣。
⇒ 用一個會數 `execute` 次數的假連線釘住，並拿「改成逐筆」的實作去撞（撞紅）。
同 `experience.md`「一條沒有被錯誤實作撞過的測試，不知道自己在測什麼」。
