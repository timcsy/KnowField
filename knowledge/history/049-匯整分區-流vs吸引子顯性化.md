# 049：匯整分區（階段 14）——流 vs 吸引子在 UI 顯性化

> 日期：2026-07-26　｜　承接 history/048（news 模式）

## 緣起（使用者洞見）
使用者：「有些來源是很重要的基礎知識（arXiv 論文、深度學習教學、經典部落格），不是新聞類。」
點破：每日匯整把**新聞流**與**基礎知識**混在一起 churn，但基礎知識是**常青**的、不該跟新聞
一起滾一起衰減。正中母概念 `有吸引子的場` 的**流（news/趨勢，會衰減）vs 吸引子（基礎/常青）**。

## 決策（AskUserQuestion 2026-07-26）
使用者選 **「分區顯示」**（非方案 A「基礎源→種子候選/不進流」）：首頁分兩區——
**📰 今日新聞**（type=news）＋**📚 基礎知識精選**（type∈{paper,blog}）。**只改呈現，不動匯整
產生流程/排序/衰減。**

## concept 投影落地（三方一致）
- concept：流＝news（會衰減）、吸引子＝基礎（常青）。spec 017 把這區分**在首頁 UI 顯性化**——
  `_section_of(type)`：paper/blog→基礎、其餘→新聞。真跑：新聞 9 則（TechCrunch/Reddit/Import AI/
  web 活水）／基礎 6 則（arXiv/HF/ycc 教學）。

## 關鍵設計
- **最小新增欄**（教訓 8）：`digest_entries` 加 `source_id`（`_migrate` ALTER 冪等）；`save_digest`
  寫、`get_last_digest` 回填 `Item.source_id`；首頁 join `sources.type` 分區。**不在條目直接存
  類別**——存 id 較穩（來源 type 可改，如 HN 重分類）。
- **HN/Reddit 重分類 blog→news**：它們是社群/新聞流、非基礎部落格；讓 `blog` 乾淨代表「基礎
  部落格」（ycc/lilianweng）。DEFAULT_SOURCES 改＋upsert 進使用者 db。
- **向後相容**：source_id 空/未知（web 材料 source_id="web"、舊條目）→ 落新聞區、不崩。
- **web 材料歸新聞**：source_id="web" 不在 sources → 預設新聞（web 活水是流，合理）。

## 其他路線（擱置為後續）
- **方案 A：基礎源→種子候選/不進每日流**——更貼「基礎＝該冊封的吸引子」，但改動大（改衰減/
  種子管線）。本次選較輕的「分區顯示」；方案 A 列後續（若分區還不夠再做）。
