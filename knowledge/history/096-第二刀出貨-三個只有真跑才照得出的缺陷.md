# 096：英→繁全文翻譯出貨——三個只有真跑才照得出的缺陷

> 日期：2026-08-18。階段 34 第二刀。spec 038、commit `ae3b8af`。
> 承 [095](095-對照被探針否決-第二刀改為一鍵全文翻譯.md)（對照被否決、改為全文翻譯）。

## 這條不是「做完了」

交付本身歸 commit 與 spec。這裡記的是**三個在 465 個測試全綠之後、把 app 真的開起來才照出的
缺陷**——它們共同修正了一條判準的寫法，所以是轉移不是完成。

## 一、假 spinner：測試綠 ≠ 進度是真的

初版把進度累積在 list 裡、**全部翻完才一次吐出**。七條契約測試全綠，因為它們只驗
「有沒有 stage 事件」。使用者體感是盯著沒反應的畫面 93 秒，最後一次看到全部。

⚠️ **我寫了三版測試才寫出有牙齒的**，而且每一版都拿一個**故意做成累積式**的實作去撞：

| 版本 | 驗什麼 | 撞累積式實作 |
|---|---|---|
| v1 契約層：有沒有 stage 事件 | 存在性 | ✅ 綠——累積式也會吐 |
| v2 契約層：第一個事件是不是 stage | 順序 | ✅ 綠——順序對、時機錯 |
| v3 單元層：直接測產生器 ＋ **時間上界** | **時機** | ❌ 紅（2.12s 失敗）← 這才是測試 |

⇒ **一條沒有被錯誤實作撞過的測試，不知道自己在測什麼。**

連帶的設計後果：時機**隔著 `TestClient` 驗不了**（它會緩衝）。所以把串流邏輯從路由抽到
`text/translate.py::translate_stream`——**不是為了分層好看，是為了讓時機測得到**。
路由只負責包 SSE。這是「可測性驅動了模組邊界」的一個乾淨實例。

## 二、接縫殘影：兩個各自正確的機制湊在一起就壞了

畫面上出現「條件式 Generat … 條件式生成」。

根因：`stitch_chunks` 靠**精確字串比對**去除塊間 40 字元重疊——那對**原文**成立。
但每塊是**獨立翻譯**的，同一段重疊文字在前後塊會翻成不同的中文，比對就失敗，兩份都留下。

⚠️ 這裡沒有任何一個元件是錯的：`chunk_markdown` 的重疊是對的（給檢索用）、`stitch_chunks`
的去重疊是對的（給原文用）、逐塊翻譯也是對的。**壞的是「獨立翻譯」這個新前提悄悄廢掉了
`stitch_chunks` 依賴的不變式**（前後塊的重疊段逐字相同）。

修完這層，殘影**變了形狀但沒消失**——露出更深的一層：`chunk_markdown` 會**從單字中間切**
（實測 124 個接縫有 **55 個**是）。`Conditioned Generat` ＋ `ion` 各自被當成完整文字翻譯，
後者成了「**離子**」。⇒ **為檢索設計的切點不是翻譯的合法切點**。

最終修法：不再重用檢索塊。先拼回全文，再用 `text/translate.py::split_units` 切成翻譯單位
（段落邊界；過長段落退而切在空白處；絕不從單字中間切；重組逐字還原）。

⚠️ 而那個修法一度**打破效能**：段落切法讓每個清單項自成一單位，125 塊 → **211 單位**，
93s → **137s**，SC-002 破了。因為 `split_units` 只切開過大的、從不合併過小的——
**一個「大小參數」若只管上界不管下界，它就沒有在管大小**。加上合併後 211 → **79 單位、63 秒**，
比接縫修正前還快。

## 三、run-knowfield 自己的檢查是錯的（第二次）

skill 的「殺完要確認」用 `ps aux | grep -c`。但 `uv run` 是包裝器，**一個 server 佔 2 行**
（`uv run …` ＋ python 子行程），加上 uv 自己的暫態行程，數字虛高。我照著它讀成
「殺不掉、還有 4 個」，實際只有剛起的那 1 個，白繞一圈。

改用 **`lsof -nP -iTCP:8000 -sTCP:LISTEN`**——問「誰在聽」，不問「有幾個像樣的行程」。

⚠️ 這是同一條指令的**第二次**出錯（第一次是 pkill 樣式帶了字面引號，見
[094](094-來源語言處理從改寫取代原文反轉為顯示層轉換.md) 那批）。兩次的形狀一樣：
**我用一個「看起來相關」的訊號代替「直接回答問題」的訊號**。`grep -c` 回答的是
「有幾個命令列長得像」，而我要問的是「port 被佔著嗎」。

## 兩條是我自己把測試寫太強

- 語言偵測：用 `"The Chinese term is 擴散..." * 10` 當「英文文章引用中文術語」的樣本——
  38 個非空白字元塞 2 個中文＝5.3%，真實文章不存在這種密度。
- 接縫：斷言「相鄰片段不准有任何共同前後綴」——週期性文字必然有，那不是缺陷。

⇒ **樣本不真實時，失敗的是測試不是實作。** 兩條都改成測真正的要求。
