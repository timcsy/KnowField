# 127：建議整理——而**不可反駁的理由等於沒有理由**

- 日期：2026-08-26 · spec：[065](../../specs/065-suggest-organization/) · 階段：vision 階段 60

## 轉移

| | 之前 | 之後 |
|---|---|---|
| 整理領域 | 全手動；領域頁明講「**刻意不自動分類**」 | AI **建議**，人逐夾決定 |
| 那條「不自動分類」的線 | 擋掉所有 AI 參與 | **提議不違反，套用才違反** |

⇒ 原則 5 的形狀本來就是「AI 大量提議候選、標出缺口（gradient oracle）；**人**做冊封」。
建議整理是同一個形狀套在領域上。⚠️ 但「提議 ＋ 一個**全部套用**的按鈕」＝ 自動分類多按一下
——所以那個按鈕**不存在，而且有一支測試守著它不會出現**。

## 核心分工：成員來自結構，命名才交給 LLM

因為理由必須**可查證**：

| | |
|---|---|
| ✅ 「這 7 條理解都是從〈某段互動〉冊封出來的」 | 你點得開、可以說「不對，那段講的是別的」 |
| ❌ 「它們都跟生成模型有關」 | 你**沒辦法不同意** |

⚠️ **不可反駁的理由等於沒有理由**，於是介面被橡皮圖章化（spec 046 學過的那條）。

⇒ 所以分群**不走 embedding 相似度**——它給不出可查證的理由。走**既有的邊**：
由來（`why_nodes.conversation_id`）· 帶入物（`conversations.carried_ref`）。
LLM 只能**重組群**，不能重組個別條目；它指了不存在的群 → 丟掉，不是憑空生一個空夾。

## 留白也是一種建議

66 件沒有任何連結的東西收成一群，標 `lonely`，**不給套用按鈕**，並說出為什麼：
「留著就好——硬分出來的資料夾之後還要拆。」
⇒ 一個什麼都能分類的建議器，跟一個什麼都不建議的一樣沒用。

## 順帶：理由的**讀感**也是判準的一部分

實跑第一版印出「這 **1** 條理解都是從⋯」，還有一個 markdown 星號漏到純文字介面上。
⚠️ 這不是文案瑕疵：理由是**要被讀的**，讀起來像機器湊的 ⇒ 不可信 ⇒ 不會細看
⇒ 判準①靠的那句「你能反駁它」就落空了。已補測試守住。
