# 規格：探索（多角度擴展搜尋）

**功能**：LearnNews 路線圖階段 9 增量 c
**分支／目錄**：`specs/011-explore-multiangle/`
**建立日期**：2026-07-25
**狀態**：草擬中（待 plan）

## 摘要

智慧搜尋（增量 b／spec 010）目前用**單一 query** 搜尋。有些主題，單一 query 照不到全貌——
換個角度問會撈到完全不同的好東西。本增量加一個 **opt-in 的「深入探索」**：開啟時，工具把你的
query **拆成 3–5 個不同角度**、各搜一次、**合併去重**，再對合併後的結果池跑既有的整理管線。
＝**反濾泡再進一步**：撒更廣的網，照到單一 query 的盲區。

只做 **(a) 多角度擴展**（單輪、有界、成本可預測）；**(b) agentic 追線索**（多輪迴圈）明確不做。
因為貴，**預設關**——多花的成本（多次搜尋＋一次拆解）只在你主動開啟時才發生。

## 使用者情境與測試

### 主要使用者故事

**US1（P1）——一鍵撒更廣的網**
作為一個覺得「單一 query 好像漏掉了什麼」的使用者，我想勾一個「深入探索」，讓工具**自動從
幾個不同角度**幫我搜，把結果**合起來**給我一份整理，這樣我不必自己想很多種問法各搜一遍。

- **驗收情境**：
  1. **Given** 我在 `/search` 打一個 query 並**勾選「深入探索」**，**When** 送出，**Then** 工具
     從**多個角度**搜尋、把結果**合併**後呈現一份整理與結果清單（涵蓋面比單 query 更廣）。
  2. **Given** 同一篇文章在多個角度都被搜到，**When** 呈現結果，**Then** 它**只出現一次**
     （合併去重），整理不會看到重複材料。
  3. **Given** 我**沒有勾**「深入探索」，**When** 送出，**Then** 行為與增量 b **完全一致**
     （單一 query 搜尋＋整理），不多花任何探索成本。

**US2（P2）——探索失敗也不擋路**
作為使用者，就算「拆角度」這步失敗，我仍希望**照常拿到單一 query 的搜尋與整理**，而不是
整頁壞掉。

- **驗收情境**：
  1. **Given** 勾了「深入探索」但拆角度服務失敗／逾時，**When** 送出，**Then** 工具**自動退回
     用原本單一 query 搜尋**、照常給整理，並（可）友善提示探索未生效；不噴錯誤堆疊。

### 邊界情況

- **query 為空**：不搜尋、不拆角度（同既有）。
- **拆角度只回 1 個（或只回原 query）**：等同單 query 探索，正常運作。
- **拆出的角度超過上限**：**只取前 5 個**（硬上限，控成本）。
- **多角度合起來 0 則結果**：顯示「查無」（同增量 b）。
- **離線（無真實後端）**：走離線 stub 的確定性拆角度，整條流程零外部呼叫可測。

## 需求（功能）

- **FR-001**：`/search` **必須**提供一個「深入探索」開關，**預設關閉**。關閉時，搜尋與整理行為
  **必須**與增量 b（單一 query）完全一致。
- **FR-002**：開關**開啟**時，系統**必須**把 query 拆成**多個（3–5 個）不同角度**的子查詢
  （含原 query），對**每個子查詢各搜一次**。
- **FR-003**：多個子查詢的結果**必須合併，並依原文網址去重**（同一網址只保留一則，保留最先
  出現者）。
- **FR-004**：合併去重後的結果池**必須**交給既有整理管線（排序＋抓 top-N 內文＋grounded 整理＋
  `[n]` 溯源），呈現方式與增量 b 相同。
- **FR-005**：子查詢數量**必須有硬上限（≤5）**；**抓取內文的則數仍受既有 top-N 限制**（不因
  子角度變多而放大抓取量）——確保成本有界。
- **FR-006**：拆角度後端**必須可插拔**：離線可用**確定性 stub**（零外部呼叫、契約測試綠燈）、
  真實後端不新增第三方相依。
- **FR-007**：拆角度**失敗／逾時**時，系統**必須自動退回單一 query 搜尋**、照常產生整理，
  以友善繁中處理，不噴例外堆疊、不回伺服器錯誤。
- **FR-008**：探索的搜尋結果**一律不落庫**；只有使用者「收進」的才成種子（沿用增量 b）。
- **FR-009**：所有面向使用者文字**必須為繁體中文**。
- **FR-010**：本功能**不得**新增資料表、不得改動既有整理／答案合成的對外行為。

### 明確排除（範圍外，防蔓延）

- **(b) agentic 追線索**（讀完看缺口再搜、多輪迴圈）——**絕不做**，optional／未 promote。
- 把子角度結果**分組顯示**（合併成單一池即可，不分組）。
- 併進 `pull`、每來源品質加權、CLI、趨勢讀數（B）。
- 探索結果落庫或快取。

## 關鍵實體

- **子角度查詢（sub-query）**：由原 query 拆出的一個不同切入問法；數量 3–5、硬上限 5；短暫。
- **合併結果池**：多個子角度搜尋結果依網址去重後的集合，作為整理管線的輸入；短暫不落庫。
- **深入探索開關**：使用者每次搜尋的一個 opt-in 選項（預設關）。

## 假設

- 沿用增量 b（spec 010）整理管線與增量 a 之前的 `/search` 頁；本增量只在其前加一層 fan-out。
- 沿用可插拔後端樣式（離線 stub／真實），拆角度屬「文字生成」類，複用既有對話後端。
- 去重以原文網址正規化比對；同 url 視為同一則。
- 拆角度預設關，因其多花成本（多次搜尋＋一次拆解）——僅在使用者主動開啟時發生（根公理：
  成本要極低）。

## 成功標準（可驗，技術中立）

- **SC-001**：使用者勾「深入探索」後，一次搜尋即**涵蓋多個角度**、結果**合併去重**（重複網址
  不重複出現）、得到一份整理——毋須自己換多種問法各搜一遍。
- **SC-002**：**不勾**時行為與增量 b 完全一致、**不多花探索成本**（不觸發拆解與多次搜尋）。
- **SC-003**：拆角度失敗時，使用者**仍拿到單一 query 的搜尋與整理**，頁面不崩。
- **SC-004**：子角度數**不超過 5**、抓取內文則數不因探索而放大（成本有界）。
- **SC-005**：離線（無金鑰）下探索流程可跑完並通過測試；**既有 209 項測試不回歸**。
- **SC-006**：**(b) agentic 未出現**在本次交付中（範圍守住）。
