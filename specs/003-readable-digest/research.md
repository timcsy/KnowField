# Phase 0 研究：可讀文章式消化

解決 plan.md 取捨。技術棧沿用階段 1–4，此處只記本功能新增決策。

## R1. 散文生成（忠實、完整、不下結論）
**決策**：新增 `ArticleBuilder`，用 OpenAI 格式 chat 生成散文，提示強約束：
- **只依原文**（標題＋摘要/前文）傳達重點／關鍵數據／適用時機；**原文沒有的數據不寫**。
- **不下第一性結論、不評價、不外推**（FR-003）——你在傳達原文，不是給觀點。
- 繁中、可讀連貫段落（非列點）；**完整傳達優先於長短**，但不灌水。
- 程式端仍保留輕量守衛（沿用 `summarizer` 的鷹架剝除防線，見 experience 教訓 2）。

**理由**：散文比一句更易編造 → 靠提示強約束＋保留原文一鍵核對＋真跑抽查忠實度。
**替代**：抽取式（取原文段落）——最保真但讀起來不順、也難「完整傳達」；故選 LLM＋強約束＋抽查。

## R2. 抓原文圖（best-effort）
**決策**：分來源策略，取不到就退（不阻塞）。
- **新聞 RSS**：抓 `<enclosure>`／`<media:content>`／description HTML 內第一張 `<img>`。
- **arXiv**：試 arXiv HTML 版（如 `arxiv.org/html/<id>`）解析第一張 figure；PDF 解析成本高，MVP 不做。
- **HF Papers**：若回應含縮圖欄位則用。
- 取得的圖以 URL 內嵌（不下載落地，MVP 從簡）；多圖時取**第一張代表圖**。

**理由**：stdlib 可解析、可溯源、零相依；PDF figure 擷取太重，留待日後。
**替代**：一律 PDF 解析圖——過重違 YAGNI；一律不抓只 AI 圖——失溯源，違原則 3。

## R3. AI 示意圖（可選）
**決策**：`ai_image.py` 走 OpenAI 格式 **images 端點**（urllib），**預設關閉**，以旗標
（如 `--ai-image`）啟用；一旦產生，回傳物件標 `kind="AI 示意"`，渲染 MUST 標
**「AI 示意・非原文」**（FR-007）。無金鑰/失敗則略過（退純文字）。

**理由**：使用者要「也可 AI 生」，但這是加值＋有成本/失真風險 → 預設關、必標示、可降級。
**替代**：預設開——增加成本且易被誤認原文，違原則 3/YAGNI。

## R4. Article 取代 Summary 的資料遷移
**決策**：新增 `Article`（正文＋來源連結＋可選 Figure）作為預設消化產物；
`DigestEntry`／`PullEntry` 改帶 `article`（取代 `summary`）。`--raw` 時 `article=None`。
`digest_entries` 表增欄存文章正文/圖資訊（供 `--from-digest`／回顧）。舊 `Summary` 保留供
過渡與測試，不再是預設路徑。

**理由**：Article 是這階段的核心產物；直接讓 entry 帶它最清楚。遷移侷限在 entry 層。

## R5. 優雅降級（FR-011）
**決策**：散文/AI 圖後端失敗或限流 → 於 CLI 邊界攔截（沿用 `OpenAIError` 處理），
**優先降級而非中斷**：散文失敗 → 退回精簡標題＋來源＋連結（等同該則 raw）並標示「消化
暫不可用」；抓圖失敗 → 純文字。整體指令**不炸 traceback、退出碼 0**（除致命設定錯誤）。

**理由**：外部相依必失敗（experience 教訓 3）；降級保住「至少拿到原礦」，守根公理。

## R6. 渲染
**決策**：markdown 模式內嵌圖（`![標記](url)`，AI 圖標題含「AI 示意・非原文」）；
terminal 模式圖以「圖：<url>（原文／AI 示意）」一行呈現，不嵌。`--raw` 不變。

**理由**：markdown 最適合「可讀文章＋圖」；終端退為連結，資訊不失。
