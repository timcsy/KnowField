# spec 065：建議怎麼整理（vision 階段 60）

## 核心分工

> **成員來自結構，命名與合併才交給 LLM。**

因為判準①要求理由**可查證**：「這 7 條來自〈某段互動〉」你可以點開去看；
「它們都跟生成模型有關」你**沒辦法不同意**——而不可反駁的理由等於沒有理由。

⇒ 所以分群**不走 embedding 相似度**（那給不出可查證的理由），走**既有的邊**：
由來（`why_nodes.conversation_id`）· 帶入物（`conversations.carried_ref`）· 佐證來源。

## FR

- **FR-001** 結構分群：把**未歸屬**（在根領域）的知識按既有的邊分成群，每群帶一句**可查證**的理由。
- **FR-002** LLM 把那些群**命名並合併**成 3–7 個資料夾（可帶一層父子）。
  ⚠️ LLM **只能重組群，不能重組個別條目**——那樣它就在做指派了。
- **FR-003** 離線／LLM 失敗 → **退回結構群本身**（用群自己的理由當名字），不是回空的。
- **FR-004** ⚠️ **沒有「全部套用」。** 逐夾：建立（建領域＋搬進去）／改名／略過。
- **FR-005** **允許留白**：分不出來的落單條目歸成「還沒有連結」，**明講不建議分**。
- **FR-006** ⚠️ 採用次數／熱門度**不進**任何排序（馬太陷阱）。
- **FR-007** 套用一夾要回報**拆散了哪些糾纏**（沿用 spec 049，不自動連帶搬）。

## 驗收

1. 每個建議夾的每一條理由都指得出**具體的那條邊**
2. 離線後端也回得出建議（結構群 fallback）
3. ⚠️ 已經歸屬的東西**不出現在建議裡**（只整理未歸屬的）
4. API 沒有任何一次套用多夾的路徑
5. 實跑：在正式庫按下去看得到建議，套用一夾後件數對得上
