# 功能規格：來源直接對話（階段 38）

**Feature Branch**: `main`（小刀，不開分支）· **Created**: 2026-08-21 · **Status**: Draft

**Input**: 使用者（2026-08-21）：「我希望連來源也有支援直接對話功能」

**知識庫來源**：vision 階段 38 · 設計源 [`draft/2026-08-21-來源直接對話.md`](../../knowledge/draft/2026-08-21-來源直接對話.md) · 母設計 spec 041（同一套機制換一個資料來源）

---

## ⚠️ 先釘死這一刀的價值，否則做完會覺得沒差別

來源**現在就已經**進得了對話——`app.py:262` 的 `_chat_corpus` 會撒網撈「你收藏的」相關資料。

⇒ 本刀**不是**「讓來源能進對話」。本刀是把「**它猜哪些相關**」換成「**我說就是這一份**」。

| | 撒網（現況） | 帶著這份聊（本刀） |
|---|---|---|
| 選誰 | 依這句話的相似度挑 | 使用者指定 |
| 範圍 | 片段，可能漏 | 整份在視野裡 |
| 失敗方式 | ⚠️ **沉默**——沒撈到你不會知道 | 沒有這種失敗 |

**撒網真正的成本是沉默地漏掉，不是不夠準。** 這決定了 SC-002 必須在「撒網關掉」的條件下驗。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 指定這一份，不靠猜 (Priority: P1)

使用者在來源詳情頁按一個動作，就能帶著這份來源開始新的一段對話；接下來的回答**確實**依據這份來源，
而不取決於撒網有沒有撈到它。

**Why this priority**：這是使用者要的東西本身，也是本刀存在的唯一理由。

**Independent Test**：把撒網停用，帶入某份來源後提問，回答仍可驗證地反映該來源內容。

**Acceptance Scenarios**:

1. **Given** 一份已收進的來源，**When** 使用者按「帶著這份聊」，**Then** 進入**一段新的對話**，
   該來源以**這一輪的第一則**呈現（形狀與 spec 041 逐項相同）。
2. **Given** 帶了來源的對話且**撒網停用**，**When** 使用者問該來源的內容，**Then** 回答反映該來源。
3. **Given** 沒帶來源，**When** 使用者聊天，**Then** 行為與現況逐字相同。

---

### User Story 2 - 形狀沿用，不重開討論 (Priority: P1)

已帶的來源在對話頁的呈現、展開收合、殘留規則，與 spec 041 的文章**逐項相同**。

**Why this priority**：與 P1 並列。spec 041 的形狀被使用者糾正**五次**才定案
（[`history/101`](../../knowledge/history/101-文章當第一則-從掛在對話上改為開新對話.md)）。
⚠️ 藉本刀重開形狀討論＝把那五次的成本再付一遍。

**Independent Test**：把來源版與文章版的呈現並排比對，找不到形狀上的差異。

**Acceptance Scenarios**:

1. **Given** 帶了來源的對話，**When** 使用者看畫面，**Then** 是可收合的第一則（`<details>`／▸▾／章節樣式），
   沒有起手式、沒有額外控制項。
2. **Given** 帶了來源，**When** 使用者接回既有對話或開新對話，**Then** 該來源不殘留。

---

### User Story 3 - 原文為真相 (Priority: P1)

進入脈絡的是**原文**，不是使用者眼前的譯文。

**Why this priority**：與 P1 並列。這是 spec 037 FR-004／038 FR-005 延續下來的紅線，
而且有具體 payoff：模型看得到原文才抓得出翻譯的失真。

**Independent Test**：對一份英文來源，翻譯後帶入對話，檢查送給模型的脈絡含英文原文、不含譯文。

**Acceptance Scenarios**:

1. **Given** 一份已翻譯的英文來源，**When** 帶入對話，**Then** 脈絡中是原文。
2. **Given** 使用者讀的是譯文，**When** 帶入對話，**Then** 脈絡中**明講**這件事。

---

### Edge Cases

- **來源很長**（實測 20k–38k 字）→ 見 FR-005；⚠️ **不得截斷**。
- **同一份既被帶入、又被撒網命中** → 見 FR-007（去重）。
- **來源不存在／已刪** → 與 spec 041 相同：安靜地當作沒帶。
- **bare 模式** → 不注入（FR-008）。

## Requirements *(mandatory)*

- **FR-001**：使用者 MUST 能在來源詳情頁**以一個動作**把該來源帶進**新的一段對話**；
  MUST NOT 掛到當前對話上、MUST NOT 自動注入。（沿用 spec 041 FR-001／001c）
- **FR-002**：已帶的來源 MUST 呈現為**這一輪的第一則**，可就地展開閱讀，展開收合 MUST 沿用
  對話章節既有的 `<details>` 做法。MUST NOT 新增任何 spec 041 沒有的控制項。（沿用 041 FR-001a／001b／001d）
- **FR-003**：⚠️ 帶入的來源 MUST 進入模型脈絡，且該注入 MUST NOT 依賴檢索是否命中它
  ——**這是本刀與現況的全部差別**。
- **FR-004**：⚠️ 注入的 MUST 是**儲存層原文**；譯文與簡→繁轉換後的顯示文字 MUST NOT 進入脈絡。
  脈絡 MUST 明講「使用者在頁面上看到的可能是繁體化或翻譯後的版本，以下是原文」，好讓模型能做對應。
  ⓘ 刻意**不**傳「使用者現在看的是哪一版」——那要多一條前後端參數，而它可能傳錯；
  無條件講一句永遠為真的話，達成同一個目的且沒有新的失效點（YAGNI）。
- **FR-005**：長來源 MUST 有上限策略，且該策略 MUST NOT 是「截斷前 N 字」
  ——被丟掉的後半使用者看不見，那是沉默失敗。超過上限時 MUST 以**該來源內部的檢索**取相關段落，
  且 MUST 保留足以回答「這篇整體在講什麼」的成分。
- **FR-006**：來源 MUST 在脈絡中被標示為**使用者收進的一手素材**，與 roots、與 spec 041 的文章分層陳述。
- **FR-007**：⚠️ 同一份來源同時被「帶入」與「撒網命中」時，MUST 只計為一份證言。
  否則模型會把同一段當成兩個獨立佐證，而畫面上看不出來。
- **FR-008**：bare 模式 MUST NOT 注入來源。
- **FR-009**：帶入來源 MUST NOT 修改該來源或任何已儲存內容。
- **FR-010**：⚠️ spec 041 FR-003 的閘門（冊封候選不得由文章原文生成）**MUST NOT** 套用於來源。
  理由：該閘門擋的是 model collapse，前提是**文章為 AI 產物**；來源是使用者收進的一手素材，
  而且從來源冊封是既有的合法功能（`/api/source/distill`）。照搬等於閹掉一條本來就開著的路。
- **FR-011**：未帶來源時，行為 MUST 與現況逐字相同。

## Success Criteria *(mandatory)*

- **SC-001**：使用者以**一個動作**把來源帶進對話；帶入後對話內容 **＝ 空**（是新的一段）。
- **SC-002**：⚠️ **撒網停用**的條件下，帶了來源的回答仍可驗證地反映該來源內容
  ——這條是本刀存在的理由，不能用「撒網也會撈到」蒙混過去。
- **SC-003**：送給模型的脈絡中，該來源譯文出現次數 **＝ 0**；原文出現次數 **≥ 1**。
- **SC-004**：長來源（> 上限）帶入時，脈絡長度在上限內，且**沒有任何一段是被硬切的**。
- **SC-005**：同一份來源被帶入且被撒網命中時，脈絡中該來源的內容區塊 **＝ 1 份**。
- **SC-006**：來源版與文章版的呈現，形狀差異 **＝ 0 處**。
- **SC-007**：未帶來源時，送給模型的脈絡與現況 **逐字相同**。
- **SC-008**：既有測試零回歸。

## Assumptions

- 沿用 spec 041 已定案的形狀，不重新徵詢。
- 「份內檢索」重用既有的 `retrieve_corpus`，只加來源過濾——不引入新的檢索機制（YAGNI）。
- 上限沿用文章的量級起步（`_ARTICLE_CAP` 同一個數量級），量到不夠再調。

## Out of Scope

- 段落級出處、多來源同時帶入、來源編輯、跨來源比對。
- 重開 spec 041 已定案的任何形狀。
