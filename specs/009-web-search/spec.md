## User Scenarios & Testing *(mandatory)*

### User Story 1 - 對開放網路搜尋（Priority: P1）

使用者想找某個剛紅、還沒進論文/電子報的東西——固定名冊和訂閱都看不到。他在 `/search` 打一個
查詢，工具對**開放網路**搜尋，回一串結果（每則：標題、網址、摘要），讓他快速掃看有什麼。

**Why this priority**: 這是第三口進水（web search＝臨時撒的網、反濾泡），補固定來源的盲點——
使用者能伸手到策展名冊**之外**。單獨實作即為可用 MVP（先能搜、能看）。

**Independent Test**: 用可注入的假搜尋後端回固定假結果，打一個查詢 → 頁面列出那些結果
（標題/網址/摘要），每則可點原文。

**Acceptance Scenarios**:

1. **Given** 一個查詢，**When** 在 `/search` 送出，**Then** 頁面列出搜尋結果，每則顯示標題、
   **可點的原文網址**、摘要。
2. **Given** 查詢無結果，**When** 送出，**Then** 顯示明確的「查無結果」提示（不空白、不報錯）。

---

### User Story 2 - 把有價值的結果冊封成種子（Priority: P1）

使用者在搜尋結果裡看到一篇很有價值的——他按該則的「**收進**」，工具把它抓下來、消化、收進
知識庫成為**種子**（複用既有 ingest）。之後問答就能檢索到它。**沒按收進的結果不會留下**。

**Why this priority**: 這是本階段的核心價值與概念關鍵——**搜尋＝AI 撒網（撈候選）、收進＝人挑
（冊封吸引子）**。與 P1 同列（搜尋若不能沉澱成 KB，價值大減）。

**Independent Test**: 假搜尋結果 → 對其中一則按「收進」（走既有 ingest，抓取可注入）→ 該篇成為
種子、`ask` 檢索得到；未收進的結果不在知識庫。

**Acceptance Scenarios**:

1. **Given** 一則搜尋結果，**When** 按「收進」，**Then** 該則被抓取、消化、收進知識庫成種子，
   之後 `ask` 可檢索到它（含原文連結）。
2. **Given** 一次搜尋回 N 則結果、使用者只收進其中一則，**When** 之後檢視知識庫，**Then** 只有
   **被收進的那則**在庫；其餘結果**未落庫**（搜尋結果預設短暫）。

---

### User Story 3 - 誠實邊界：後端不可用不炸（Priority: P3）

使用者可能沒設定搜尋 API 金鑰、或搜尋服務暫時失效/逾時。工具要**穩健**：友善繁中提示、
不噴技術堆疊；離線時也能以預設後端運作（供測試/展示）。

**Why this priority**: 搜尋是可選外部服務，失敗要優雅（教訓 3）；依附 P1，故 P3。

**Independent Test**: 令搜尋後端拋錯/未設金鑰 → `/search` 顯示友善繁中提示、頁面正常、無堆疊。

**Acceptance Scenarios**:

1. **Given** 搜尋後端失敗（無金鑰／逾時／服務錯誤），**When** 送出查詢，**Then** 顯示友善繁中
   提示、頁面正常回應、不噴未處理技術堆疊。

### Edge Cases

- **未設搜尋金鑰**：以預設（離線）後端運作或提示需設定；不崩。
- **收進失敗**（結果網址抓不到/解析失敗）：沿用 ingest 的友善提示，不寫半殘種子。
- **重複收進同一結果**：沿用 ingest 去重（已在庫則提示）。
- **搜尋結果不落庫**：離開頁面即消失，除非收進。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系統 MUST 提供一個 web 頁，接受一個查詢字串，對**開放網路**搜尋並列出結果，
  每則含**標題、可點原文網址、摘要**。
- **FR-002**：每則搜尋結果 MUST 能被**「收進」冊封成種子**——抓取該網址、消化、收進知識庫
  （**複用既有 ingest 流程**）；之後問答（`ask`）MUST 能檢索到它。
- **FR-003**：搜尋結果 MUST **預設短暫**——**不自動落庫**；**只有使用者按「收進」的才留**
  （原則 5 人冊封；工具不自動把搜尋結果存進 KB）。
- **FR-004**：搜尋後端 MUST **可插拔**——具備**離線預設後端**（回固定結果，供零外部呼叫測試），
  真實後端為可選外部服務（憲章 IV：不新增第三方相依）。
- **FR-005**：搜尋後端失敗／未設定／逾時時，系統 MUST 顯示**友善繁中提示**、頁面正常、
  不噴未處理技術堆疊（教訓 3）。
- **FR-006**：查無結果時 MUST 顯示明確提示（不空白、不報錯）。
- **FR-007**：「收進」MUST **復用種子機制**（不新增資料結構，教訓 8）；抓取/去重/失敗處理沿用
  既有 ingest（原則 3 溯源、不寫半殘）。
- **FR-008**：所有面向使用者文字 MUST 為**繁體中文**（憲章原則 II）。

### Key Entities *(include if feature involves data)*

- **查詢（Query）**：使用者輸入的搜尋字串。
- **搜尋結果（Search Result）**：一則開放網路結果——標題、原文網址、摘要；**短暫**（不落庫）。
- **種子（Seed）**：搜尋結果被「收進」後成為的 KB 條目（既有實體，spec 006）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：`/search` 對一個查詢 100% 回列結果（標題/原文網址/摘要），或查無時明確提示。
- **SC-002**：對一則結果按「收進」後，該篇**成為種子且 `ask` 檢索得到**（含原文連結）；
  未收進的結果**0 落庫**。
- **SC-003**：搜尋後端失敗/未設定時 **100%** 友善繁中提示、無技術堆疊。
- **SC-004**：功能在**離線**下完整通過測試（可注入假搜尋後端＋假抓取，零外部呼叫）；
  既有 190 測試不回歸。
- **SC-005**：面向使用者文字全繁中。

## Assumptions

- **搜尋結果短暫**是刻意設計：搜尋＝AI 撒網（撈候選）、收進＝人挑（冊封吸引子）。不做「搜尋
  歷史落庫」（YAGNI）。
- **真實搜尋後端**沿用既有 OpenAI 格式後端那套（stdlib urllib 呼叫＋config 金鑰/端點），
  故**不新增 Python 相依**；具體搜尋服務（Tavily/Brave 等）由 `/speckit-plan` 定，可換。
- **「收進」復用 spec 006 ingest**（`fetch_url`／SeedService）；種子存既有種子容器（無新 schema）。
- **介面**：本階段為 **web `/search`**；CLI 為後續。
- **範圍外**：趨勢讀數（B：熱詞 chips／固定池統計）、把 web search 併進 `pull`、搜尋結果自動落庫、
  每來源品質加權。
- **開發**：TDD 強制（憲章原則 I）——先寫失敗測試再實作；契約測試用可注入假搜尋後端（離線）。
