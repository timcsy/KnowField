## User Scenarios & Testing *(mandatory)*

### User Story 1 - 瀏覽並刪除我收的種子（Priority: P1）

使用者用 `ingest`／web 收進框陸續收了不少種子。時間久了想**清理**——看看收了哪些、把當初收
錯或不再需要的**刪掉**。打開 `/library`，看到自己冊封的種子清單（標題、類型、日期、原文連結），
按刪除即從知識庫移除；之後問答不再檢索到它。

**Why this priority**: 這是本階段的核心價值，也補上工具最大的缺口——**只能加、不能修剪**。
是原則 5「人冊封」的另一半（也能**退**吸引子）。單獨實作即為可用 MVP。

**Independent Test**: 種入幾則種子 → 開 `/library` 看到清單 → 刪一則 → 該則消失、且 `ask`
再也檢索不到它、其嵌入向量也清掉（無孤兒）。

**Acceptance Scenarios**:

1. **Given** 已收了數則種子，**When** 開 `/library`，**Then** 看到種子清單，每則顯示整理過標題、
   來源類型（解說文／一般）、收進日期、可點的原文連結。
2. **Given** 清單中一則種子，**When** 刪除它，**Then** 該則從清單消失、`ask` 不再檢索到它、
   **其嵌入向量也一併清除**（無孤兒向量）。
3. **Given** 尚無任何種子，**When** 開 `/library`，**Then** 顯示明確空狀態提示（不空白、不報錯）。

---

### User Story 2 - 重新分類（解說文↔一般）（Priority: P2）

使用者發現某則種子其實是高品質解說文（或當初誤標了），想調整它的品質層級。在 `/library`
把它在「解說文↔一般」間切換；改完後，該種子在問答檢索的**權重立即跟著變**。

**Why this priority**: 調權重是「人冊封」的第三個動作（加／退／**改**）；依附 P1 的清單，故 P2。

**Independent Test**: 一則種子標為一般 → 在 `/library` 改成解說文 → 對相關問題問 `ask`，
驗證它的檢索權重提高（沿用 spec 006 的解說文加權）。

**Acceptance Scenarios**:

1. **Given** 一則「一般」種子，**When** 在 `/library` 重分類為「解說文」，**Then** 清單反映新類型，
   且該種子在問答檢索的權重提高（解說文加權生效）。
2. **Given** 一則「解說文」種子，**When** 重分類回「一般」，**Then** 權重回到一般。

---

### User Story 3 - 只碰種子、每日流唯讀（Priority: P3）

使用者的知識庫同時有「種子」（手動冊封）與「每日匯整條目」（自動流）。管理頁**只**呈現與
操作種子；每日流的條目是流的歷史紀錄，**不出現在管理頁、也不能從這裡刪**——避免誤刪紀錄。

**Why this priority**: 保護每日流紀錄的完整性（防誤刪）；是管理範圍的界線，依附 P1 清單，故 P3。

**Independent Test**: 種一份每日匯整＋幾則種子；開 `/library` 只看到種子、看不到每日流條目；
確認沒有途徑從管理頁刪掉每日流條目。

**Acceptance Scenarios**:

1. **Given** 庫中同時有每日匯整條目與種子，**When** 開 `/library`，**Then** 只列出**種子**，
   不含每日流條目。
2. **Given** 管理頁，**When** 檢視可操作項，**Then** 沒有任何刪除每日流條目的入口。

### Edge Cases

- **空知識庫**：無種子 → 空狀態提示（引導去「收進」）。
- **刪除已被問答引用的種子**：刪除後該來源自然不再出現在新答案（歷史答案不追改）。
- **重分類為相同類型**：無害的 no-op。
- **並發**：刪除一則不影響其他種子的檢索。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系統 MUST 提供一個 web 管理頁，列出使用者收進知識庫的**種子**，每則顯示：整理過
  標題、**來源類型（解說文／一般）**、收進日期、**可點的原文連結**（原則 3 溯源）。
- **FR-002**：使用者 MUST 能**刪除**一則種子；刪除後該種子從知識庫移除，問答（`ask`）**不再
  檢索到它**。
- **FR-003**：刪除種子 MUST **一併清除其嵌入向量**，不得留下孤兒向量（教訓 8）。
- **FR-004**：使用者 MUST 能將種子在「**解說文（高品質）↔一般**」間**重新分類**；變更後其問答
  檢索**權重即時反映**（沿用既有解說文加權）。
- **FR-005**：管理頁 MUST **只列出／只操作種子**；**每日匯整（流）的條目 MUST NOT 出現於此、
  也 MUST NOT 可從此刪除**（流的歷史紀錄唯讀）。
- **FR-006**：所有面向使用者文字 MUST 為**繁體中文**（憲章原則 II）。
- **FR-007**：知識庫**尚無種子**時 MUST 顯示明確空狀態提示（不空白、不報未處理錯誤）。
- **FR-008**：本功能 MUST 為**純資料操作**、**離線可完整測試**（零外部呼叫綠燈，教訓 1）；
  MUST **複用既有核心**（既有資料存取、web CRUD 樣式），不重寫核心。
- **FR-009**：管理範圍 MUST **僅止於組織／刪除／重分類**，MUST NOT 提供編輯消化內容（散文本體）。

### Key Entities *(include if feature involves data)*

- **種子條目（Seed）**：使用者手動冊封的一則材料——含整理過標題、來源類型（解說文／一般）、
  收進日期、原文連結、內部識別；與**每日流條目**同屬語料但來源不同（管理頁只碰種子）。
- **來源類型／品質層級**：`解說文（高品質）` 或 `一般`；決定問答檢索權重（可被重分類變更）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：`/library` 100% 列出使用者收的種子（標題／類型／日期／原文連結俱全），且**不含**
  任何每日流條目。
- **SC-002**：刪除一則種子後，該則**不再出現在管理頁、不再被問答檢索到、其嵌入向量已清除**
  （孤兒向量數 = 0）。
- **SC-003**：把一則種子重分類為解說文後，對相關問題其**檢索排序權重提高**（以對照材料驗證）。
- **SC-004**：**無法**從管理頁刪除或編輯每日流條目（保護流的紀錄）。
- **SC-005**：面向使用者文字全繁中；空狀態有提示。
- **SC-006**：功能在**離線**下完整通過測試（零外部呼叫）；既有 166 測試不回歸。

## Assumptions

- **管理對象＝種子**（`ingest`／web 收進框收的、存於種子容器）；每日匯整條目為**流的紀錄、
  唯讀**，不在管理範圍。
- **刪除為刻意操作**（明確的刪除動作）；本增量不做「回收桶／復原」（YAGNI，後續再議）。
- **重分類**沿用既有 `source_class` 二分（解說文／一般）與其檢索加權（spec 006）。
- **介面**：本階段為 **web `/library`**（照既有 `/interests` 的 web CRUD 模式）；CLI 管理為後續。
- **範圍外**：來源管理（耦合「來源訂閱」，另做、之後共用管理頁模式）；編輯散文本體；批次操作／
  搜尋（KB 大了才需要）；學到的興趣畫像檢視（興趣畫像 draft）；每日流條目刪除。
- **開發**：TDD 強制（憲章原則 I）——先寫失敗測試再實作；契約測試離線（純 DB CRUD）。
