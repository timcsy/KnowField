**用詞**：**領域**＝樹上的節點 · **主題 Topic**＝從根到節點的路徑 · **知識**＝葉（來源／對話／核心理解／文章）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 建得出多層的領域樹 (Priority: P1)

**Acceptance Scenarios**:

1. **Given** 空的知識庫，**When** 建「AI」再在其下建「生成模型」，**Then** 樹有兩層。
2. **Given** 一個節點，**When** 查它的**主題路徑**，**Then** 得到從根到它的完整序列。
3. **Given** 同名節點掛在不同父下，**Then** 它們的主題路徑**不同**。

---

### User Story 2 - 對話有位置，也能在位置上開始 (Priority: P1)

**Acceptance Scenarios**:

1. **Given** 一個領域，**When** 在它底下開新對話，**Then** 那段對話歸屬到該領域。
2. **Given** 既有對話，**When** 指定領域，**Then** 歸屬更新。
3. **Given** 沒指定，**Then** 該對話**未歸屬**（不屬於任何領域）。

---

### User Story 3 - 現有行為一個字都不變 (Priority: P1)

**Why this priority**：這一刀的價值有一半在「安全」。使用者要用過真的樹才決定第三刀，
⚠️ **若這一刀偷偷改了 grounding，那個判斷就被污染了**。

**Independent Test**：`git diff` 中，`list_why_nodes("anointed")` 與 `list_corpus_entries`
的 **8+4 處呼叫點一行都沒被碰**。

---

### Edge Cases

- ⚠️ **把節點搬到自己的子孫底下** → 會成環，而路徑計算**不會報錯**、只會變成無意義的結果 ⇒ MUST 擋。
- **刪除有子節點的領域** → 見 FR-008。
- **既有 75 條理解、31 段對話** → 全部未歸屬，MUST NOT 自動分類。

## Requirements *(mandatory)*

- **FR-001**：MUST 能建立／改名領域，且領域 MUST 能有父領域（多層）。
- **FR-002**：MUST 能查出任一領域的**主題路徑**（從根到它）。
- **FR-003**：⚠️ 路徑 MUST 由 `parent_id` **導出**，MUST NOT 另存一份路徑字串
  ——存了就要在改名／搬家時全量重算，而**漏算不會報錯**，只會讓路徑慢慢對不上。
- **FR-004**：⚠️ 搬動領域時 MUST 擋住成環（把節點搬到自己的子孫底下）。
- **FR-005**：對話 MUST 能歸屬到一個領域；MUST 能「在某領域開新對話」。
- **FR-006**：未歸屬 MUST 以「沒有值」表示，MUST NOT 種一個 magic root 列
  ——那會讓「未歸屬」變成樹上的一個節點。
- **FR-007**：⚠️ 既有資料 MUST 全部維持未歸屬；MUST NOT 自動分類
  ——AI 猜領域＝造假歸屬，而它看起來會跟真的一樣。
- **FR-008**：刪除領域 MUST NOT 靜默孤兒化其子節點或對話——要嘛擋、要嘛明講會發生什麼。
- **FR-009**：⚠️ **grounding 逐字不變**：`list_why_nodes("anointed")`（8 處）與
  `list_corpus_entries`（4 處）的呼叫點 MUST NOT 被修改。
- **FR-010**：領域樹 MUST NOT 影響任何檢索排序——它是**導航**，不是權重
  （原則 5：權重由人冊封，不由位置給）。

## Success Criteria *(mandatory)*

- **SC-001**：三層樹（A/B/C）中，C 的主題路徑 **＝ [A, B, C]**。
- **SC-002**：同名節點掛不同父 → 兩者主題路徑**不相等**。
- **SC-003**：⚠️ 把 A 搬到 C 底下 → **被拒**，且樹維持原狀。
- **SC-004**：新建對話帶領域 → DB 中該對話的領域 ＝ 指定值；不帶 → 空。
- **SC-005**：⚠️ 既有對話與理解的歸屬 **100% 為空**（沒有任何一筆被自動分類）。
- **SC-006**：⚠️ `git diff` 中，那 8+4 處呼叫點的改動行數 **＝ 0**。
- **SC-007**：兩後端（SQLite／PG）行為相同。
- **SC-008**：既有測試零回歸。

## Out of Scope

- 捷徑／DAG、RAG scope、跨領域核心理解。
- 核心理解／文章／來源的歸屬（只做對話）。
- 自動分類、把既有資料搬進樹。
- `matched_topic` ——⚠️ **它不是殘骸**（活在種子進料路徑，8 個測試在守，111 塊有值）。
