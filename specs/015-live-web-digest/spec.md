# 規格：live web 活水（開放網路進每日 digest）

**功能**：LearnNews 路線圖階段 13
**分支／目錄**：`specs/015-live-web-digest/`
**建立日期**：2026-07-25
**設計源**：`draft/2026-07-24-趨勢熱詞發現.md`（live 活水段）、`concepts/有吸引子的場.md`（反濾泡）

## 摘要

使用者核心痛點：**追不到剛紅的 AI 趨勢**——連 Opus 5 這種大新聞，工具都漏。因為固定名冊
（論文骨幹＋週刊策展）**結構上抓不到即時產品新聞**。本功能讓每日匯整**除了抓固定名冊，也對
「AI 最新」做一次開放網路搜尋**，把剛炸的新聞當材料餵進**既有匯整流程**（去重／依興趣排序／
消化）——刻意伸手到策展名冊**之外**（concept 的反濾泡／驚訝力）。

因為用搜尋服務、有成本，這是一個**預設停用的 opt-in 來源**：使用者在來源管理啟用、且設了
搜尋金鑰，才真正生效；不啟用＝零成本、行為與現在完全一樣。web 帶進來的是**流**（會被排序
過濾），**不是種子**——要長期留仍靠「收進」冊封（主權不變）。

## 使用者情境與測試

### 主要使用者故事

**US1（P1）——匯整也抓得到剛紅的新聞**
作為一個想跟上最新的使用者，我希望每日匯整**不只有論文和週報**，也能把「昨天剛發布的 Opus 5」
這種開放網路上正在紅的新聞納進來。

- **驗收情境**：
  1. **Given** 我啟用了「開放網路 AI 趨勢」這個來源、且設了搜尋金鑰，**When** 我產生／重新整理
     匯整，**Then** 匯整**納入開放網路上剛紅的 AI 新聞**（如新模型發布），每則**帶原文連結可回溯**。
  2. **Given** web 帶進來的新聞，**When** 呈現在匯整，**Then** 它們**經過與我興趣的相關度排序**
     （離題的被濾掉）、消化成可讀重點——與其他來源一視同仁。

**US2（P1）——預設不花錢、要才開**
作為在意成本的使用者，我希望這個「開放網路搜尋」**預設是關的**，只有我主動啟用才會花搜尋額度。

- **驗收情境**：
  1. **Given** 我**沒有啟用**該來源（或沒設搜尋金鑰），**When** 我產生匯整，**Then** **不會**觸發任何
     開放網路搜尋，行為與現在完全一致（零額外成本）。
  2. **Given** 該來源，**When** 我在來源管理看它，**Then** 它**預設是停用**的，我可自行啟用／停用。

**US3（P1）——進的是流，不是自動種子**
作為知識庫的主人，我不希望開放網路搜到的一堆東西**自動變成我知識庫的種子**（那會被雜訊污染）。

- **驗收情境**：
  1. **Given** web 帶進匯整的新聞，**When** 匯整產生，**Then** 它們是**當日流的一部分**、**不會自動
     成為種子**；我看到有價值的那則，**仍需自己「收進」**才冊封成種子。

**US4（P2）——搜尋掛了不擋整份匯整**
- **驗收情境**：
  1. **Given** 啟用了 web 來源但搜尋服務失敗／逾時，**When** 產生匯整，**Then** 匯整**照常用其他
     來源產出**，並**標示這個來源缺漏**（沿用既有缺漏機制），不噴錯誤堆疊。

### 邊界情況

- **啟用了但沒設金鑰**：等同離線／無結果——沿用缺漏標示，匯整照常（不崩）。
- **搜尋回重複網址**：合併去重（同 url 只一則）。
- **web 結果與興趣無關**：被既有相關度排序過濾，不硬塞。
- **離線（測試）**：走離線 stub 搜尋，零外部呼叫、可測。

## 需求（功能）

- **FR-001**：系統**必須**提供一個「開放網路 AI 趨勢」來源，啟用且具搜尋金鑰時，產生匯整會**對
  一組「AI 最新」查詢做開放網路搜尋**，把結果作為匯整材料。
- **FR-002**：web 搜尋結果**必須經與其他來源相同的匯整流程**（去重、依使用者興趣相關度排序、
  消化），且**每則帶原文連結可回溯**（原則 3）。
- **FR-003**：該來源**必須預設停用（opt-in）**；未啟用或未設搜尋金鑰時，**不得觸發任何開放網路
  搜尋**、行為與現況一致（零額外成本、原則 5＋根公理成本閘）。
- **FR-004**：web 帶進匯整的材料是**當日流**、**不得自動成為種子**；要冊封成種子**必須**經使用者
  「收進」（原則 5、憲章 VI）。
- **FR-005**：該來源搜尋**失敗／逾時**時，匯整**必須照常以其他來源產出**、並**標示此來源缺漏**
  （沿用既有缺漏機制，憲章 V、教訓 3）；不得噴例外堆疊。
- **FR-006**：多個查詢的結果**必須合併去重**（同原文網址只保留一則）。
- **FR-007**：web 搜尋**必須可離線測試**（可插拔、零外部網路呼叫可通過契約測試）。
- **FR-008**：本功能**必須不新增資料表、不改動既有資料表**（該來源即來源清單中的一列，教訓 8）。
- **FR-009**：所有面向使用者文字**必須為繁體中文**。

### 明確排除（範圍外，防蔓延）

- **web 結果自動變種子**（絕不；只當流，收進才留）。
- **竄升排序、成核**（另階段）。
- **per-query LLM 查詢擴展**、即時串流。
- **興趣驅動自動生成查詢**（MVP 用固定查詢清單；興趣驅動列後續）。
- **硬抓 Threads/X**（無公開 API／合規顧慮）——用既有 HN/Reddit 源＋本 web 活水補。

## 關鍵實體

- **開放網路 AI 趨勢來源**：來源清單中的一列（預設停用），承載一組「AI 最新」查詢；啟用＋有金鑰
  才生效。
- **web 匯整材料**：由開放網路搜尋得到、映成匯整材料（標題／原文連結／摘要）；短暫的當日流，
  不落庫為種子。

## 假設

- 沿用既有可插拔搜尋後端（離線 stub／真實 API）與搜尋金鑰設定（同 `/search`）。
- 沿用整條匯整流程（去重／依興趣排序／消化／缺漏標示）與來源管理（啟用/停用）。
- web 結果無可靠日期 → 不做時間過濾，靠匯整的相關度排序與去重把關。
- 查詢用固定一組「AI 最新」問法（MVP）；興趣驅動查詢列後續。

## 成功標準（可驗，技術中立）

- **SC-001**：使用者啟用該來源＋設金鑰後，匯整**納入開放網路剛紅的 AI 新聞**（Opus 5 這類進得來），
  每則可回原文——追得到固定名冊看不到的東西。
- **SC-002**：**預設停用**；未啟用／未設金鑰時**零開放網路搜尋、行為與現況一致**。
- **SC-003**：web 材料**經興趣相關度排序過濾**、**不自動變種子**（要留靠「收進」）。
- **SC-004**：該來源搜尋失敗時匯整**照常產出並標示缺漏**、頁面不崩。
- **SC-005**：**離線可測、零外部呼叫**；**不新增／不改資料表**；既有 249 測試不回歸。
- **SC-006**：**自動變種子／竄升／成核／LLM 查詢擴展／串流／硬抓 Threads-X 未出現**（範圍守住）。
