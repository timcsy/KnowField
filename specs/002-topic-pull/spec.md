# 功能規格：主題拉取深挖（拉模式）

**Feature Branch**: `002-topic-pull`

**Created**: 2026-07-23

**Status**: Draft

**Input**: 路線圖階段 3——LearnNews「拉」模式：使用者對某主題有興趣時，工具往那條線
擴展來源、溯源，把相關原始材料鋪到面前。工具**不分析、不下結論、不嚼爛**（原則 4）；
拉的本質就是溯源（原則 3）。設計輸入見 `knowledge/draft/2026-07-23-雙模式-推拉.md`、
`knowledge/draft/2026-07-23-興趣畫像.md`。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 對一個主題拉取相關原礦 (Priority: P1)

作為一位想深入某條線的使用者，我給工具一個**主題**（例如「latent reasoning」），
工具跨來源**搜尋擴展**該主題（不只當日最新，而是更廣更深）、去重、依相關性排序，
把一份**可直達原文**的相關材料清單鋪到我面前，讓我自己去挖。

**Why this priority**：這是「拉」模式的核心價值——把分診（推）之外的「深挖某主題」補齊。
單獨實作即為可用增量：使用者當下就能對任一主題快速拉到一疊可信、可溯源的原礦。

**Independent Test**：給定一個主題與一組來源樣本，執行一次拉取；驗證輸出為跨來源、
去重後、依該主題相關性排序、每則含直達原文的清單。

**Acceptance Scenarios**:

1. **Given** 指定主題與可用來源，**When** 執行拉取，**Then** 得到依該主題相關性排序的
   材料清單，且與主題無關者被濾除。
2. **Given** 同一則材料跨多個來源出現，**When** 拉取，**Then** 在結果中只出現一次（去重）。
3. **Given** 拉取結果，**When** 檢視任一則，**Then** 有可直達原文的連結；無原文者不納入。
4. **Given** 拉取結果，**When** 檢視，**Then** 工具**不提供**對主題的結論、評價或深度分析
   ——只鋪相關原礦（原則 4）。
5. **Given** 一個較廣的主題，**When** 拉取，**Then** 結果數量收斂在可控上限，且可調整。

### User Story 2 - 從推模式匯整一鍵深挖 (Priority: P2)

作為使用者，我在每日匯整（推）看到一則感興趣的條目時，可以直接對它所屬的**主題**
發起拉取，順勢深挖，而不必重打主題。

**Why this priority**：讓推與拉銜接成一個自然流程（掃匯整 → 勾到 → 深挖），放大兩者
合體的價值。依賴 US1 的拉取能力，故次於它。

**Independent Test**：從一則既有匯整條目取得其主題／關鍵詞，發起拉取，驗證回傳該主題的
擴展結果。

**Acceptance Scenarios**:

1. **Given** 一則匯整條目，**When** 以它為起點發起拉取，**Then** 得到該主題的擴展材料清單。

### Edge Cases

- 主題**過於冷門**、跨來源都搜不到相關材料時，如何呈現（空結果並明確說明）？
- 某來源在拉取時**不可取得**（逾時／限流）時，是否照常回傳其他來源結果並標示缺漏？
- 主題**過於寬泛**（如「AI」）導致擴展爆量時，如何以上限與相關性門檻收斂？
- 拉取結果與**近期推匯整**高度重疊時，是否標示或去重？
- 主題原文為**非中文**時，結果清單與相關性照常運作，直達連結指向原文。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：使用者 MUST 能對一個**指定主題**發起拉取。
- **FR-002**：系統 MUST 跨來源**搜尋擴展**該主題的相關材料（不限於當日最新，涵蓋更廣範圍）。
- **FR-003**：系統 MUST 對拉取結果**去重**（同一則材料只出現一次）。
- **FR-004**：系統 MUST 依材料與**主題的相關性**排序，並濾除低於門檻的無關材料。
- **FR-005**：系統 MUST 為每則結果提供**可直達原文**的連結；無法直達原文者 MUST 排除或
  明確標示，不得以生成內容取代原文。
- **FR-006**：系統 MUST NOT 對主題產生**結論、評價或深度分析**——無論是否附摘要，
  拉取都只鋪相關原礦（深加工由使用者自己做）。
- **FR-006a**：**預設**每則結果附一句**封頂定位**（幫使用者快速判斷要不要深挖），其長度
  與「不代勞」限制比照推模式（不超過一句、禁結論式分析）。使用者 MUST 能以旗標
  （如 `--raw`／`--no-summary`）切換成**純原礦清單**（僅標題＋來源＋直達連結，完全不生成文字）。
- **FR-007**：系統 MUST 將結果數量收斂在**可調整的上限**內，避免擴展爆量。
- **FR-008**：當某來源不可取得或主題無相關結果時，系統 MUST 仍回傳可用結果並**明確標示**
  缺漏或空狀態，不得靜默失敗。
- **FR-009**：所有面向使用者的文字（介面、狀態、錯誤）MUST 以**繁體中文**呈現；材料原文
  為其他語言時，直達連結仍指向原文。
- **FR-010**：系統 SHOULD 讓使用者能**從一則既有匯整條目**發起對其主題的拉取（US2）。

### Key Entities *(include if feature involves data)*

- **主題查詢（Topic Query）**：使用者指定的主題字串，作為擴展搜尋與相關性排序的依據。
- **拉取結果集（Pull Result）**：某次拉取產出的、去重且依相關性排序的材料清單，附缺漏
  來源標示與可控上限的截斷資訊。
- **材料（Item）**：一則新聞或論文（沿用推模式的條目概念），具標題、原文連結、來源、
  所屬事件群組、與主題的相關性分數。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：對一個明確主題發起拉取，結果中使用者判定為「相關」的比例 **≥ 75%**。
- **SC-002**：拉取結果**100%** 提供可直達原文的連結。
- **SC-003**：結果中同一則材料**不重複出現**（去重正確率 ≥ 95%）。
- **SC-004**：拉取結果數量收斂在可控上限內（預設上限，例如 **≤ 30 則**，可調整）。
- **SC-005**：拉取結果中**不含**系統對主題的結論式判斷或分析文字（不論預設附定位或
  `--raw`，皆 0% 出現結論／分析）。
- **SC-007**：`--raw` 模式下**完全不生成任何文字**（僅標題＋來源＋連結）；預設模式每則
  定位不超過一句（比照推模式封頂）。
- **SC-006**：使用者能在一次操作內對指定主題取得擴展結果（無需多步設定）。

## Assumptions

- **來源集**：沿用推模式的來源（arXiv 主題搜尋、HF Papers、精選新聞源）；拉取的「擴展」
  主要靠**可依主題查詢的來源**（如 arXiv search API）＋對其他來源近期材料的相關性過濾。
  **不依賴 Semantic Scholar citation graph**（free 端點持續 429，見 `history/005`）。
- **不新增付費／X 來源**（沿用 MVP 來源政策）。
- **沿用既有能力**：去重、相關性排序、可插拔 Embedder 直接複用推模式的實作。
- **範圍邊界**：本規格只涵蓋「拉」（主題擴展溯源）。**知識沉澱（階段 4）不在範圍。**
- **不做深加工**：不產生第一性拆解、趨勢外推或任何結論（憲章原則 IV／`principles.md` 原則 4）。
- **摘要預設開（已定案 2026-07-23）**：預設每則附一句封頂定位（幫快速判斷），使用者可用
  `--raw`／`--no-summary` 切成純原礦清單。定位仍受「不代勞」約束（原則 4）。
