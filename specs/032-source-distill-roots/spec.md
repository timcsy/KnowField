# Feature Specification: 收進的活化——整理成核心理解

**Feature Branch**: `032-source-distill-roots`

**Created**: 2026-08-05

**Status**: Draft

**Input**: User description: 收進的活化——「整理成核心理解」（路線圖階段 26，promote 自 draft/2026-08-05 第一刀 #1）。讓一份收進的來源（外部證言）能經人閘門，被整理、升級成使用者的「核心理解」，原文成為該理解的「由來」。

## 動機 *(why)*

進料層做完後，「收進」是一個**被動的證言桶**——像 Evernote：捕捉容易、囤到爆、再也不看。這工具的差異化**不在多捕捉、在活化**：讓收進的內容能經**使用者親手**的一道關卡，升級成他自己的**核心理解**（往下推理的地基），而原文留作那條理解的**由來**（可回溯）。這是「證言 →（人把關）→ 地基」的下一步，也是產品「反 Evernote」的靈魂動作。

**紅線（貫穿全規格）**：升級**只能由人按**。系統只**提候選**、**絕不**自動把收進內容變成核心理解、**絕不**讓收進內容偷偷變成推理地基。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 把一份收進整理成核心理解（Priority: P1）

使用者在某份收進來源的檢視頁，按一個「整理成核心理解」的動作。系統讀這份來源的內容，**提出幾條候選的核心理解**（每條都標明是「AI 從這份來源推斷的、附證據」）。使用者**逐條檢視**，把真的內化、認同的**親手收進**核心理解。收進後，那條核心理解能**連回這份來源**當它的「由來」。

**Why this priority**: 這是整個階段的 MVP 主迴圈——沒有它就沒有「活化」。它把被動的收進變成主動的內化入口，是差異化的核心。

**Independent Test**: 給一份已收進的來源 → 按「整理成核心理解」→ 得到候選清單 → 收進其中一條 → 到核心理解列表確認該條在、且能連回這份來源。全程離線可測（萃取後端可注入替身）。

**Acceptance Scenarios**:

1. **Given** 一份已收進、有內容的來源，**When** 使用者對它按「整理成核心理解」，**Then** 系統回傳一份**候選核心理解**清單，每條標明「AI 推斷、附來源證據」。
2. **Given** 一份候選核心理解，**When** 使用者親手把它收進核心理解，**Then** 它出現在核心理解列表，且該條能**連回原來源**當「由來」。
3. **Given** 使用者只看候選但**沒有**收進任何一條，**Then** 核心理解列表**不變**（沒有任何東西被自動收進）。

---

### User Story 2 - 純度守衛：整理不污染地基（Priority: P2）

使用者信任這工具**不會**把他收進的別人文章偷偷當成他自己的想法。因此「整理成核心理解」這個動作，**只產候選、不自動收進**；收進的內容在被使用者親手升級之前，**永遠是外部證言、不進推理地基**。

**Why this priority**: 這是使用者「敢建知識庫」的信任基礎（原則 6：只有沉澱物入場）。若破，整個產品的反逢迎承諾就破。它可獨立以守衛測驗證，故列 P2。

**Independent Test**: 對一份來源跑「整理成核心理解」後，檢查：候選未被自動收進核心理解；且系統餵給聊天的「地基」不含這份收進內容。以守衛測驗（延續既有純度守衛）。

**Acceptance Scenarios**:

1. **Given** 對一份來源跑完「整理成核心理解」，**When** 檢查核心理解的地基，**Then** 這份收進內容**不在**地基裡、也**沒有**被自動收進成核心理解。
2. **Given** 一條候選核心理解，**When** 使用者未按收進，**Then** 它停在「候選」狀態，不影響任何推理。

---

### User Story 3 - 整理失敗不擋看原文（Priority: P3）

使用者對一份來源按「整理成核心理解」，但當下萃取（需要外部模型）失敗。此時來源檢視頁**照常顯示原文**，只是給一句友善的「整理暫時失敗，稍後再試」，不噴錯誤頁、不擋使用者看原文。

**Why this priority**: 韌性（教訓 3：外部失敗在邊界攔截）。不是主迴圈，但缺了會在真實使用中砸掉信任，故納入。

**Independent Test**: 注入一個會失敗的萃取後端 → 按「整理成核心理解」→ 頁面仍顯示來源原文＋友善訊息，不 500。

**Acceptance Scenarios**:

1. **Given** 萃取後端會失敗，**When** 使用者按「整理成核心理解」，**Then** 來源檢視頁照常顯示原文，並給友善的失敗提示，不中斷。

---

### Edge Cases

- **來源內容很短/很空**：應能回「這份來源沒有足夠內容可整理」而非硬生出候選（避免無中生有的橡皮圖章）。
- **候選與既有核心理解重複**：已收進過的同一條理解不該重複出現在候選（沿用既有去重）。
- **同一份來源被整理多次**：重按不應產生重複的由來連結或重複收進。
- **使用者刪掉那份來源後**：已由它升級的核心理解**仍在**（核心理解是使用者的地基、不隨來源消失），但其「由來」連結需優雅處理來源已不在（顯示為已移除，不留破連結）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 讓使用者在一份收進來源的檢視頁，觸發「整理成核心理解」動作。
- **FR-002**: 系統 MUST 讀該來源的內容、產出一份**候選核心理解**清單；每條候選 MUST 標明「AI 從此來源推斷、附來源證據」。
- **FR-003**: 每條候選 MUST 經過可信度過濾（自我反駁的試金石，比照既有根因萃取的信心層級），低信心者標明或濾除，**不得**把未過濾的推斷當成確定結論呈現。
- **FR-004**: 系統 MUST NOT 自動把任何候選收進成核心理解；升級成核心理解 MUST 由使用者親手觸發（人閘門）。
- **FR-005**: 系統 MUST NOT 讓收進來源的內容進入聊天推理的「地基」，也 MUST NOT 讓它在未經人閘門下自動成為核心理解（純度守衛，延續既有守衛）。
- **FR-006**: 使用者把候選收進核心理解後，系統 MUST 建立該核心理解到**原來源**的「由來」連結，使核心理解列表能回溯到這份來源。
- **FR-007**: 系統 MUST 沿用既有的候選→收進流程與核心理解列表（不另做一套平行的收進介面）。
- **FR-008**: 對外顯示 MUST 只用「整理成核心理解」「核心理解」「候選」「由來」等一般語彙，MUST NOT 洩漏內部設計詞（如 distill／anoint／why-node）。
- **FR-009**: 當萃取失敗時，系統 MUST 在邊界攔截，來源檢視頁照常顯示原文並給友善提示，MUST NOT 中斷或噴伺服器錯誤。
- **FR-010**: 已由某來源升級的核心理解，在該來源被刪除後 MUST 仍保留（核心理解屬使用者地基）；其由來連結 MUST 優雅處理來源已不存在。
- **FR-011**: 全繁體中文。

### Key Entities *(include if feature involves data)*

- **核心理解（使用者親手冊封的根因）**：使用者親手收進的地基理解。本功能新增一種**由來＝來源**的可能（既有由來為對話）。
- **候選核心理解**：AI 從一份來源推斷、待使用者檢視的暫態提議；標「AI 推斷＋來源證據」，未收進前不影響任何推理。
- **收進來源**：既有的一份收進（按 url 歸組的塊集合），是本功能的輸入與被連回的「由來」對象。
- **由來連結**：核心理解 ↔ 其來源出處的關聯。既有為「核心理解 ↔ 對話」；本功能需擴出「核心理解 ↔ 收進來源」（具體資料模型由技術方案定案，優先低遷移風險）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者能在來源檢視頁一鍵得到該來源的候選核心理解，並親手把其中認同的收進——**全程無需離開該來源脈絡**。
- **SC-002**: 跑完「整理成核心理解」後，**未經使用者親手收進的候選一律不進核心理解、不進推理地基**（守衛測 100% 通過，零污染）。
- **SC-003**: 每條候選都可見「這是 AI 從哪份來源推斷、依據為何」，使用者能判斷是否採信——**沒有無來源、無標記的斷言被當成確定核心理解呈現**。
- **SC-004**: 收進後，從核心理解列表能一步回溯到原來源（由來連結可用）。
- **SC-005**: 萃取失敗時，來源檢視頁仍 100% 可看原文，不出現伺服器錯誤頁。
- **SC-006**: 既有測試零回歸（現 336）；全繁中；不改既有已出貨表的語義。

## Assumptions

- **沿用既有機制**：候選產生、候選→收進（人閘門）、核心理解列表、由來連結、來源檢視與取回來源塊，皆復用既有能力；本功能是把「整理」的輸入從「對話」擴到「一份收進來源」，不新建平行系統。
- **萃取後端可注入**：需要外部模型的萃取藏在可插拔介面後、預設離線替身，故核心離線可測、零外呼。
- **源→根因由來的資料模型**：現有由來為「核心理解 ↔ 對話」；來源不是對話，故需擴一條「核心理解 ↔ 來源」的連結。**優先不改既有已出貨表語義、加可空欄位**（比照既有以加 nullable 欄擴充的低遷移風險先例）；確切方式由技術方案（plan/research）定案。
- **刻意排除「無摩擦一鍵升級」**：候選必須逐條經人檢視、親手收進，避免「批准提案」淪為橡皮圖章（教訓：提案-批准 ≠ 打到需求）。
- **範圍外**（各自後續 promote）：引用頻率信號（常被引用→升級提醒/沉降保護）、收進的沉降排序（能見度）、核心理解的拓撲/收斂（階層/backlinks/分群）、密度自動分級、無摩擦一鍵升級、對話端整理（已在聊天既有）。
