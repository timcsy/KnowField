# spec 080：專案落成來源（階段 71 第二刀）

## 為什麼

> 「**專案就像是一個來源一般**⋯我還是希望有開發模式，不過**專案成為來源而已**。」

而既有的來源那一層，語意逐字就是對的：
「**外部證言**：可以引用，但**比他精選的理解軟**⋯**別當成他的地基**」。

⚠️ 而 `_ingest_markdown(md, title, url)` **就是共同出口**——貼上／網址／PDF 都走它。
專案的知識檔一樣走它，⇒ 切塊、嵌入、去重、進語料**全部免費**。

## FR

- **FR-001** 抓一個 repo 之後，把 `knowledge/**.md` **逐檔落成來源**
  （`url = github://owner/repo/knowledge/x.md`），走既有的 `_ingest_markdown`。
- **FR-002** ⚠️ **歸屬要跟抓取同時發生**：一個專案 ＝ 一個領域（沒有就建），
  每個來源直接歸到它底下。
  ⚠️ 三個專案 ＝ **514 個新來源**，湧進一個只有 55 個來源的頁面
  ——**第一次淹掉就是你唯一會發現它的時刻**。
- **FR-003** 重抓時 `seed_exists(url)` 會擋重複 ⇒ **只補新檔**；
  ⚠️ 而**刪掉的檔案要處理**：不處理的話，那個來源會永遠留著（而且進語料）。
- **FR-004** 開發模式的樹改讀**那個領域底下的來源**，路徑從 `url` 還原。
- **FR-005** ⚠️ **`ext_items` 不再是語料來源**——退成「抓下來的原始快照」，
  只供死指標檢查與樹用。spec 076／078 的兩個場**退役**。
- **FR-006** 每個查詢過 `_own()`。

## 驗收

1. 抓一個 repo → 它的知識檔變成來源，且**全部歸在那個專案的領域底下**
2. 站在那個領域裡聊 → 只用得到它的東西（spec 079 的機制）
3. 不縮範圍 → 跨專案都在（**跨專案是免費的**）
4. ⚠️ 重抓 → 不重複增生；⚠️ 而**已刪除的檔案**要看得出來（不靜默留著）
5. 開發模式的樹讀得到，路徑照舊
6. 換 owner／persona 看不到
