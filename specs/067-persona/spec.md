# spec 067：persona——隱私的硬隔離（vision 階段 62）

## 為什麼

使用者：「很像是**開小帳**一樣，一個人有多個帳號，但**又不是真的多個帳號**」。
後來澄清：「我要的隔離**不是知識的軟隔離，而是隱私的硬隔離**」。

它跟領域的差別正是**軟／硬**：

| | 機制 | 有沒有後門 |
|---|---|---|
| **領域**（站在一個領域裡） | 軟過濾 | ✅ 有——隨時可以「在整個知識庫找」 |
| **persona** | **硬隔離** | ❌ **沒有**，不然它就不是隱私 |

⇒ 所以它不是領域的變體，是 `owner_id` 的變體。地基在 spec 063 已經做好。

## FR

- **FR-001** 五張表加 `persona_id`。⚠️ **`NULL` ＝ 共用**。
- **FR-002** **預設共用，隔離是選擇**。反過來（預設隔離）會讓場碎掉——
  而北極星第一條是「給你意外的連結」。
- **FR-003** 過濾在 `Repository(owner, persona)` 一層，跟 owner **同一個述詞**
  ⇒ 88 個查詢點自動涵蓋，不需要再改一次。
- **FR-004** ⚠️ **沒有「看全部」模式。** 有後門就不是硬隔離。
  （沒有 persona 時＝只看共用，而那時所有東西都是共用的，所以看得到全部。）
- **FR-005** 寫入預設歸**當前身分**（同「出生就歸位」：不問你，從脈絡決定）。
- **FR-006** ⚠️ **切錯身分而不自知不會報錯**——私人的東西會寫進工作的場。
  ⇒ 當前身分必須**一直看得見**，而且**整條側欄換色**（文字標籤太弱）。
  理由沿用階段 49：**你按下它之前，要先看得到它會生在哪。**

## 驗收

1. 建 persona、切換、切換後看到「共用 ＋ 當前」
2. ⚠️ 在 A 身分建的東西，切到 B 看不到；**搜尋也搜不到**（spec 066 那條路最容易漏）
3. ⚠️ 沒有任何 API 回得出「全部身分」的東西
4. 對抗：把 persona 述詞拿掉 → 隔離測試要紅
5. 實跑：切換器看得見、側欄換色、冊封時看得出會進哪個身分

## Out of scope

per-persona 設定 · 身分之間搬移 · 鎖定／密碼 · persona 的分享
