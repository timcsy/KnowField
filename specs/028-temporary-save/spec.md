# Feature Specification: 對話暫時存檔（自動、TTL 衰減）＋永久存檔（人閘門）

**Feature Branch**: `028-temporary-save`

**Created**: 2026-08-03

**Status**: Draft

**Input**: User description: "怕丟對話→暫時存檔（自動、閒置 7 天刪、便宜標題）＋永久存檔（手動、無 TTL、升永久才生落點標題）＝knowie 的 draft 層；autosave 每輪 upsert 一筆、懶清不開背景、升永久人閘門、暫存不注入回場"

## 由來

使用者「不能存檔」踩雷後怕丟東西，問「能不能自動存」。用膜頂回：**自動存全部＝打臉 spec 023「預設流走、不囤積」**（剛花 025/026 清完 19→4 複本）。使用者自己提出更好模型——**暫時存檔（自動、閒置一段時間刪）＋永久存檔（手動）**：這正是 **knowie 的 draft 層**（捕捉了、預設衰減、動它才留＝「captured ≠ committed」），而「閒置就刪」把**「預設流走」從口號變成機制**。使用者定 **TTL＝7 天**。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 聊天自動暫存，重整/切走都不會丟（Priority: P1）

使用者跟知識聊到一半，切去別的分頁、或不小心重整。回到「跟知識聊」，**剛剛那段對話還在**（自動暫存了）；他可以接著聊。整段對話只有**一筆暫存**（不是每句一筆），而且**沒有壓到他的知識庫**——它只是暫時放著。

**Why this priority**: 直接解「不見了」的恐懼（使用者剛因存不了而丟過工作）。單獨交付即消除損失。

**Independent Test**: 模擬一段對話逐輪自動暫存 → 驗證只產生**一筆**暫存（逐輪更新、非新增）；重新載入能取回；空對話不暫存。

**Acceptance Scenarios**:

1. **Given** 使用者聊了幾輪，**When** 每輪完成，**Then** 系統把整段自動存為**一筆暫存**（逐輪更新同一筆、不新增多筆）。
2. **Given** 使用者重整/離開再回來，**When** 開「跟知識聊」，**Then** 能**接回**剛剛那段暫存繼續聊。
3. **Given** 自動暫存當下失敗（外部/寫入問題），**When** 使用者繼續聊，**Then** 聊天**不被中斷**（best-effort、不崩）。
4. **Given** 一段空對話（沒有訊息），**When** 觸發暫存，**Then** **不產生**暫存。

---

### User Story 2 - 沒再碰的暫存，過 7 天自動消失（不囤積）（Priority: P1）

使用者的暫存**不會無限累積**：一段暫存如果**超過 7 天沒有再被碰**（沒新對話、沒接回），就會被**自動清除**。只要他在 7 天內又聊了/接回，計時就重來。這樣「不見了」的恐懼沒了，存檔也不會被一堆半成品閒聊塞爆。

**Why this priority**: 這是「暫時」的靈魂——**衰減**讓自動暫存不變成囤積（守住 spec 023「預設流走」）。與 US1 同為 P1（自動存＋自動流走是一體兩面）。

**Independent Test**: 餵不同 `last_activity` 的暫存清單給判準純函式 → 驗證只有閒置超過 TTL 的暫存被判過期；載入/存檔時懶清會刪掉它們；永久存檔**不受影響**。

**Acceptance Scenarios**:

1. **Given** 一筆暫存超過 7 天沒被碰，**When** 使用者開「對話存檔」或存任何東西，**Then** 該暫存被**清除**。
2. **Given** 一筆暫存 6 天沒碰、第 6 天又接回聊了一句，**When** 之後再檢查，**Then** 計時**重來**（不會在原本第 7 天被刪）。
3. **Given** 有永久存檔與過期暫存並存，**When** 懶清執行，**Then** **只刪過期暫存**，永久存檔一律保留。
4. **Given** 系統，**When** 平時運作，**Then** 清除**不靠背景排程**（只在載入/存檔時順手清）。

---

### User Story 3 - 想留的按一下升永久（人閘門）（Priority: P2）

使用者覺得某段暫存值得長期留，按「**轉永久**」（或既有「存這段對話」／冊封連同存）——那筆就**升為永久**（不再有 7 天大限），並生一個反映**落點**的正式標題。「對話存檔」頁把「**永久**」和「**暫存（會自動清除）**」**分兩區**顯示，一眼分得清哪些會消失。

**Why this priority**: 保留「人決定什麼值得長留」（原則 5 人閘門）；但自動暫存＋衰減（US1/2）已先解決損失，升永久是加值。

**Independent Test**: 對一筆暫存按升永久 → 驗證該筆變永久（無 TTL、不再被懶清刪）、生了正式標題、**不新增重複份**；`/conversations` 分兩區顯示。

**Acceptance Scenarios**:

1. **Given** 一筆暫存，**When** 使用者按「轉永久」或「存這段對話」，**Then** **同一筆**升為永久（不新增重複）、TTL 解除、標題重生為反映落點的標題。
2. **Given** 冊封根因時勾「連同這段對話存成由來」，**When** 存下，**Then** 該由來對話為**永久**（不會 7 天後消失）。
3. **Given** 「對話存檔」頁，**When** 使用者檢視，**Then** 「永久」與「暫存（會自動清除）」**分區顯示**，暫存區每筆可「轉永久」。

---

### Edge Cases

- **暫存標題**：暫存用**便宜標題**（如首句截斷），**不每輪呼 LLM**（省成本）；升永久時才生落點標題（spec 027）。
- **一段對話一筆**：同一段 live 對話逐輪更新**同一筆**暫存，不得每輪新增（否則又囤積）。
- **接回後繼續**：接回暫存續聊 → 仍是**同一筆**、更新 last_activity（重設計時）。
- **既有存檔**：spec 023 已存的對話一律視為**永久**（不會被 TTL 清）。
- **不污染**：暫存與永久一樣是**沙盒層**——**絕不注入回未來對話的場脈絡**（比照既有守衛）。
- **懶清時機**：只在載入「對話存檔」或存檔動作時清；平時不跑背景工作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在聊天每輪完成後，把整段 live 對話**自動存為一筆暫存**（逐輪**更新同一筆**、非每輪新增）。
- **FR-002**: 自動暫存 MUST 為 **best-effort**——失敗時 MUST NOT 中斷或報錯打斷聊天（教訓 3）；空對話 MUST NOT 產生暫存。
- **FR-003**: 使用者 MUST 能在重整/離開後**接回**最近一段暫存繼續聊；接回或新對話 MUST 更新其「最後活動時間」。
- **FR-004**: 暫存 MUST 在**閒置超過 7 天**（自最後活動起）後被視為過期；判斷過期的邏輯 MUST 為**純函式**（給暫存清單＋現在時間＋TTL → 過期者），離線可測。
- **FR-005**: 過期暫存 MUST 被清除，且清除 MUST **僅在載入「對話存檔」或執行存檔時懶清**——MUST NOT 依賴背景/定期排程。
- **FR-006**: 清除 MUST **只刪過期暫存**——永久存檔一律不受影響、不誤刪。
- **FR-007**: 使用者 MUST 能把一筆暫存**升為永久**（透過「轉永久」或既有「存這段對話」／冊封連同存）；升永久 MUST 是**人觸發**（原則 5）。
- **FR-008**: 升永久 MUST 對**同一筆**操作（temporary→permanent）、**不新增重複份**；升永久後 MUST 解除 TTL 且生反映**落點**的正式標題（spec 027）。
- **FR-009**: 暫存 MUST 用**便宜標題**（如首句截斷），**MUST NOT 每輪呼叫 LLM 生標題**。
- **FR-010**: 暫存與永久對話 MUST 皆為沙盒層——**MUST NOT 被注入回未來對話的場脈絡**（守衛比照 spec 023）。
- **FR-011**: 「對話存檔」頁 MUST 把「永久」與「暫存（會自動清除）」**分區顯示**。
- **FR-012**: 既有（spec 023）已存對話 MUST 一律視為**永久**（結構升級須冪等、不破既有存檔）；全繁中；TTL 判準核心零第三方相依。

### Key Entities *(include if feature involves data)*

- **對話存檔（Conversation）**：既有實體，本輪多兩個屬性——**是否暫時**（temporary / permanent）、**最後活動時間**。
- **暫存（Temporary conversation）**：自動、逐輪更新的一筆；閒置 7 天過期被清；便宜標題。＝draft/短期。
- **永久（Permanent conversation）**：人升級或人手動存；無 TTL；落點標題。＝episodes/committed。
- **TTL 判準（純值）**：`(暫存清單, 現在, TTL天數) → 過期 ids`，不落庫。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 聊天每輪後 live 對話自動存為**一筆**暫存（逐輪更新、非新增）；重整/離開後可接回；autosave 失敗不中斷聊天；空對話不暫存。
- **SC-002**: 閒置 >7 天的暫存會被清；7 天內又碰過的**不被清**（計時重設）；判準為純函式、離線可測；清除**不靠背景排程**。
- **SC-003**: 懶清**只刪過期暫存**，永久存檔零誤刪。
- **SC-004**: 人可把暫存**升永久**（同一筆、不重複）、解除 TTL、生落點標題；冊封連同存的由來為永久。
- **SC-005**: 暫存不注入回場（守衛測）；升永久為人閘門（原則 5）。
- **SC-006**: 「對話存檔」分「永久／暫存」兩區；既有存檔升級為永久（冪等、不破）；全繁中；核心零相依；**現有 441 測試不回歸**＋新增涵蓋 upsert、TTL 判準、升永久、守衛的測試。

## Assumptions

- **TTL＝7 天**（使用者定；以「最後活動時間」起算）。
- 自動暫存在**每輪對話完成後**觸發（一段 live 對話對應一筆，藉識別碼逐輪更新）。
- 暫存便宜標題以首句截斷等非 LLM 方式；落點標題沿用 spec 027（升永久時生）。
- 沿用既有 `conversations`（加屬性）、`/chat`、`/conversations`、既有「存這段對話」／冊封連同存與不注入回場的守衛。

## Out of Scope（明確排除，防蔓延）

- **背景/定期清理排程**（只在載入/存檔時懶清）。
- 暫存也**自動生 LLM 標題**（貴、每輪呼；改升永久才生，暫存用便宜標題）。
- 跨對話關聯、對話全文搜尋、章節切分（階段 22）。
- CLI。
