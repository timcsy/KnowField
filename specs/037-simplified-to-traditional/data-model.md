# Phase 1 資料模型

## 不新增任何資料表、不新增任何欄位

本功能**只讀不寫**。FR-004 要求儲存層逐字保留，因此資料模型的正確答案是「沒有變更」。
下面描述的是**記憶體中的中介型別**，不落地。

## 中介型別

### ProtectedText（承重保護後的中介狀態）

| 欄位 | 型別 | 說明 |
|---|---|---|
| `masked` | `str` | 承重片段已被佔位符取代的文字。這是唯一送進轉換引擎的東西。 |
| `segments` | `list[str]` | 被抽出的承重片段，依出現順序。索引即佔位符編號。 |

**不變式**：
- `restore(mask(t)) == t` 對任意輸入成立（往返無損）。這是最重要的一條，必須有測試。
- `masked` 不得包含任何會被 `s2twp` 轉換的字元 → 佔位符使用純 ASCII。
- `len(segments)` 與 `masked` 中的佔位符數量相等。

### 承重片段的類別與抽取順序

順序有意義：**塊級先抽，行內後抽**。反序會破壞配對（fenced 內部的行內語法被先抽走）。

| 順序 | 類別 | 形態 |
|---|---|---|
| 1 | 圍欄程式碼區塊 | ` ```…``` `、`~~~…~~~` |
| 2 | 數學區塊 | `$$…$$`、`\[…\]` |
| 3 | 圖片 | `![alt](url)` — ⚠️ **整段抽**，alt 也不轉（alt 常是檔名的一部分或與 url 對應） |
| 4 | 連結 | `[text](url)` — ⚠️ 只抽 `(url)` 部分，`text` 是給人讀的**要轉** |
| 5 | 行內程式碼 | `` `…` `` |
| 6 | 行內數學 | `$…$`、`\(…\)` |
| 7 | 裸 URL | `https?://…` |

⚠️ 第 3、4 兩條的處理**不同**，這是實測逼出來的：
- 圖片的 alt（`深入解析Flow Matching技术`）雖然是人讀的，但實測中它與 URL 一起被改；
  且圖片 alt 極少需要閱讀，整段抽最安全。
- 連結的 `text` 是正文的一部分（讀者真的在讀它），轉了才有價值 → 只保護 URL。

## 既有實體（唯讀，不變更）

- **來源內容**：塊文存於 `digest_entries.article_body`，經 `get_source_chunks(url)` 依序取出、
  `stitch_chunks` 拼回。本功能在拼回**之後**作用，不觸碰上述任何一環。

## 狀態轉移

無。本功能是無狀態的純函式管線：

```
儲存的原文 ──(既有讀取路徑)──> 完整 markdown
                                    │
                          ┌─────────┴─────────┐
                          │                   │
                    raw=1 │                   │ 預設
                          ▼                   ▼
                       原樣回傳          mask → s2twp → restore → 回傳
```
