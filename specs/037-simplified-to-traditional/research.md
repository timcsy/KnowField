# Phase 0 研究：來源簡體正規化（顯示層）

所有結論皆為**實測**，非查文件推論。指令可重跑覆核。

## 決策 1：轉換引擎用 `opencc-python-reimplemented`，設定檔 `s2twp`

- **決策**：純 Python 的 `opencc-python-reimplemented`，設定 `s2twp`（Simplified → Traditional Taiwan **with phrases**）。
- **理由（實測）**：

  ```
  簡體詞彙  变 | 这个软件的内存管理很复杂，程序员需要学习。
               → 這個軟體的記憶體管理很複雜，程式設計師需要學習。
  繁體原樣  同 | 逐字不變
  英文     同 | 逐字不變
  一對多   变 | 头发很长，发展很快。→ 頭髮很長，發展很快。（分對了）
  全形標點  同 | 「引號」、全形（括號）…… 不變
  ```

  ⇒ FR-002（詞彙在地化）、FR-008（非簡體逐字不變）、一對多映射、標點四項一次全滿足。
  安裝耗時 5ms、無 C 相依 → 不違反憲章 IV（YAGNI）也不製造安裝負擔。

- **否決的替代方案**：
  - **`OpenCC`（原生綁定）**：需要 C 函式庫，跨平台安裝負擔高，與此庫「預設零安裝可跑」的既有做法牴觸。
  - **LLM 做簡→繁**：設計源已列入「考慮過但不採」——有確定性解時用辨識，違反 experience「解析 > 辨識」；且會順手改寫原文。
  - **自建字表**：詞彙層（軟件→軟體）需要數萬條詞庫，自建是重造輪子且必然更差。

## 決策 2：佔位保護是**必要條件**，不是防禦性加碼

- **決策**：轉換前先把承重片段抽成佔位符，轉換後塞回。
- **理由（實測，六個危險案例**全部**被破壞）**：

  | 案例 | 前 | 後 | 後果 |
  |---|---|---|---|
  | 程式碼 | `def 处理(内存):` | `def 處理(記憶體):` | **識別字被改，程式不能跑** |
  | URL | `http://a.cn/发展/index.html` | `…/發展/…` | **404** |
  | 圖片 | `pic1.zhimg.com/发展_v2.jpg` | `…發展_v2.jpg` | **破圖** |
  | 行內數學 | `$x_{发}$` | `$x_{發}$` | 下標標籤被改 |
  | 數學塊 | `$$…\text{发展}$$` | `\text{發展}` | 公式內容被改 |
  | 行內 code | `` `发送` `` | `` `傳送` `` | 識別字被改 |

  ⇒ 這正是 [`history/081`](../../knowledge/history/081-來源進料品質-arxiv路線與數學圖標題.md) 警告的形態，
  而且**實測成立**。沒有佔位保護，本功能的淨值為負。

  註：純 ASCII 的 `os.path.dirname` 未被動——**風險只在含 CJK 的承重片段**，但那正是簡體來源最常見的情況。

- **技法前例**：commit `9c3352e`（中文粗體 `**…**` 抽佔位繞過 marked flanking）；
  `ingest/convert.py:26` 也用同一招把 OCR 圖片內嵌回正文。**此庫已有兩個同型前例，不是新機制。**

- **保護順序（重要）**：先抽**塊級**（```fenced```、`$$…$$`），再抽**行內**（`` ` ` ``、`$…$`、
  圖片 `![](…)`、連結 `[](…)`、裸 URL）。反過來會把 fenced 內部的行內語法先抽走、破壞配對。

- **佔位符字元集**：必須是 OpenCC **不會轉換**的字元（純 ASCII + 數字），且極不可能出現在原文。
  驗收要包含「佔位符本身不被轉換」這條。

## 決策 3：可插拔 + 確定性 fallback

- **決策**：轉換走一個薄介面；引擎不可用時回傳原文（identity）。
- **理由**：experience「把重量級相依藏在可插拔介面後，預設離線 stub」——原文為
  「MVP 預設用確定性、零相依的 `HashingEmbedder`／`StubSummarizer`；真實後端作為可選 extras 插拔」。
  同一形狀套用：**沒裝 OpenCC 不該讓測試跑不動**（FR-007、SC-005）。
- **否決**：硬性相依。會讓「跑第一個測試前必須先裝套件」，牴觸憲章 I 的 TDD 節奏。

## 決策 4：套用點在拼回之後、回傳之前

- **決策**：在來源詳情頁的讀取路徑上，內容拼回成完整 markdown 之後、回應送出之前套用。
- **理由**：塊是儲存單位不是語意單位，逐塊轉換會讓跨塊的承重片段（例如被切開的 fenced block）
  抽佔位時配對失敗。拼回後是完整文件，配對才可靠。
- **牴觸檢查**：不寫回儲存 → FR-004（逐字保留）自動成立。
