# 功能規格：領域管理頁與導航列歸位（階段 49）

**Feature Branch**: `main` · **Created**: 2026-08-26 · **Status**: Draft

**知識庫來源**：vision 階段 49

---

## ⚠️ 上一刀把兩件事塞進同一個入口

階段 48 的「領域」入口同時做**導覽**（往上／同層／子領域）與**管理**（新增）。
使用者把它們分開：

| | 是什麼 | 在哪 |
|---|---|---|
| **導航列** | 一直看得到的**位置指示** | 側欄頂端（Logo 下、＋新對話上） |
| **領域** | 點進去**管理**的地方 | 一頁（`/domains`） |

⇒ 導航列在「＋新對話」**之上**是有理由的：**你按下它之前，要先看得到它會生在哪。**

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 導航列歸位 (Priority: P1)

1. **Given** 側欄，**Then** 順序是 Logo → **導航列** → ＋新對話 → 五個入口。
2. **When** 點導航列任一段，**Then** 站到它（history push）。
3. **When** 展開某段的 `▾`，**Then** 看到同層的兄弟，點了就跳過去。

### User Story 2 - 領域點進去就是管理頁 (Priority: P1)

1. **When** 點側欄「🗂 領域」，**Then** 到 `/domains`，且**保留當前領域**。
2. **Given** 管理頁，**Then** 可以**新增**子領域、**改名**、**刪除**、**搬動**。

### User Story 3 - 刪領域不刪知識 (Priority: P1)

1. **Given** 一個底下有 3 件知識、2 個子領域的領域，**When** 刪掉它，
   **Then** 那 3 件知識與 2 個子領域**上移到它的父領域**，一件都不少。
2. **Given** 一個最上層領域，**When** 刪掉它，**Then** 內容與子領域回到**根領域**。
3. **When** 刪除前，**Then** 系統**說出**會影響幾件、往哪裡搬。
4. **Given** 當前站在被刪的領域，**When** 刪掉，**Then** 站到它的父領域（⚠️ 不能站在不存在的地方）。

## Requirements *(mandatory)*

- **FR-001** 導航列 MUST 在側欄 Logo 之下、「＋新對話」之上。
- **FR-002** 「領域」入口 MUST 連到管理頁，MUST NOT 在側欄就地展開管理。
- **FR-003** 管理頁 MUST 支援 新增／改名／刪除／搬動。
- **FR-004** ⚠️ 刪除領域 MUST NOT 刪掉任何知識，也 MUST NOT 刪掉子領域。
  內容與直屬子領域 MUST **上移到父領域**（父為空＝根領域）。
- **FR-005** 刪除前 MUST 說出影響範圍（幾件知識、幾個子領域、往哪裡搬）。
- **FR-006** 刪掉當前所在領域後，MUST 把使用者移到它的**父領域**。
- **FR-007** 底部重複的「整理台」入口 MUST 移除——同一件事不留兩個入口。

## Out of Scope

- 領域的顏色／圖示 · 拖曳排序 · 回收桶／復原 · 合併兩個領域
