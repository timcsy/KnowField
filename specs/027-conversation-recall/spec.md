# Feature Specification: 對話的可找回性——落點重命名＋章節切分

**Feature Branch**: `027-conversation-recall`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "長對話標題凍在第一句、最原創的落點被埋、半年找不回——US1 落點重命名（自動更準＋手動改名＋既有可重生）、US2 章節切分（有小標的可跳讀大綱、on-demand 不落庫）、US3 每章單獨匯出/整理"

## 由來

真實使用審計的第三個漏：長對話**標題凍在第一句**——`knowfield.db` 19 份對話幾乎全叫「Flow Matching」，但最原創的落點（四元樹多尺度、影片串流，第 33–70 句）被埋，**半年後找不回**。具體成因已定位：自動標題**只看對話開頭**，所以標題永遠反映開頭主題、不反映對話**最後聊到哪／整體是什麼**。

本規格解「找不回」：**US1 重命名**（真正的修）＋**US2 章節切分**（把長對話拆成可跳讀的小節）＋**US3 每章動作**。**MVP＝US1**。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 對話標題反映「落點/全貌」，且能自己改名（Priority: P1）

使用者存下一段從「Flow Matching」一路聊到「四元樹×影片串流」的長對話。自動標題應反映它**最後聊到／整體在講什麼**（落點/全貌），而不是只抓開頭。若自動標題還是不合意，使用者可以**自己改名**；既有那些叫「Flow Matching」的舊對話，也能**重新命名**（重跑更準的自動標題，或手動輸入）。

**Why this priority**: 這是「找不回」的**直接修**——標題是清單上唯一的辨識線索。單獨交付即解決核心痛點（半年後找得回那條四元樹想法）。

**Independent Test**: 餵一段「開頭 A、落點 B」的對話給自動標題（注入替身）→ 驗證標題反映 B（非只 A）；對既有對話呼叫改名／重生 → 標題更新；標題生成失敗 → 退回不崩。

**Acceptance Scenarios**:

1. **Given** 一段開頭談 A、最後落在 B 的長對話，**When** 系統自動生標題，**Then** 標題反映**落點/全貌 B**（不只是開頭 A）。
2. **Given** 「對話存檔」清單，**When** 使用者對某則輸入新名稱送出，**Then** 該對話標題更新為使用者輸入。
3. **Given** 一則舊的「開頭主題」標題對話，**When** 使用者按「重新命名」，**Then** 系統重生一個反映落點/全貌的標題（或讓使用者手動輸入）。
4. **Given** 標題生成（外部）失敗，**When** 存檔或重生，**Then** 退回合理標題（如首句截斷）、**不崩**；且**不會自動改動**既有標題（人按才改）。

---

### User Story 2 - 把一段長對話切成可跳讀的章節（Priority: P2）

使用者打開一段 70 句的長對話，想快速看它**走過哪些階段**、跳到某一段，而不必從頭讀。他按「整理成章節」，系統把對話切成幾個**章節**：每章有**小標＋起訖範圍（第 N–M 句）＋一句摘要**，列成大綱；點某章可**跳到**該段訊息。

**Why this priority**: 長對話（productive drift）常裝好幾個探究；章節讓「找到那一段」變快。次於 US1（標題是清單層的辨識，章節是單篇內的導航）。

**Independent Test**: 餵一段多主題對話給切分器（注入替身回確定性章節）→ 驗證回傳章節有小標/範圍/摘要、範圍涵蓋且不重疊；切分失敗 → 退回「整段為一章」、不崩。

**Acceptance Scenarios**:

1. **Given** 一段跨多主題的長對話，**When** 使用者按「整理成章節」，**Then** 顯示章節大綱（每章小標＋第 N–M 句＋一句摘要）。
2. **Given** 章節大綱，**When** 使用者點某一章，**Then** 頁面**跳到**該章起始訊息。
3. **Given** 切分（外部）失敗或對話太短，**When** 使用者按「整理成章節」，**Then** 友善退回（如「整段為一章」或提示太短），**不崩**。
4. **Given** 一段對話，**When** 章節被算出，**Then** 章節**不寫入資料庫**（每次為即時檢視、可重算）。

---

### User Story 3 - 每一章可單獨匯出／整理成重點（Priority: P3）

看完章節大綱，使用者想把**其中一章**（例如「四元樹×影片串流」那章）帶去 NotebookLM，或把那章**收成一條根因**。每章旁有「複製 Markdown／佐證網址」（只含該章範圍）與「整理這章成重點」（把該章交給整理→冊封流，人按才存）。

**Why this priority**: 讓章節不只是導航、能直接**行動**（匯出/收料）；但屬加值，次於能切出章節本身。

**Independent Test**: 對某章範圍呼叫匯出 → 得到只含該章的 Markdown/網址；對某章按「整理成重點」→ 走既有整理→冊封流（人閘門）。

**Acceptance Scenarios**:

1. **Given** 一份切好章節的對話，**When** 使用者對某章按「複製 Markdown」，**Then** 剪貼簿只含**該章範圍**的內容（複用既有匯出）。
2. **Given** 同上，**When** 使用者對某章按「整理這章成重點」，**Then** 系統就**該章訊息**整理出候選、由使用者決定是否冊封（不自動冊封）。

---

### Edge Cases

- **短對話**：太短（如 ≤ 1–2 輪）→ 不切章節（或整段一章）；自動標題正常。
- **標題/切分外部失敗**：退回（標題退首句、切分退整段），友善繁中、不崩（教訓 3）。
- **落點與開頭相同**（單一主題對話）：標題自然就是該主題；章節可能只有一章——皆合理。
- **章節範圍**：各章範圍**涵蓋全對話且不重疊**（不漏訊息、不重覆）。
- **人閘門**：改名／重生／切分／每章冊封**都需人按**；系統不自動改既有標題、不自動切分、不自動冊封。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 自動對話標題 MUST 反映對話的**落點/全貌**（涵蓋結尾，而非只看開頭）；長對話標題 MUST NOT 只由開頭決定。
- **FR-002**: 使用者 MUST 能在「對話存檔」對任一對話**手動改名**（輸入新標題並保存）。
- **FR-003**: 使用者 MUST 能對既有對話觸發**重新命名**（重生更準的自動標題，或改為手動輸入）。
- **FR-004**: 標題生成 MUST 可注入替身、離線可測；外部失敗時 MUST 退回合理標題（如首句截斷）、**不崩**。
- **FR-005**: 系統 MUST 不**自動**改動既有標題——改名／重生皆需**人觸發**（原則 5）。
- **FR-006**: 使用者 MUST 能對一段對話觸發**切成章節**，每章含**小標＋起訖範圍（第 N–M 句）＋一句摘要**。
- **FR-007**: 章節範圍 MUST **涵蓋全對話且不重疊**；章節大綱 MUST 可**跳到**對應訊息。
- **FR-008**: 切分器 MUST 可注入替身、離線可測；切分失敗或對話過短時 MUST 友善退回（整段一章／提示）、不崩。
- **FR-009**: 章節 MUST **不寫入資料庫**（on-demand 計算、可重算）；本功能 MUST NOT 新增資料表。
- **FR-010**: 使用者 MUST 能對**單一章節**匯出 Markdown／佐證網址（只含該章範圍，複用既有匯出）。
- **FR-011**: 使用者 MUST 能對**單一章節**觸發「整理成重點」（就該章訊息走整理→冊封流），且**不自動冊封**（人決定，原則 5）。
- **FR-012**: 全繁中；核心（標題取材、切分結果處理、範圍切片）零第三方相依；重命名只更動既有標題欄、不新增結構。

### Key Entities *(include if feature involves data)*

- **對話存檔（Conversation）**：既有實體。US1 更動其**標題**（自動更準／手動改名／重生）。
- **章節（Chapter）**：**衍生值、不落庫**——`{小標, 起訖範圍, 一句摘要}`；由切分器就對話訊息算出，供檢視／跳讀／每章動作。
- **章節切片**：某章的訊息子序列（依起訖範圍）——供每章匯出（spec 024）與「整理成重點」（distill）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 開頭 A、落點 B 的對話 → 自動標題反映 B（非只 A）；使用者可手動改名；既有對話可重生標題。
- **SC-002**: 標題生成可注入替身、離線可測；外部失敗退回不崩；不自動改既有標題。
- **SC-003**: 一段對話可切成有**小標＋範圍＋摘要**的章節、可跳讀；範圍涵蓋全對話且不重疊。
- **SC-004**: 切分器可注入、離線可測；失敗／過短友善退回；章節**不落庫**（可重算）。
- **SC-005**: 每章可單獨匯出 Markdown／網址（只含該章）；可就該章「整理成重點」（人閘門、不自動冊封）。
- **SC-006**: 全繁中；核心零相依；不自動改名／切分／冊封（原則 5）；**現有 423 測試不回歸**＋新增涵蓋標題取材、切分處理、每章切片的測試。

## Assumptions

- 「落點/全貌」以**涵蓋對話結尾**的取材（如首尾並取、或尾段為主）＋提示達成；具體取材於實作定、封裝可測。
- 章節切分為**語意判斷**，交由可注入的後端（離線 stub 回確定性章節）；本規格不綁特定演算法。
- 每章匯出複用 spec 024 的匯出（加起訖範圍切片）；「整理成重點」複用既有整理→冊封流。
- 沿用既有 `conversations` 表（僅更動 title 欄）、`/conversations`、`/conversations/{id}`。

## Out of Scope（明確排除，防蔓延）

- 存檔時就**自動**切分／自動命名（只人手動觸發）。
- 章節**落庫／版本控制**（on-demand 計算、不存）。
- 跨對話關聯、對話全文搜尋。
- CLI。
