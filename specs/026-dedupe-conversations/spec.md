# Feature Specification: 既有重複對話清理（一次性、非破壞、人確認）

**Feature Branch**: `026-dedupe-conversations`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "在 /conversations 提供『清理重複對話』——先 dry-run 預覽（N 組重複、M 份多餘、K 條根因將重指）、人確認才執行（同指紋只留最新一份、根因重指、刪其餘）；只併內容完全相同者、非破壞"

## 由來

spec 025（階段 20）修了「以後不再複製」，但 `knowfield.db` 仍留著**既存複本**——15 份同 32 句的 Flow Matching 對話（每份連一條根因）＋Transformer 那組等，全是真實使用審計照出的囤積。使用者 2026-07-30 定案：把既有複本也清掉。

刪除不可逆，故本功能**兩段式、人閘門**（原則 5）、**只併內容完全相同者**（非破壞）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 預覽有多少重複可清（不動任何資料）（Priority: P1）

使用者在「對話存檔」頁想知道有多少重複可以清。他按「清理重複對話」，系統先給一份**預覽**：發現幾組重複、共有幾份多餘、有幾條根因的「由來」會被重指到留存那份——但**此時什麼都還沒改**。使用者看清楚要發生什麼，才決定要不要執行。

**Why this priority**: 刪除不可逆，預覽是安全前提；使用者必須先看見「將發生什麼」才可能安心確認。單獨交付預覽即有價值（讓使用者掌握囤積現況）。

**Independent Test**: 種入數組同內容＋若干不同內容的對話 → 呼叫預覽 → 驗證回報的「組數／多餘份數／將重指根因數」正確，且資料**完全未變**（對話數、根因連結不動）。

**Acceptance Scenarios**:

1. **Given** 庫中有 3 組重複（每組數份同內容）與若干不重複對話，**When** 使用者按「清理重複對話」，**Then** 顯示預覽「發現 3 組重複、共 M 份多餘、K 條根因將重指」，且**未刪除、未重指任何東西**。
2. **Given** 庫中沒有任何重複，**When** 使用者按「清理重複對話」，**Then** 顯示「沒有重複可清」，不報錯、不動資料。

---

### User Story 2 - 確認後執行清理（同內容併成一份、根因重指、非破壞）（Priority: P1）

看過預覽後，使用者按「確認清理」。系統把**每組內容完全相同**的對話**併成一份**（留最新一份），把所有原本指向該組任一份的根因「由來」**重指到留存那份**，刪掉其餘多餘份。內容不同的對話（即使相關，如同一串聊天的不同長度）**完全不動**。清理後每條根因的「← 由來」仍連得到（指向留存份）。

**Why this priority**: 這是清理的實際價值——把囤積的複本收乾淨。與 US1 同為 P1（預覽＋執行是一個完整動作的兩段）。

**Independent Test**: 種入同內容多份（各連不同根因）＋不同內容數份 → 執行 → 驗證每組只剩一份（最新）、原指向舊份的根因全部重指到留存份、不同內容份數不變、根因主張未改。

**Acceptance Scenarios**:

1. **Given** 一組 15 份內容完全相同的對話、各連一條根因，**When** 使用者確認清理，**Then** 該組只剩**1 份**（最新）、那 15 條根因的「由來」皆重指到它、其餘 14 份被刪。
2. **Given** 兩份**內容不同**但相關的對話（如同串聊天的 65 句版與 70 句版），**When** 確認清理，**Then** 兩份**都保留**（不因相關而被併）。
3. **Given** 清理完成，**When** 使用者到「根因」頁，**Then** 每條原本有「← 由來」的根因**仍連得到**（指向留存份），連結不斷。
4. **Given** 清理完成，**When** 檢視任何根因，**Then** 其**主張／階梯內容未被更動**（清理只動「由來」連結與多餘對話份）。

---

### Edge Cases

- **空庫／無重複**：回「沒有重複可清」，不動資料、不報錯。
- **一組中有份未連任何根因**：仍併入該組（留最新份）；無根因需重指者略過重指、只刪多餘份。
- **留存份本身連著根因**：留最新份；其既有根因連結保留、其餘份的根因併過來。
- **預覽與執行之間資料改變**（理論上單人本機少見）：執行時以當下實際內容重新計畫，仍只併同指紋。
- **不同內容絕不併**：即使標題相同、長度接近，只要內容指紋不同就分開保留（非破壞第一原則）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在「對話存檔」頁提供「清理重複對話」動作，且**先預覽、後執行**兩段式。
- **FR-002**: 預覽 MUST 回報「重複組數、多餘份數、將重指的根因數」，且**不修改任何資料**（不刪、不重指）。
- **FR-003**: 清理 MUST 只在**內容完全相同**（同內容指紋）的對話間進行；內容不同者（即使相關）MUST **完全不動**。
- **FR-004**: 每組重複 MUST 只留**一份**（規則：最新的一份）；其餘份 MUST 被刪除。
- **FR-005**: 所有原本指向該組**任一份**的根因「由來」連結 MUST 被**重指到留存那份**；清理後每條原有由來的根因 MUST 仍連得到（`/roots`「← 由來」不斷）。
- **FR-006**: 清理 MUST **只更動「由來」連結與多餘對話份**——**不得更改任何根因的主張／階梯內容**。
- **FR-007**: 執行 MUST 需**人明確確認**（原則 5，刪除不可逆）；系統 MUST NOT 自動、定期或在背景清理。
- **FR-008**: 「分組／選留存／產生重指計畫」的邏輯 MUST 為**純函式**（給對話清單＋根因連結 → 回留存 id、待刪 ids、根因重指對應），離線可測、對空／無重複不崩。
- **FR-009**: 空庫或無重複時 MUST 友善回報「沒有重複可清」、不報錯、不動資料。
- **FR-010**: 全繁中；核心計畫邏輯零第三方相依；不新增資料表或欄位（用既有結構）。

### Key Entities *(include if feature involves data)*

- **對話存檔（Conversation）**：既有實體。清理的對象——同內容多份併為一份。
- **內容指紋**：既有純函式（spec 025）判「內容完全相同」；清理的分組依據。
- **根因（Why node）由來連結**：既有 `根因 → 對話` 連結。清理時**重指**（改指留存份），根因主張不動。
- **清理計畫（純值）**：`{每組: 留存 id, 待刪 ids, 根因重指 old→new}`——由對話清單＋連結算出、**預覽時不落地**。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 預覽正確回報「組數／多餘份數／將重指根因數」，且執行前資料**零變動**。
- **SC-002**: 確認執行後，每組同內容對話只剩**1 份**（最新）；多餘份全數刪除。
- **SC-003**: 原本指向被刪份的根因**全部重指到留存份**；清理後每條原有由來的根因「← 由來」**仍連得到**。
- **SC-004**: 內容不同的對話（含相關但非相同者）**份數不變**；任何根因的**主張／階梯內容未被更動**。
- **SC-005**: 分組／計畫邏輯為純函式、離線可測；空庫／無重複友善不崩。
- **SC-006**: 執行需人確認（無自動／背景清理）；全繁中；核心零相依；**現有 414 測試不回歸**＋新增涵蓋計畫與執行的測試。

## Assumptions

- 「內容完全相同」以既有內容指紋（spec 025 `conversation_fingerprint`）判定，忽略標題等易變欄——同指紋即視為可併。
- 「留最新一份」以建立序（id 最大）為準；留存份保留其標題與既有根因連結。
- 本功能為**一次性維護動作**（使用者手動觸發）；不改變 spec 023／025 既有的存檔與去重行為。
- 沿用既有 `conversations`、`why_nodes.conversation_id`、`why_node_provenance`、`/conversations` 頁。

## Out of Scope（明確排除，防蔓延）

- 併「內容不同但相關」的對話（如同串聊天的 65 句／70 句版）——只併完全相同。
- 自動／定期／背景清理（只人手動觸發一次）。
- #3：標題凍住／章節切分／落點重命名（另議）。
- 對話全文搜尋、跨對話關聯。
- CLI。
