# spec 073：場自己算跨 base 群——讓抓進來的知識走進收件匣（階段 68 第二刀）

## 為什麼

spec 072 把別的專案的 `knowledge/` 抓進場了。正式庫現在有 **3 個 base、514 個知識檔**。
⚠️ **而它們被任何東西消費**——`_SEARCH` 不含外部知識，收件匣的 `origin like 'from:%'` 是 **0**。

那正是 spec 062 FR-005 那條的重演：**寫進去了、清單看得到、但不在你的場裡**。

⇒ 這一刀把 `knowie-crosscheck` 的**運算**搬進 `src/`，讓場自己算出跨 base 群、
落進**既有的收件匣**（spec 071），由人逐條冊封。

## 形狀：吃資料，不吃路徑

```python
group(bases: dict[str, list[str]], ...)   # {"VizGPT": ["判準一", ...], ...}
```

⚠️ 不吃目錄路徑 ⇒ 教訓從**磁碟**、從 **clone**、還是從 **`ext_items`** 來，這支都不在乎。
skill 那版寫死在磁碟上，這次不要重複那個。

## FR

- **FR-001** `src/knowfield/organize/crossbase.py`：`_clean` · 抽教訓 · 分群 · 校驗，
  全部**吃資料**。`knowledge/skills/knowie-crosscheck/` 改成呼叫它，**不再自己實作一份**。
- **FR-002** 抽教訓涵蓋 **experience 的 `###`** ＋ **concepts 的檔名**
  （概念名就是主張；根公理 1「一個概念，多個投影」⇒ 概念層撞到比教訓層強）。
- **FR-003** ⚠️ **帶 `⚠️ 借來的` 標記的不算獨立撞到**——否則計數餵回推薦、推薦餵回計數（馬太）。
- **FR-004** ⚠️ **沒有校驗配對就不給群**——結構性禁令，不是提醒。
  一個沒校驗的門檻會給你一個看起來很專業的錯結論（0.78 ⇒「幾乎沒有複利」）。
- **FR-005** 門檻**兩邊都量**：校驗配對給**上界**、最大群的大小給**下界**（連通分量會傳遞性串連）。
  兩個數字都要回給呼叫端。
- **FR-006** 群落進**既有收件匣**（`import_borrowed`，`origin='from:<bases>'`）。
  ⚠️ **不繞過那道閘門**——原則 6：只有沉澱物入場，守門在膜上。
- **FR-007** 上限（預設 15）。⚠️ 群是**報**不是**擋** ⇒ 要精確：不把全部倒進收件匣。
- **FR-008** 向量落庫、可重用；重抓那個 base 就作廢。
- **FR-009** 背景執行、狀態可輪詢（沿用 spec 072 的模式，**不引入工作佇列**）。
- **FR-010** 每個查詢過 `_own()`；新表帶 `owner_id`＋`persona_id`。

## 驗收

1. 正式庫（3 個 base）跑得出群 → 收件匣 `origin like 'from:%'` 從 **0 變正數**
2. 群數與本機 `knowie-crosscheck` 同門檻下**同一個數量級**（已知答案校驗）
3. ⚠️ 把一條教訓加上借來標記 → 它**不再**被算成那個 base 獨立撞到
4. ⚠️ 不給校驗配對 → **拒絕給群**（而不是給一個預設門檻）
5. 回傳同時帶**噪音上緣**與**最大群大小**（兩個界）
6. 收件匣裡每條看得出跨哪幾個 base ＋ 各自原文（沿用 spec 071 的畫面）
7. 換 owner／persona 看不到
8. skill 的 16 條測試**改 import 之後全綠**（搬家沒弄丟判準）

## Out of scope

RAG 消化 · `knowie-pull` 移駕 knowie · 機器憑證 ·
⚠️ **讓 `ext_items` 進搜尋／檢索語料**——「外來的東西算不算你的場」是**另一個決定**，不順手做掉。
