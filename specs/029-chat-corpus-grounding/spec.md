# Feature Specification: 問答併進聊天——聊天 ground 在核心理解＋收進的文章＋web

**Feature Branch**: `029-chat-corpus-grounding`

**Created**: 2026-08-03

**Status**: Draft

**Input**: User description: "讓聊天每輪也檢索相關的收進文章/論文、當『你收藏的』證言餵進場脈絡（帶膜、附引用、比核心理解軟、絕不當地基）；併掉 /ask、導覽問答退場"

## 由來

產品轉向後，`問答`（對收進的文章/論文發問）和 `聊天`（從**精選的核心理解**＋每輪 **web** 撒網推理，帶反逢迎的膜）是**兩條路**。使用者定案**合併**——讓聊天**每輪也檢索相關的收進文章/論文**、當**證言**餵進場脈絡。

＝**在你自己內容上、帶反逢迎膜的 NotebookLM**：聊天同時 ground 在「你精選的核心理解（地基）＋你收進的文章（證言）＋web（外部）」，而且膜**分層**——收進的資料是**別人的證言**，比你的核心理解軟，**引用它、但絕不當地基**。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 聊天會引用我收進的文章／論文（Priority: P1）

使用者收進過一些文章/論文，然後在「跟知識聊」問一個相關問題。除了從他精選的核心理解與 web 找料，聊天**也把他收進的相關文章找出來**、放進這輪的參考，答案**引用得到**（附 `[n]`、標明「你收藏的」，跟 web 來源分得清）。他不必再切去「問答」頁。

**Why this priority**: 這是合併的核心價值——聊天終於能用上**使用者自己蒐集的內容**，不只根因＋web。單獨交付即把「對收進內容發問」的能力搬進聊天。

**Independent Test**: 種入幾則收進條目，注入替身檢索 → 問一個相關問題 → 驗證答案的來源清單含該收進條目（附 `[n]`、標「你收藏的」）；無關問題／無收進內容 → 不硬塞。

**Acceptance Scenarios**:

1. **Given** 使用者收進過相關文章、且在聊天問相關問題，**When** 送出，**Then** 該輪參考含**相關的收進條目**、答案可引用（`[n]`、標「你收藏的」）。
2. **Given** 收進的與問題無關，**When** 送出，**Then** 不把不相關的收進條目塞進來（門檻過濾）。
3. **Given** 使用者**沒有收進任何東西**，**When** 送出，**Then** 退回現況（只用核心理解＋web），不報錯。

---

### User Story 2 - 膜把「收進的資料」當證言、不當地基（Priority: P1）

聊天引用收進的文章時，膜清楚**分層**：使用者**精選的核心理解**是**地基**（從它往下推、當自己的理解）；**收進的文章**是**外部證言**（引用、「你收的資料說…」，比核心理解軟，可能有錯、可能是別人觀點）。收進的內容**絕不會被當成使用者的地基**、**絕不自動變成核心理解**。

**Why this priority**: 這是純度守門（原則 6）——收進的是**別人的內容**，若被當成「你的理解」灌回場，就是污染。與 US1 同為 P1（引用得靠這條把關才安全）。

**Independent Test**: 存一條含特定字串的收進內容 → 之後聊天的**場脈絡地基（system prompt）不含它**（只含冊封的核心理解）；答案裡它以「你收藏的」證言出現、不被當核心理解。

**Acceptance Scenarios**:

1. **Given** 一則收進內容含 `SECRET_外部觀點`，**When** 之後聊天，**Then** 場脈絡的**地基**（核心理解 system prompt）**不含**它——它只以**引用證言**出現（原則 6 守衛）。
2. **Given** 聊天引用了收進的文章，**When** 檢視，**Then** 收進內容**沒有自動變成核心理解**（`/核心理解` 頁不因此新增）。
3. **Given** 收進資料與核心理解相衝，**When** 聊天，**Then** 膜以**核心理解為地基**、把收進資料標為「你收的資料說（但…）」，不讓證言蓋過地基。

---

### User Story 3 - 「問答」併入聊天、退場（Priority: P2）

既有的獨立「問答」頁（對收進內容發問）功能已在聊天裡，導覽的「問答」**退場**（或導向聊天）。使用者只有一個對話入口。

**Why this priority**: 收斂表面、少一個入口（延續砍鷹架的「一個對話入口」）；但 US1/2 先把能力搬過去才談退場。

**Independent Test**: 導覽不再有獨立「問答」；舊 `/ask` 路徑導向聊天（或退場），不 500。

**Acceptance Scenarios**:

1. **Given** 導覽列，**When** 使用者看，**Then** 沒有獨立「問答」入口（能力在「跟知識聊」）。
2. **Given** 舊的問答網址，**When** 造訪，**Then** 導向聊天、不報錯。

---

### Edge Cases

- **沒收進任何東西**：檢索回空 → 聊天照跑（只核心理解＋web），不報錯、不硬塞。
- **檢索失敗**（服務/金鑰）：best-effort → 該輪略過收進檢索、聊天不中斷（比照 web 撒網失敗，教訓 3）。
- **腦力激盪模式**：這輪純聊、不撒網也**不檢索收進**（沙盒，維持既有行為）。
- **收進條目與問題弱相關**：門檻過濾，只收夠相關的（避免噪音，比照 RAG min_score）。
- **只顯示被引用的**：沒被答案 `[n]` 引用到的收進條目不列（比照 web 來源的 cited-only）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 聊天每輪（非腦力激盪）MUST 除了既有的核心理解與 web，還**檢索使用者收進語料中相關的條目**（依相關度門檻、取前幾則）注入該輪場脈絡。
- **FR-002**: 檢索到的收進條目 MUST 可被答案**引用**（`[n]`），且來源清單 MUST **標明「你收藏的」**、與 web 來源**可區分**。
- **FR-003**: 膜 MUST 把三種來源**分層**：**核心理解＝地基**（從它往下推）；**收進的文章＝外部證言**（引用、比核心理解軟、可能有錯/是他人觀點）；web＝外部。
- **FR-004（純度守門，原則 6）**: 收進的內容 MUST NOT 進入場脈絡的**地基**（`build_field_system_prompt` 只含冊封的核心理解）；MUST NOT **自動變成核心理解**。以守衛測證明。
- **FR-005**: 檢索邏輯 MUST 可**注入替身**、離線可測（不需真 embedder/後端）。
- **FR-006**: 檢索失敗或無收進內容時 MUST **不中斷聊天**——退回「只核心理解＋web」（best-effort，教訓 3）。
- **FR-007**: 只有被答案 `[n]` 引用到的收進條目 MUST 才列入來源（不相關的不塞，比照 web 的 cited-only）。
- **FR-008**: 「對收進內容發問」的能力 MUST 併入聊天；獨立「問答」導覽入口 MUST 退場（舊路徑導向聊天、不報錯）。
- **FR-009**: 全繁中；核心檢索 MUST 複用既有 embeddings/語料機制、不新增資料表（教訓 8）、核心零第三方相依（憲章 IV）。

### Key Entities *(include if feature involves data)*

- **核心理解（root）**：既有。地基——聊天從它往下推。
- **收進條目（corpus entry）**：既有（收進的文章/論文＋其 embedding）。本功能**檢索**它、當**證言**注入，**唯讀**、不改其性質。
- **來源（source）**：答案引用的項目。本功能新增一類**「你收藏的」**來源，與既有「web」來源並存、可區分。
- **場脈絡地基**：`build_field_system_prompt` 產物——**只含冊封的核心理解**，收進內容不得入。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者收進相關文章後在聊天問相關問題 → 答案能**引用該收進條目**（`[n]`、標「你收藏的」）；無關/無收進 → 不硬塞、不報錯。
- **SC-002**: **膜分層**：核心理解為地基、收進資料為證言（比核心理解軟）；**守衛測**：收進內容不進地基 system prompt、不自動變核心理解。
- **SC-003**: 檢索可注入替身、離線可測；檢索失敗/無語料 → 聊天照跑（best-effort）。
- **SC-004**: 只有被引用的收進條目才列入來源。
- **SC-005**: 獨立「問答」入口退場、能力在聊天；舊路徑導向聊天不報錯。
- **SC-006**: 全繁中；核心零相依；不新增資料表；**現有 265 測試不回歸**＋新增涵蓋檢索注入、膜分層、純度守衛的測試。

## Assumptions

- 「相關」以既有 RAG 檢索的相似度門檻（embedding cosine ≥ min_score）判定；取前幾則（沿用既有 top_k 尺度）。
- 收進條目的 embedding 與語料清單沿用既有機制（收進時已建/可即時補）；本功能只讀。
- 收進條目注入場脈絡的方式比照既有「貼的網址內容／web 來源」的注入與引用慣例。
- 腦力激盪模式維持「純聊、不撒網、不檢索」。

## Out of Scope（明確排除，防蔓延）

- 檢索調參 UI（讓使用者調 top_k／門檻）。
- 跨文件多跳推理、文件全文搜尋。
- PDF／影音／網頁 → Markdown 進料（另階段）。
- 收進資料**自動變成核心理解**（違原則 6）。
- CLI。
