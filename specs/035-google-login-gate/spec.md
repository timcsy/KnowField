# Feature Specification: 單人 Google 登入門鎖——部署上「不被看光」

**Feature Branch**: `035-google-login-gate`

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: 見 vision 階段 32、`draft/2026-07-23-部署與介面路線`（A 登入牆＋②節）。

## User Scenarios & Testing *(mandatory)*

> 由來：階段 31 換好 PG 部署 substrate；本階段是讓「手機能開、公開網址不被路人看光」成真的那道門。
> 現行 app 完全沒有登入機制（全開）。這是**單人門鎖**，不是多租戶。

### User Story 1 - 只有我進得來（Priority: P1）

擁有者把 KnowField 部署到公開網址後，**只有他自己（用他的 Google 帳號）能進**；任何其他人——不管有沒有 Google
帳號——都被擋在門外，看不到他的知識。

**Why this priority**: 這是整個功能的存在理由（「不被看光」）。少了它，部署＝把私人知識攤在公網上。

**Independent Test**: 用擁有者帳號登入→全站可用；用任何非白名單帳號登入→被拒；完全不登入→被擋。

**Acceptance Scenarios**:

1. **Given** 未登入的訪客，**When** 訪問任何應用頁或資料端點，**Then** 被導去 Google 登入、看不到任何內容。
2. **Given** 一個**非白名單**的 Google 帳號完成 Google 端登入，**When** 回到本站，**Then** 被拒、不建立登入狀態。
3. **Given** **擁有者本人**的白名單 Google 帳號，**When** 登入完成，**Then** 建立登入狀態、全站可用。
4. **Given** 已登入的擁有者，**When** 登出，**Then** 登入狀態被清除、再訪即需重新登入。

---

### User Story 2 - 私密是「真的鎖上」，不是「網址難猜」（Priority: P1）

擁有者信任這道鎖時，鎖必須是**結構上成立**的：登入狀態不可被偽造或竊取，機密設定不外洩。

**Why this priority**: 呼應原則 3「保證做進結構」。一道「看起來鎖上、其實能繞過」的門比沒有門更危險（給人虛假安全感）。
「感覺私密」≠「真的私密」。

**Independent Test**: 登入狀態以無法被前端 JavaScript 讀取的方式保存；機密設定不在版本庫中；擋人邏輯在伺服器端、非前端隱藏。

**Acceptance Scenarios**:

1. **Given** 已登入狀態，**When** 檢視它如何保存，**Then** 它無法被頁面 JavaScript 讀取（防竊取）。
2. **Given** 專案原始碼，**When** 搜尋機密（用戶端密鑰、白名單），**Then** 它們來自環境設定、不在版本庫。
3. **Given** 一個「前端沒顯示」但直接打的資料端點，**When** 未登入訪問，**Then** 仍被伺服器端擋下（非只靠前端藏）。

---

### User Story 3 - 別把自己鎖在外面（Priority: P2）

擁有者設定白名單時可能打錯自己的 email；他需要一條在本機安全打開、不會把自己永久鎖死的路。

**Why this priority**: 單人門鎖若設錯就自己也進不去；需要可恢復性，否則一個 typo = 完全失聯。

**Independent Test**: 提供一個**僅限本機開發、預設關閉**的繞過開關；白名單不符時給出清楚可行動的錯誤訊息。

**Acceptance Scenarios**:

1. **Given** 白名單設錯導致本人被拒，**When** 在本機開發啟用繞過開關，**Then** 可進入以修正設定。
2. **Given** 非白名單帳號被拒，**When** 看到回應，**Then** 訊息清楚說明「此帳號未獲授權」（不洩漏白名單內容）。

---

### Edge Cases

- **登入頁與必要靜態資源**本身必須在未登入時可取得（否則無法呈現登入入口）——白名單放行，其餘預設全擋。
- **Google 端登入成功但非白名單**：必須在**回到本站時**於伺服器端拒絕、不建立登入狀態（Google 認得你 ≠ 本站授權你）。
- **登入狀態過期/無效**：視為未登入，導去重新登入，不報伺服器錯。
- **測試環境**：測試必須能在**不打真實 Google**下模擬「已登入某身分」與「未登入」，否則無法離線驗證。
- **假綠風險**：只測「登入成功可用」會漏掉「未登入其實沒被擋」——**必須有未登入被擋的負向測試**。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 要求登入才能存取任何應用頁面與資料端點；未登入者 MUST 被導向 Google 登入。
- **FR-002**: 系統 MUST 僅允許**白名單內的 Google 帳號**（擁有者自己）建立登入狀態；非白名單帳號 MUST 被拒。
- **FR-003**: 白名單 MUST 由環境設定提供，MUST NOT 進入版本庫。
- **FR-004**: 登入狀態 MUST 以無法被頁面 JavaScript 讀取的方式保存（防竊取）。
- **FR-005**: 授權判斷 MUST 在伺服器端執行；MUST NOT 只靠前端隱藏內容。
- **FR-006**: 系統 MUST 提供登出，清除登入狀態。
- **FR-007**: 系統 MUST 提供**僅限本機開發、預設關閉**的登入繞過開關（防設錯把自己鎖死）；正式環境 MUST NOT 生效。
- **FR-008**: 非白名單被拒時 MUST 給清楚訊息，且 MUST NOT 洩漏白名單內容。
- **FR-009**: 測試 MUST 能在不呼叫真實 Google 的情況下模擬「已登入身分」與「未登入」，離線可驗。
- **FR-010**: 測試套件 MUST 包含**未登入被擋**的負向測試（不得只測登入成功路徑）。
- **FR-011**: 既有 344 測 MUST 不回歸（測試走注入/繞過、不打真實 Google）。
- **FR-012**: 新增的登入相依 MUST 在實作計畫中說明必要性（憲章額外限制）；核心演算法層 MUST NOT 受影響（登入只在 web 層）。

### Key Entities *(include if feature involves data)*

- **登入狀態（session）**：代表「這個瀏覽器目前是已驗證的擁有者」；不可被前端讀取、可登出清除、會過期。
- **白名單（allowlist）**：獲授權的 Google email 集合（單人情境下＝擁有者自己）；來自環境設定。
- **驗證身分（identity）**：Google 回傳的帳號 email，用來比對白名單；**不儲存**於資料庫（單人門鎖不需使用者表）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 未登入者存取任何頁面/端點的成功率為 **0%**——**100%** 被導去登入或擋下。
- **SC-002**: 非白名單帳號建立登入狀態的成功率為 **0%**。
- **SC-003**: 擁有者本人登入後可存取 **100%** 的既有功能（與加門前一致）。
- **SC-004**: 登入狀態 **100%** 無法被頁面 JavaScript 讀取；機密設定 **0** 進入版本庫。
- **SC-005**: 測試套件含**未登入被擋**的負向測試，且全套（既有 344 ＋ 新增）在不打真實 Google 下 **100%** 通過。
- **SC-006**: 範圍外項目（多租戶、聯邦、公開分享、Helm/佈署、領域分類）**皆未被引入**。

## Assumptions

- **身分提供者＝Google**：使用者定案用 Google 登入（憑證安全外包 Google，勝過自刻密碼）。
- **使用者手動步驟（AI 不碰憑證，安全紅線）**：在 Google Cloud 建立 OAuth client、設定回呼網址、完成同意授權
  ——**由使用者自己做**；本功能只實作程式那側的登入流程。用戶端密鑰／白名單由使用者放入環境設定。
- **HTTPS 由佈署層負責**：正式環境前擺反向代理（Caddy 自動 TLS）——**非本 spec 的應用碼責任**，但記為部署前提
  （沒有 HTTPS，登入狀態在傳輸中可被看光，鎖等於半開）。
- **單人、無使用者表**：不建多租戶資料結構；身分只用於比對白名單，不落庫。
- **範圍嚴限**：只做單人登入牆；多租戶、聯邦、公開分享、Helm/host、領域分類皆排在其後、各自 promote。
