# 功能規格：Web 介面

**Feature Branch**: `004-web-ui`

**Created**: 2026-07-23

**Status**: Draft

**Input**: 路線圖階段 6——一個本機 web app，讓使用者在瀏覽器裡看今日匯整（散文＋圖內嵌
＋一鍵原文）、輸入主題即時拉、管理興趣清單。複用既有核心（digest／pull／interests／
消化），web 只是薄薄一層呈現。設計理由見 `knowledge/draft/2026-07-23-部署與介面路線.md`。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在瀏覽器看今日匯整 (Priority: P1)

作為使用者，我打開瀏覽器就能看到**今日分診匯整**：每則是一篇可讀散文（整理過的標題＋
內文），**原文圖直接內嵌顯示**（終端做不到），並附一鍵直達原文的連結。我不必開終端或
檔案，掃一眼就能決定要不要點進原文。

**Why this priority**：這是 web 介面的核心價值——把已有的消化匯整用瀏覽器好讀地呈現，
尤其**圖內嵌**是相對終端的關鍵加值。單獨實作即為可用增量。

**Independent Test**：啟動 web app，開首頁；驗證顯示當日匯整、每則有散文、原文圖以
`<img>` 內嵌、每則有可點的原文連結。

**Acceptance Scenarios**:

1. **Given** 已有當日匯整，**When** 開首頁，**Then** 看到每則的散文（標題＋內文）與可點
   原文連結。
2. **Given** 某則有原文圖，**When** 檢視該則，**Then** 圖**內嵌顯示**（非只有連結）。
3. **Given** 某則圖為 AI 示意，**When** 檢視，**Then** 明確標示「AI 示意・非原文」。
4. **Given** 在手機或桌面開啟，**When** 檢視首頁，**Then** 版面皆正常排版（RWD）。

### User Story 2 - 輸入主題即時拉 (Priority: P2)

作為使用者，我在 web 上輸入一個主題，就能**即時拉取**該主題的深挖結果（跨源擴展、去重、
散文消化、一鍵原文），不必回到終端。

**Why this priority**：把「拉」搬上 web，讓深挖也在同一個介面完成。依賴 US1 的呈現與核心
拉能力。

**Independent Test**：在 web 輸入一個主題送出，驗證回傳該主題的散文結果清單、每則有原文
連結。

**Acceptance Scenarios**:

1. **Given** 在首頁的主題輸入框，**When** 輸入主題並送出，**Then** 顯示該主題的拉取結果
   （散文＋原文連結）。
2. **Given** 短時間內重複相同主題，**When** 再次送出，**Then** 系統以**快取**回應，不重複
   打真實後端（避免狂打 API）。
3. **Given** 拉取進行中，**When** 等待，**Then** 有明確的載入狀態提示。

### User Story 3 - 管理興趣清單 (Priority: P3)

作為使用者，我可以在 web 上**檢視、新增、刪除**我的興趣主題，變更會影響後續的匯整過濾。

**Why this priority**：把興趣管理搬上 web，讓設定不必用 CLI。加值但非核心呈現，故 P3。

**Independent Test**：在 web 新增一個興趣主題、再刪除，驗證清單即時反映變更。

**Acceptance Scenarios**:

1. **Given** 興趣管理頁，**When** 新增一個主題，**Then** 清單顯示新主題。
2. **Given** 既有主題，**When** 刪除，**Then** 清單移除該主題。

### Edge Cases

- 當日**尚無匯整**（還沒跑過）時，首頁如何呈現（提示去產生／空狀態）？
- **後端失敗**（如 API 額度隔離）時，頁面如何呈現（友善繁中訊息，非 500 錯誤頁）？
- 即時拉的主題**查無結果**（冷門）時，如何呈現空狀態？
- 原文圖 URL **失效／載入失敗**時，版面如何處理（退為無圖，不破版）？
- **多人同時**開頁（本機工具通常單人，但不應崩）？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系統 MUST 提供一個 web 首頁，顯示**當日分診匯整**（每則散文＋整理過標題）。
- **FR-002**：每則 MUST 提供**一鍵直達原文**的可點連結（原則 3 溯源）。
- **FR-003**：有原文圖者 MUST **內嵌顯示圖**；AI 示意圖 MUST 標示「AI 示意・非原文」（FR-007 對應）。
- **FR-004**：使用者 MUST 能在 web 輸入主題並**即時拉取**，顯示散文結果與原文連結。
- **FR-005**：即時拉 MUST 有**快取／節流**，避免對真實後端重複／過量呼叫。
- **FR-006**：使用者 MUST 能在 web **檢視／新增／刪除**興趣主題，變更影響後續匯整。
- **FR-007**：介面 MUST 為 **RWD**——手機與桌面皆正常排版。
- **FR-008**：所有面向使用者文字 MUST 為**繁體中文**（消化語言跟隨既有設定）。
- **FR-009**：後端失敗（API 隔離／限流／逾時）MUST 於 web 層攔成**友善繁中頁面／提示**，
  不得回傳未處理的 500 堆疊（原則 V、`experience.md` 教訓 3）。
- **FR-010**：web 層 MUST **複用既有核心**（digest／pull／interests／消化），不重寫核心邏輯。
- **FR-011**：當日無匯整、拉取無結果等**空狀態** MUST 有明確提示（不空白、不報錯）。

### Key Entities *(include if feature involves data)*

- **匯整頁面（Digest View）**：當日匯整的網頁呈現，含多則消化文章（沿用 Article／Figure）。
- **拉取結果頁（Pull View）**：即時拉的結果呈現。
- **興趣管理（Interest View）**：興趣清單的檢視與編輯。
- （資料實體沿用既有：Article、Figure、Digest、PullResult、InterestProfile，不重新定義。）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：使用者開首頁後，**無需其他操作**即看到當日匯整（散文＋圖＋原文連結）。
- **SC-002**：進入匯整的每則 **100%** 有可點原文連結；有原文圖者圖**內嵌顯示**。
- **SC-003**：在手機（窄螢幕）與桌面（寬螢幕）**皆正常排版**，無破版、無需橫向捲動。
- **SC-004**：重複相同主題的即時拉，第二次**不再打真實後端**（快取命中）。
- **SC-005**：後端失敗時，使用者看到的是**繁中友善提示**，**0%** 出現未處理的 500 堆疊。
- **SC-006**：興趣主題的新增／刪除在**同一頁即時反映**。
- **SC-007**：全介面文字為繁體中文；AI 示意圖 100% 帶標示。

## Assumptions

- **本機單人使用**：預設本機執行、單一使用者；不做認證／多租戶（範圍外）。
- **沿用既有核心與設定**：來源、消化、`--lang`、後端（OpenAI 格式／離線 stub）皆複用；
  離線 stub 下 web 也能開發／展示（圖與繁中翻譯需真實後端）。
- **當日匯整來源**：首頁顯示的匯整以**已落庫**的當日匯整為主；若尚無則提示去產生
  （是否在 web 內觸發每日匯整產生，屬實作決定，MVP 可先讀既有）。
- **範圍外**：容器化／K8s／Helm（階段 7–9，另案）；多使用者／認證；完整前端 SPA；
  付費／X 來源。
- **RWD 以 server-render＋響應式 CSS 達成**（不引入前端 SPA 框架）。
