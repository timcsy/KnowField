# spec 072：場自己去拿——貼一個 repo，它把知識抓進來（階段 68 第一刀）

## 為什麼

階段 67 做的是**你送進來**（我在筆電跑腳本 → POST 進收件匣）。
使用者要的是**場自己去拿**：

> 「我希望可以直接複製 git 網址過去就可以方便使用的，**存取權越方便拿到越好**（private repo），
> 而且是**好的 UX**。」

⇒ 而**安全的那條跟方便的那條是同一條**：GitHub App 比貼 PAT 更好用
（不過期、一鍵撤銷、加 repo 在 GitHub 勾一下），也剛好只要 `Contents: Read-only`。
設計與實查見 [draft/2026-08-27-場自己去拿](../../knowledge/draft/2026-08-27-場自己去拿-憑證與目錄樹.md)。

## 這一刀的產出不是水管

⚠️ 一個「只是把東西抓進來」的階段，做完看不出有沒有用。所以第一刀就要交付
**跨 base 死指標檢查**：每條教訓的「來源」指著一個路徑，而**那個檔案還在嗎？**
本 base 就有兩條教訓指著 `digest/builder.py`，而它在 `5cb07b9` 已被刪除——翻 commit 才發現的。

⇒ 它是**全稱**問題（每一個，不是 top-k）⇒ RAG 做不了，**目錄樹是唯一解法**。

## FR

### 連結與選擇
- **FR-001** GitHub App 授權流程：連結 → 在 GitHub 勾 repo → 跳回。
  ⚠️ App private key 從環境變數讀，**不進 DB、不進 log**；token **每次現鑄、不落庫**。
- **FR-002** 兩個入口：**repo 清單**（預設，不必去找網址）＋ **貼網址**。兩者走同一條後端路徑。

### 抓什麼
- **FR-003** `knowledge/**` 抓**內容**，六層全部：`experience` · `concepts` · `principles` ·
  `vision` · `history` · `episodes`（⚠️ 不是只有 `experience.md`）。
- **FR-004** 其餘路徑只抓**目錄樹**（路徑字串），**不抓內容**。
  ⇒ 樹本來就在 Trees API `recursive=1` 那一次呼叫裡。
- **FR-005** ⚠️ **不 clone**：正式環境容器沒有 `git`，也不該有。全部走 API。
- **FR-006** ⚠️ **結構性禁令**：程式裡**不存在**抓 `knowledge/**` 以外檔案內容的路徑。
  測試掃原始碼確認（沿用 spec 065／069／071 的做法）。

### 落庫
- **FR-007** 新表全部帶 `owner_id` ＋ `persona_id`，每個查詢過 `_own()`（spec 063／067）。
  ⚠️ 這是最容易漏的一層——沿用既有述詞，**不要另外發明一份**。
- **FR-008** 每次抓存 `fetched_at`。⚠️ **樹一抓下來就開始過期，而沒有人會發現**
  ⇒ 任何用到樹的輸出都要顯示「根據 N 天前的樹」。
- **FR-009** 樹**截斷了要說**（GitHub 自己會截斷，monorepo 也會爆量）——不能靜默給一份不完整的樹。

### 產出
- **FR-010** 清單頁：哪些 base、各層各幾條、上次抓取時間、「重新抓」。
- **FR-011** **死指標報告**：每個 base 裡，`知識檔案 → 指向的路徑`，而那個路徑不在樹裡。
  ⚠️ 只報**機器可判**的（路徑不存在）；「這條來源寫得好不好」是語意判斷，**不擋、不評分**。

## 驗收

1. 連結 GitHub → 勾 repo → 回到 KnowField 看得到清單
2. 貼網址也能加，且**走同一條路徑**（不是第二套實作）
3. 抓進來的六層計數，**對得上本機 `knowie-crosscheck` 算出來的數**（已知答案校驗）
4. ⚠️ 掃程式碼：沒有任何路徑抓 `knowledge/**` 以外的**內容**；樹只存路徑
5. 死指標報告在**本 base** 上跑得出 `digest/builder.py` 那兩條（已知答案）
6. 死指標報告顯示樹的抓取時間；樹被截斷時報告要**講出來**
7. 換 owner／persona → 看不到、也搜不到
8. **實跑：至少連一個真的 private repo**，而且 log 裡搜不到 token

## Out of scope

clone · 分群搬 `src/`（下一刀）· RAG 消化 · `knowie-pull` 移駕 knowie ·
**機器憑證**（knowie → 場那個**反方向**，見 draft §十二／§十三）· webhook 自動更新 · 寫回 repo ·
結構的跨 base 比對（⚠️ 那是**流行度不是判準**，跟「只算撞到不算借走」同一個陷阱）

## ⚠️ 三條要寫進實作的判準

- **拿資料的階段可以有憑證，處理資料的階段不能。** Codex 在 agent 階段前移除 secrets、
  Claude Code 把憑證放在沙盒外的代理——這一刀沒有 LLM，但**下一刀有**，
  所以抓進來的內容從一開始就當**不可信文字**存，不要跟自己的知識混在同一張表。
- **唯讀做在結構上，不是紀律上**（`history/131`）：那個 token 就不給 write scope，
  而不是「程式裡沒寫 push」。
- **樹是第三種東西**：不給人讀、不進收件匣、不當判準——只回答「這個路徑還在嗎」。
  ⇒ 落庫時**不要跟其他六層混在一起**。
