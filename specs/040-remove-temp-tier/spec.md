# 功能規格：移除暫存分層——對話就是對話（階段 35）

**知識庫來源**：vision 階段 35 · 轉移 [`history/097`](../../knowledge/history/097-暫存分層移除-對話就是對話.md) · 設計源 [`draft/2026-08-18`](../../knowledge/draft/2026-08-18-暫存的真實使用回報與連接密度.md) · 被取代者 [`history/067`](../../knowledge/history/067-對話暫時存檔完成.md)（spec 028）

⚠️ **這是移除，不是新增**。風險不對稱：做多了會刪掉使用者的東西。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 對話清單不再有兩種東西 (Priority: P1)

使用者打開對話清單，看到的就是他的對話——沒有「暫存」分組、沒有需要決定要不要升級的項目。

**Why this priority**：這是使用者抱怨的那件事本身。「麻煩」來自清單裡混著一批他本來就不打算留的東西。

**Independent Test**：開啟對話清單，確認只有一組對話、沒有暫存分區。

**Acceptance Scenarios**:

1. **Given** 系統中有原本標為暫存與永久的對話，**When** 使用者開啟清單，**Then** 它們**混在同一組**呈現，沒有分區標籤。
2. **Given** 任一對話，**When** 使用者查看它的操作，**Then** 沒有「升為永久」這類動作。

---

### User Story 2 - 舊資料一個都不能少 (Priority: P1)

使用者原本存在系統裡的對話——**包含那些標為暫存的**——在移除之後全部還在。

**Why this priority**：⚠️ 與 P1 並列且**優先於 US1 實作**。移除機制時最容易發生的傷害是「順手把那類資料也清了」。使用者要的是拿掉**分層**，不是拿掉**資料**。

**Independent Test**：記錄移除前的對話 id 集合，移除後逐一比對，一個都不能少。

**Acceptance Scenarios**:

1. **Given** 系統中有 N 筆對話（含暫存），**When** 完成移除，**Then** 仍有 N 筆，且 id 集合完全相同。
2. **Given** 一筆原本標為暫存的對話，**When** 移除後開啟它，**Then** 內容與標題與先前相同。

---

### User Story 3 - 安全網還在 (Priority: P1)

使用者聊到一半關掉視窗，回來還找得到那段對話。

**Why this priority**：與 P1 並列。這是 spec 028 當初存在的**唯一理由**（「不能存檔踩雷後怕丟東西」）。移除分層時把它一起拿掉，等於把那個痛還回去——使用者明確選了保留。

**Independent Test**：進行一段對話但不做任何存檔動作，重新載入後那段對話仍在清單中。

**Acceptance Scenarios**:

1. **Given** 使用者聊了幾輪、沒有按任何存檔按鈕，**When** 重新載入，**Then** 那段對話在清單中。
2. **Given** 一段既有對話，**When** 使用者接回繼續聊，**Then** 更新的是**同一筆**，不會另開新的。

---

### Edge Cases

- **移除當下正好有過期的暫存**：⚠️ 不得因為「反正它本來就要被清」而清掉——移除的是機制，不是資料。
- **同一份對話同時被兩處開啟**：不得因為分層消失而互相覆蓋。
- **原本綁了根因（由來）的對話**：連結必須完好。
- **章節切分過的對話**：章節資料必須保留。

## Requirements *(mandatory)*

- **FR-001**：系統 MUST NOT 再區分暫存與永久對話。
- **FR-002**：對話清單 MUST 以單一分組呈現，MUST NOT 有暫存分區。
- **FR-003**：系統 MUST NOT 提供「升為永久」之類的動作。
- **FR-004**：系統 MUST NOT 再依時間自動刪除任何對話。
- **FR-005**：移除前既存的所有對話 MUST 全部保留，**包含原本標為暫存者**。
- **FR-006**：系統 MUST 繼續自動保存進行中的對話（安全網不移除）。
- **FR-007**：接回既有對話繼續聊 MUST 更新同一筆，MUST NOT 另開新的。
- **FR-008**：既有的由來（根因連結）與章節資料 MUST 完好。

## Success Criteria *(mandatory)*

- **SC-001**：移除前後對話**數量與 id 集合完全相同**（一筆不少、一筆不多）。
- **SC-002**：對話清單上**看不到**任何與「暫存／永久」有關的字樣或分區。
- **SC-003**：未經任何存檔動作的對話，重新載入後 **100%** 仍在。
- **SC-004**：既有測試零回歸。

## Assumptions

- **⚠️ 已知代價（知情接受）**：清單會持續長大——正是 spec 023 當初否決「自動存全部」的理由。使用者選擇先承擔；若日後變成問題，走「**可見性**」那條軸處理，**不要走回「存活期限」**（那是 `draft/2026-08-18` 的診斷，也是 097 的教訓）。
- 資料庫欄位可以留著不用（移除的是行為與呈現），是否清理欄位屬實作細節，不影響本規格。

## Out of Scope

- 清單雜訊的長期解法（可見性那條軸）。
- 對話的自動摘要、自動分類、自動刪除。
