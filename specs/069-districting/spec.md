# spec 069：行政區——領域改成機器劃、人核准（vision 階段 63）

## 形狀

**邊界是資料，不是函數**：存的是「指派」（誰在哪一區），不是「離誰最近」。
⇒ 換 embedding 模型不會重劃；新增一個區不會讓別的區靜靜改變。

## ⚠️ 全量重劃**在 API 層面不存在**，不是靠紀律

實驗（2026-08-26，正式庫 117 節點）：換個隨機種子分區就大幅重排，**ARI ≈ 0.18**。
⇒ 「哪天重跑一次」會讓大量地址改變。

所以這一刀的劃界**只作用在還沒有地址的東西**（`domain_id IS NULL`）。
⇒ **它永遠不會動已經歸屬的東西**——不是因為我們記得不要，是因為沒有那條路。

## FR

- **FR-001** 位置：理解／來源用既有向量；互動用**它冊封出的理解的重心**；
  應用用**骨幹理解的重心**；都沒有的才補算。
  ⚠️ 這不只是省錢——**互動的位置由它的理解決定**，比拿標題去 embed 更貼近它實際在講什麼。
- **FR-002** 邊：**同種＝相似度**（地形）· **跨種＝真實關係**（道路，權重更高）。
  硬理由：異質節點的相似度不可比（40 則的互動 vs 一句理解 vs 一塊來源文字）。
- **FR-003** 平衡分割：人口當**約束**（每區 ∈ [n/2, 2n]），目標是**最小化切斷的邊**。
- **FR-004** 每區的名字＝**離中心最近的那條理解**（錨，穩定且可查證），
  ⚠️ 但顯示名要**短**——實驗印出的區名是一整句主張，完全不能用。
- **FR-005** 理由要**可判斷**：列出錨 ＋ 最靠近中心的幾件。
  ⇒ 你能說「不對，這些跟那條沒關係」。**分數（0.87）不算理由**。
- **FR-006** 逐區接受／改名／略過，**沒有全部套用**（沿用 spec 065）。
- **FR-007** 記 `assigned_by`（`machine`／`human`）——⚠️ **人的 override 要看得出來**，
  否則你分不出「這是我放的」和「這是算的」。

## 驗收

1. 未歸屬的東西被分成大小相近的幾區，每區有錨與可判斷的理由
2. ⚠️ **已經歸屬的東西不出現在任何建議裡**（結構上不可能）
3. 接受一區 → 建領域、搬入、`assigned_by='machine'`
4. 離線／無向量時**退回既有的邊**分群（不是回空的）
5. 實跑：正式庫按下去看得到區，接受一區後件數對得上
